# video-cut — 교체 절차

상태: 📝 신규 도입 (10-02). [`서비스-개요와-철학.md`](서비스-개요와-철학.md) 원칙 3(기존 기능을 대체할 때는 옛 흔적을 같은 작업에서 지운다)을 실제로 지키기 위한 양식·커밋 규칙·기계적 장치.
문서 지도는 [`README.md`](README.md).

## 한 문장

**새 작업이 기존의 무엇과 같은 일을 하게 되는지 착수 전에 표로 적고, "삭제"라고 적은 흔적은 새 기능을 넣는 바로 그 커밋에서 함께 없앤다.**

## 왜 필요한가

묻지 않으면 같은 목적의 화면·경로·데이터가 쌓이고, 묻더라도 적어두지 않으면 "제거는 나중에"로 미뤄지다 영구히 남는다. 이 프로젝트에 실제로 있었던 사례 두 가지:

- 설치 경로가 수동 `git clone`+`ln -sfn`과 `claude plugin` CLI 두 가지로 한동안 공존했다 (10-01에 통일, [`업데이트와-마이그레이션.md`](업데이트와-마이그레이션.md))
- 검토 화면이 09-30 하향식 재설계 이후에도 옛 카드 큐·선택 팝업이 새 C/V 플로우와 나란히 남아 있다가, 사용자가 직접 써보고서야 지적되어 10-02에 제거됐다 (`결정-이력.md` 10-02 항목)

둘 다 "같은 역할을 하는 게 이미 있는가"를 작업 시작 시점에 표로 확인했다면 더 빨리 잡혔을 문제다.

## 1. 작업 착수 전 — 대체 표

작업을 시작하기 전(요청을 받는 시점) 판단한다: **이 작업이 기존 기능과 같은 목적을 수행하게 되는가?** (새 진입 경로 추가, 수동→자동 전환, 유사 화면 신설 등) 그렇다면 아래 표를 채운다.

이 저장소는 GitHub 이슈를 쓰지 않으므로 표를 적을 위치는 작업 성격에 따라 다르다:
- 전용 기획 문서를 새로 만들 정도의 재설계면 그 문서(`기획/`)에
- 그 정도가 아니면 같은 작업의 커밋 메시지 본문에, 또는 [`결정-이력.md`](결정-이력.md) 해당 줄에

| 기존 흔적 종류 | 구체 대상 | 운명 (기본: 삭제) |
|---|---|---|
| 화면/UI (`web/index.html`) | | |
| 스크립트/CLI (`scripts/*.py`) | | |
| 사용자 매뉴얼 (`SKILL.md`, `촬영-가이드.md`) | | |
| 설계 문서 (`docs/*.md`, `기획/`) | | |
| 데이터 (`edit/*.json`, `~/.video-cut/`) | | |

- 기본값은 **삭제**. "병행 유지"는 예외이며, 예외로 두려면 (a) 사용자 승인 (b) 종료 조건(언제 누가 없앨지)이 둘 다 있어야 한다 — `서비스-개요와-철학.md` 원칙 3과 동일한 기준.
- 애매하면 표를 만드는 비용이 작으니 일단 만든다. 해당 없는 행은 비워두지 말고 "없음"이라고 적는다 — 빈 칸은 "확인 안 함"과 구분이 안 된다.

## 2. 구현 — 같은 커밋에서 교체와 제거

표에 "삭제"라고 적은 항목은 새 기능을 넣는 **그 커밋**에서 함께 지운다. "제거는 다음에"로 미루지 않는다 — 다음은 거의 오지 않는다. 자동/수동처럼 모드가 둘로 나뉘면 화면·경로를 따로 만들지 않고 같은 화면 안의 설정 하나로 전환한다. (구체적인 4단계 — 전체 코드 검색 → 운명 결정 → 모드 통합 → 결정-이력 기록 — 는 이미 `서비스-개요와-철학.md` 원칙 3에 있으므로 여기서 반복하지 않는다.)

## 3~4. 설계 문서·사용자 매뉴얼 동기화

- 이번 작업이 `docs/서비스-개요와-철학.md`·`docs/현재-설계/`·`docs/기획/`가 설명하는 규칙·동작을 바꾸거나 끝내면 **같은 커밋**에서 그 문서도 고친다. 전체를 다시 쓰지 않고, 날짜를 붙인 정정이나 더는 맞지 않는 문장만 지운다.
- `SKILL.md`·`docs/촬영-가이드.md`가 설명하는 사용자 조작(버튼·명령·단축키·메시지)이 생기거나 바뀌거나 없어지면 같은 커밋에서 고친다.
- 스키마가 바뀌는 변경(`edit/*.json` 필드 구조)은 [`업데이트와-마이그레이션.md`](업데이트와-마이그레이션.md)가 이미 정한 절차(`SCHEMA_VERSIONS` + `MIGRATIONS`)를 따른다 — 여기서 중복 설명하지 않는다.

## 5. 커밋 메시지 필수 필드 + 훅

`web/`·`scripts/`·`SKILL.md` 중 하나라도 건드리는 커밋은 본문에 아래 두 줄을 남긴다 (바뀐 게 없어도 "해당 없음 — 이유"를 적는다):

```
매뉴얼: <갱신한 SKILL.md/촬영-가이드.md 절> / 해당 없음 — <이유>
문서: <갱신한 docs/*.md 파일> / 해당 없음 — <이유>
```

`scripts/hooks/commit-msg`가 이 두 줄의 **존재 여부만** 커밋 훅으로 강제한다 — 내용이 맞는지는 여전히 사람(또는 다음에 그 커밋을 보는 세션)이 판단한다, 이 분리가 중요하다. `scripts/setup.py`를 호출할 때마다 이 훅을 `.git/hooks/commit-msg`에 설치/갱신하므로 따로 설치할 필요는 없다. `web/`·`scripts/`·`SKILL.md`를 건드리지 않는 순수 문서 전용 커밋은 검사 대상이 아니다. 급하게 건너뛰어야 하면 `git commit --no-verify`를 쓸 수 있지만, 세션 공통 규칙대로 사용자가 명시적으로 지시했을 때만 쓴다.

## 6. 정기 전수조사

개별 작업의 대체 표만으로는 "아무도 지적하지 않은 조용한 중복"까지는 못 잡는다. 09-30~10-01의 "설치~업데이트 전체 경로 점검"(커밋 `9ead579`, 버그 9건 발견)이 이미 한 차례 실제로 수행된 선례다. 이 작업을 **정기 반복 작업**으로 명시한다:

- 트리거: 화면(`web/index.html`)이나 설치·업데이트 경로가 큰 재설계를 한 번 마칠 때마다, 또는 사용자가 "전수조사해줘"라고 요청할 때
- 방법: 체크리스트 기반으로 `SKILL.md`·`scripts/`·`web/`·`docs/`를 훑어 같은 역할을 다른 방식으로 구현한 곳을 찾는다
- 기능 개발할 때마다 전체를 훑지는 않는다 — 별도 작업으로 스케줄한다

## 7. 동시 작업자 조율

이 저장소는 여러 Claude Code 세션이 동시에 같은 워킹트리를 건드릴 수 있다 (`ListAgents`로 확인 가능). 작업하려는 파일(특히 `SKILL.md`·`docs/*.md`·`web/index.html`)에 이미 커밋 안 된 변경이 있으면:

1. `ListAgents`로 다른 세션이 같은 작업을 하고 있는지 먼저 확인한다
2. 겹치면 조율하거나, 최소한 내 변경은 다른 파일·다른 절에 추가하는 방식으로 충돌을 줄인다
3. 커밋은 내가 실제로 바꾼 파일만 경로로 지정해서 올린다 — 다른 세션의 미완성 변경을 같이 커밋하지 않는다

## 8. 자기 교정 루틴

이 절차를 적용하다 과거의 어긋남(되돌려진 변경, 옛 섹션 번호 참조 오류 등)을 발견하면 즉시 고치고, 왜 그런 어긋남이 생겼는지(동시 작업, stash 복원 등)를 커밋 메시지나 `결정-이력.md`에 남긴다 — 같은 실수가 반복되는지 추적할 수 있게.
