# 주제별 분할 — 완성본 영상을 주제 단위로 잘라 여러 개로 내려받기

상태: ✅ S1~S4 1차 구현 완료 (10-08) · 진짜 완성본으로 결과 확인 대기 · 결정 기록은 맨 아래 · 문서 지도: [`../README.md`](../README.md)

## 한 문장

**자막 편집까지 끝난 완성본을 올리면 전사 후 "이 부분만 떼어 봐도 완결되는" 지점을 자동으로 찾아 구간을
제안하고, 사용자가 스크립트 위에서 경계를 드래그로 고친 뒤 확정하면 구간별 mp4와 그 구간의 대본이 함께 내려받아진다.**

## 용도

강의 영상이 한 편으로는 너무 길고 지루해서 **여러 편의 강의 영상으로 나눈다** (10-07 확인). 쇼츠·하이라이트 추출이 아니다.
그래서 각 편은 "주제 하나를 처음부터 끝까지 다루는 짧은 강의"여야 하고, 기본 길이는 **3~10분**(분석 전 설정에서 변경 가능)으로 둔다.

**원본 전체를 빈틈없이 나눈다** (10-08 결정). 버리는 구간은 없다. 인트로는 1편에, 아웃트로는 마지막 편에 붙는다.
그래서 N편으로 나누는 것 = **경계 N−1개를 정하는 것**이고, 모든 편을 이어 붙이면 원본과 같다.

## 컷편집과의 관계: 완전히 분리

| | 컷편집 (기존) | 주제별 분할 (신규) |
|---|---|---|
| 입력 | 촬영 원본 (`raw.mp4`) | **완성본** (자막·편집 끝난 영상) |
| 폴더 | `videos/<이름>/` | **`splits/<이름>/`** (별도 루트) |
| 구간 안쪽 | NG·말더듬·무음을 잘라냄 | 손대지 않음 |
| 순서 | 유지 | 유지 (재배열 없음) |
| 결과 | FCPXML 1개 | mp4 N개 + 편별 대본 |

- 두 작업은 데이터를 주고받지 않는다. 컷편집 결과를 분할 입력으로 쓰는 경로는 만들지 않는다
- 공유하는 건 **코드**뿐: `transcribe.py`(전사), `audio_map.py`(무음 지점), `claude_cli.py`(LLM 호출), 홈 화면 셸·업로드 스트리밍
- 홈 화면에서는 목록을 **탭 두 개**(`컷편집` / `주제별 분할`)로 나눈다. 업로드 폼도 탭마다 따로

## 사용 흐름

1. 홈 → `주제별 분할` 탭 → 완성본 업로드 (`splits/<이름>/source.mp4`) + **자막 파일(SRT)은 있으면 함께, 없으면 생략**
2. 자동 처리: 대본 준비(SRT 또는 전사) → 문장 나누기 → 구간 제안 → 완결성 검사. 전사를 빼고 1~2분 목표
3. 분할 화면에서 스크립트와 구간을 보며 경계 수정
4. **내보내기** → 편마다 `01_<제목>.mp4` + `01_<제목>.txt`(대본) 생성, 브라우저에서 zip 한 번 또는 편별 다운로드

## 처리 파이프라인

```
split_run.py                          진입점 (단계별 캐시, --redo로 문장·구간만 다시)
SRT 없음: transcribe.py              (기존 코드 재사용, 입력 경로만 source.mp4. SRT 있으면 생략)
 → audio_map.py                       (기존 코드, 경계를 문장 사이 가장 조용한 지점에 맞추는 데 사용)
 → split_sentences.py   [신규]        SRT 파싱·검증 + 큐/단어 → 문장. 문장 끝 = 종결어미(~다·~요·~죠)/문장부호 + 쉼
 → propose_segments.py  [신규]        LLM 1회: 문장 번호 목록 전체 → 구간 제안
 → check_standalone.py  [신규]        다른 모델이 구간별 "이것만 봐도 이해되나" 판정 (만든 모델 ≠ 판정 모델)
 → 분할 화면
```

`clean_media.py`(FCP 호환용 tmcd 제거)는 쓰지 않는다. 결과가 FCP로 가지 않기 때문.
`run.py`도 컷편집 전용으로 두고, 분할은 진입점 `split_run.py`를 따로 둔다.

### 대본 출처: SRT가 있을 때와 없을 때

| | SRT 있음 | SRT 없음 |
|---|---|---|
| 대본 글 | 자막 그대로 (사람이 교정한 글) | 전사 결과 |
| 시간 | 자막 큐 시간 | 전사 단어 시간 |
| 경계 단위 | 문장 (큐 경계) | 문장, `Alt`로 단어 |
| 전사 비용 | 0 | 있음 |
| 오타 대응 | 거의 필요 없음 | **분할 화면에서 대본 글자 직접 수정** |

- **SRT가 있으면 번인 자막 문제도 같이 풀린다.** 경계가 자막 큐가 바뀌는 순간과 일치하니 다음 편 첫 프레임에 앞 자막이 남지 않는다
- 한국어 자막은 마침표가 없는 경우가 많다. 문장 끝은 문장부호가 아니라 종결어미 + 큐 사이 쉼으로 판단하고, 애매하면 LLM 구간 제안 단계에서 함께 정한다
- 큐 하나가 문장 중간에서 끊기는 것(두 줄 자막)은 큐를 이어 붙여 문장으로 만든다
- **검증**: SRT 마지막 큐 끝 시각이 영상 길이를 넘거나, 첫 몇 문장의 큐 시간이 음성 구간과 크게 어긋나면(`audio_map`으로 확인) "자막 파일이 이 영상과 맞지 않습니다"로 멈춘다. 다른 버전에서 내보낸 SRT를 막기 위함
- 전사 대본 수정은 **글자만 바꾸고 시간은 안 바꾼다**. 수정 내용은 `split_decisions.json`에 따로 저장해 원본 전사는 그대로 둔다

### 구간 제안 (propose_segments.py)

- 입력: 번호 붙은 문장 목록 + 문장 사이 쉼 길이
- 출력: `[{start_sent, end_sent, title, summary, reason}]`
  - 구간은 **원본 전체를 빈틈·겹침 없이 덮는다**. 1편은 첫 문장에서 시작, 다음 편은 앞 편 끝 바로 다음 문장에서 시작
  - 검사: 출력이 이 조건을 어기면 다시 요청 (1회), 그래도 어기면 쉼 길이만으로 나눈 결정론적 분할로 대체
- 경계 후보는 **문장 끝에서만**. 문장 중간 절단을 구조적으로 막는다
- 프롬프트에 명시할 완결성 기준:
  - 시작: 앞 맥락이 필요한 말("그래서", "아까 말씀드린", "이것도", 가리키는 대상 없는 지시어)로 시작하지 않는다
  - 끝: 결론·정리 문장으로 끝나고, 다음 구간 예고("다음으로는…")로 끝나지 않는다
  - 길이: 목표 길이(기본 3~10분)를 지키되 주제를 억지로 자르지 않는다. 범위를 벗어나는 편은 화면에서 길이에 경고색
  - 제목: 강의 편 제목으로 쓸 수 있게 "무엇을 배우는지"가 드러나게 (예: `수면 퇴행은 왜 생기나`)

### 완결성 검사 (check_standalone.py)

- 구간마다 "이 구간만 본 시청자" 입장에서 판정: `ok` / `warn` + 문제마다 종류와 이유
  - `boundary`: 편 첫머리·끝 문제 → 경계를 옮기면 풀릴 수 있다
  - `reference`: 편 중간에서 다른 편·지난 영상을 가리킴 → 경계로는 못 고친다. 화면에서 다르게 보여 헛수고를 막는다
- **자동으로 고치지 않는다.** 경고 배지로만 보여주고 사용자가 판단한다 (원칙 3: LLM은 라벨만 붙인다)

## 분할 화면

```
┌───────────────────────────────────────────────────────────────┐
│ 전체 타임라인  [■1■■■][■■2■■■■][■■■3■■■■][■4■]                │ ← 클릭하면 이동
├──────────────────────────────┬────────────────────────────────┤
│ ① 수면 퇴행이란  3:12  ⚠1    │                                │
│ ┃ 오늘은 수면 퇴행에 대해…    │         영상 플레이어           │
│ ┃ 4개월쯤 되면…              │                                │
│ ┃ …정리하면 이겁니다.         │  [구간 재생] [시작 3초] [끝 3초] │
│ ═══════ ⇕ 경계 핸들 ═══════  │                                │
│ ② 대처법 세 가지  4:40       │  ⚠ "이 방법"이 ①을 가리킴       │
│ ┃ 첫 번째는…                 │                                │
└──────────────────────────────┴────────────────────────────────┘
                                          [내보내기 (4개)]
```

- **스크립트가 주 화면.** 구간마다 왼쪽 색 띠 + 머리 카드(번호·제목·길이·경고 수)
- **경계 드래그**: 구간 사이 핸들을 위아래로 끌면 **문장 경계에 스냅**. `Alt` 누른 채 끌면 단어 경계까지 세밀하게
  - 핸들은 편 사이에만 있다. 끌면 한쪽이 줄고 다른 쪽이 늘어난다 (빈틈이 없으니 핸들 하나 = 경계 하나)
- **키보드 대안** (드래그보다 빠름): 경계 선택 후 `↑`/`↓` 한 문장씩 이동, `S` 커서 위치에서 나누기, `M` 다음 구간과 합치기, 제목 더블클릭 편집
- **경계 확인**: 각 구간의 처음 3초·마지막 3초만 재생한다. 완성본이라 소리뿐 아니라 **화면도 봐야 한다**: 앞 구간 자막·자료 화면이 첫 프레임에 걸리는지, 배경음악이 뚝 끊기는지
- **대본 직접 수정** (SRT 없을 때): 문장을 더블클릭하면 글자 수정. 수정된 문장은 작은 표시가 붙는다
- **마우스 편집** (10-08 사용자 요청 - 키보드 `S`/`M`만으로는 찾을 수 없었음): 문장에 올리면 "여기서 나누기", 경계 옆 "경계 없애기"
- **제목 자동 작성** (10-08 사용자 요청): 편집을 끝낸 경계 + 고친 대본 기준으로 모든 편 제목을 다시 짓는다 (`propose_segments.retitle`, opus effort low, BS145 4편 5.5초·$0.05). 바로 적용되고 `⌘Z`로 되돌린다
- 상단 타임라인은 만들지 않았다 (S2 구현 때 왼쪽 편 목록이 같은 역할: 클릭 이동 + 지금 보는 편 표시)
- 수정은 즉시 `split_decisions.json`에 저장되므로 새로고침해도 유지된다. 제안 원본(`segments.json`)은 덮어쓰지 않아 "제안으로 되돌리기"가 가능하다
- 화면은 `web/split.html` + 분할 전용 서버(`split_server.py`). 컷편집 검토 화면(`server.py`/`index.html`)과 코드를 섞지 않는다

## 완성본이라 생기는 문제

- **번인 자막**: 자막은 말에 맞춰 바뀌니 문장 끝 경계와 대체로 맞는다. 다만 자막이 말보다 늦게 사라지면 다음 구간 첫 프레임에 앞 자막이 남는다. SRT가 있으면 경계가 큐 경계라 이 문제가 없다. SRT가 없으면 v1은 "시작 3초" 확인으로 사람이 본다. 반복되면 v2에서 경계 근처 프레임 차이(화면이 바뀌는 순간)로 스냅한다
- **배경음악·효과음**: 무음이 거의 없을 수 있어 `audio_map`의 "가장 조용한 지점"이 잘 안 잡힌다. 경계에 오디오 페이드(앞뒤 수십 ms, 실측해 정함)를 기본으로 건다
- **화질**: 이미 한 번 압축된 영상이라 재인코딩은 고화질 설정으로 한다 (아래)

## 내보내기

- 자르는 시각: 경계마다 **한 시각**을 정한다 = 앞 문장 끝과 다음 문장 시작 사이에서 가장 조용한 지점 (`audio_map`). k번째 편은 (k−1번째 경계 ~ k번째 경계), 1편은 0초부터, 마지막 편은 영상 끝까지. 따라서 여유 계산이 필요 없고 빠지는 프레임도 없다
- **고화질 재인코딩** (결정 기록 4):
  - 스트림 복사(`-c copy`)는 무손실이고 빠르지만, 키프레임(완전한 그림, 보통 1~2초 간격)에서만 잘린다. 시작이 앞 문장 끝으로 밀려 앞 구간 말·자막이 섞일 수 있다
  - 재인코딩은 프레임 단위로 정확하다. Mac 하드웨어 인코더 고비트레이트 또는 `libx264 -crf 16` 수준이면 손실이 눈에 안 보인다
  - 대안 "스마트 컷": 시작부터 다음 키프레임까지 몇 초만 재인코딩하고 나머지는 복사한다. 거의 무손실에 빠르지만 구현이 까다롭다 → v2 후보
- 파일명: `01_수면-퇴행이란.mp4` + 같은 이름의 `.txt` 대본. 함께 `out/목록.txt` (번호·제목·길이·원본 기준 시작~끝)

### 편별 대본 (`NN_<제목>.txt`)

```
수면 퇴행은 왜 생기나
길이 4:12 · 원본 03:10~07:22

오늘은 수면 퇴행에 대해 이야기해 보겠습니다. 4개월쯤 되면…

(문단은 2초 이상 쉼 또는 화제 전환에서 나눔)
```

- 내용은 **실제 잘린 범위와 정확히 일치**해야 한다. 경계를 단어 단위로 옮겼으면 대본도 그 단어에서 끊긴다 (같은 `split_decisions.json`에서 영상과 대본을 함께 만든다)
- 대본 글은 SRT가 있으면 자막 그대로, 없으면 전사 + 사용자 수정분
- 분할 화면에서 편을 고르면 오른쪽에 그 편의 대본 미리보기가 보인다
- 진행률 표시, 끝나면 `zip 다운로드` + `Finder에서 열기`

## 폴더와 산출물

```
splits/<이름>/
  source.mp4                 업로드한 완성본
  source.srt                 함께 올린 자막 (선택)
  work/transcript.json       단어 단위 전사 (SRT 없을 때만)
  work/audio_map.json
  work/sentences.json        문장 단위 (단어 인덱스 범위, 시작·끝 시각)
  work/segments.json         LLM 제안 원본 + 완결성 판정 (불변)
  work/split_decisions.json  사용자가 고친 최종 경계 + 제목 + 대본 글자 수정
  work/actions.log           경계 이동·나누기·합치기 기록
  out/NN_<제목>.mp4
  out/NN_<제목>.txt         편별 대본
  out/목록.txt
```

`common.is_split_project()`: 폴더에 `source.mp4`가 있으면 분할 프로젝트로 보고 `edit_dir()`→`work/`, `source_media()`→`source.mp4`를 돌려준다. 그래서 `transcribe.py`·`audio_map.py`는 고치지 않고 그대로 쓴다. 분할 코드는 컷편집 스크립트(`seam_refine.py` 등)를 import하지 않는다.

## 경계 다듬기 (10-08, 사용자 요청 "끊기는 지점을 다듬어서")

첫 실제 완성본("사고력 수학 1편 풀버전", 26분, 7편)에서 확인: 문장 사이 쉼이 0.12~0.44초뿐이고, 소리만 보고 자르면
6개 경계 중 2개가 어긋났다 - 앞 편 끝 2프레임에 다음 자막이 비침(경계 4), 페이드인 첫 프레임에서 잘림(경계 6).
`split_refine.py`가 경계 근처 프레임을 192x108 흑백으로 읽어 우선순위대로 자르는 시각을 정한다:

1. **검은 화면** (밝기 < 12) → 그 구간에서 가장 어두운 프레임들의 가운데. 검은 바탕 위 문구 카드(실측 4프레임)는 피한다
2. **장면 전환** (전체 변화량 > 30) → 새 장면의 첫 프레임
3. **자막만 바뀜** (자막 영역 변화 > 8 이고 전체 변화의 3배 이상) → 새 자막이 처음 뜨는 프레임
4. 그 외 → 문장 사이 가장 조용한 지점 (이전 방식)

2·3은 앞 문장 끝 0.15초 전 ~ 다음 문장 시작 0.05초 뒤 안에서만 찾는다 (말 자르기 방지). 결과는 `work/cut_refine.json`에
문장 경계 단위로 캐시하고, 처리 6단계·저장 직후(백그라운드)·내보내기 직전에 없는 것만 계산한다 (경계당 약 0.2초).
화면의 경계 핸들에 "검은 화면 / 장면 전환 / 자막 바뀜 / 소리 쉼"을 표시한다.

실측 결과: 검은 화면 4 · 자막 1 · 장면 1, 6곳 모두 앞 편 마지막 프레임과 뒤 편 첫 프레임을 눈으로 확인.

**같이 고친 버그**: 내보내기가 길이(`-t`)로만 자르면 ffmpeg가 끝에 프레임을 하나 더 넣는 경우가 있어 앞 편 마지막
프레임에 다음 편 화면이 찍혔다 (첫 시험에선 우연히 안 보였음). 이제 영상은 프레임 수(`-frames:v`)로 자른다 -
0.6초·2.3초 길이로 바꿔 자르고 프레임 수가 계산과 일치(55/55)하는 것까지 확인.
