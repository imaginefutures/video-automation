# R8. 실패해도 떠나지 않게

상태: 🔄 부분 완료(10-01) · 우선순위 2 · 배경: [`왜-이탈하는가.md`](왜-이탈하는가.md)

10-01: 세 항목 중 서버·화면이 필요 없는 아래 두 개를 `scripts/run.py`에서 끝냈다(server.py/web/index.html은 지금 여러 세션이 미커밋 상태라 건드리지 않음) - 실제 실패(LLM 쪽을 일부러 실패시키는 더미 스크립트)로 양쪽 경로 모두 테스트 확인.
- **단계 실패 시 원인 안내**: `step()`이 실패를 잡아 "위 에러 메시지가 원인(API 키 만료/네트워크/ffmpeg가 흔함) - 단계별로 캐시되니 원인 해결 후 같은 명령으로 다시 실행하면 이어서 진행됨"을 출력하고 다시 던진다. **"브라우저에 재시도 버튼"은 못 함** - 지금 구조에서는 처리 단계가 전부 끝나야 서버가 열려서, 실패 시점엔 애초에 떠 있는 브라우저 화면이 없다(R2 "브라우저 먼저 열기"가 먼저 끝나야 버튼을 놓을 자리가 생김 - 그 항목은 회귀 위험으로 미착수). 지금은 터미널에 원인+재시도 안내로 동등한 역할
- **LLM 실패 시 결정론적 자동 대체**: Stage 1/2·화자 블록(이미 `--no-llm` 결정론적 경로가 있는 세 단계)이 LLM 호출 실패로 죽으면 `step()`이 자동으로 `--no-llm`을 붙여 한 번 더 시도 + "검토 항목이 평소보다 많을 수 있음" 안내. 파이프라인이 LLM 장애로 완전히 멈추지 않음

**남은 것**: 영수증에 영상당 처리 비용 추정 표시 — server.py/web/index.html 필요, 지금 두 파일이 다른 세션 작업과 섞여 있고 P4(검토 화면 재설계)가 영수증 영역 자체를 다시 설계 중이라 그쪽이 정리된 뒤가 안전함
