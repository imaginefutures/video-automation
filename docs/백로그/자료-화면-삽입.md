# 자료 화면 삽입 — 컷편집이 끝난 영상에 이미지·모션그래픽을 만들어 FCP 타임라인 제자리에 얹기

상태: 🔄 V1·V2 1차 구현 (10-09) — 인서트 편집 화면(`/insert`) + 형태 결정 + 텍스트·이미지 생성 + FCPXML 내보내기. 영상(모션그래픽)도 10-09 2차로 생성까지 · 결정 기록은 맨 아래 · 문서 지도: [`../README.md`](../README.md)
**무엇을·언제·왜 넣는지의 기준은 [`../인서트-가이드.md`](../인서트-가이드.md)(완성본 3편 분석)를 따른다.** 이 문서는 그 기준을 자동화하는 방법을 다룬다. 둘이 어긋나면 가이드가 우선이고, 이 문서를 고친다.
이 문서는 [`R6-출력-확장.md`](R6-출력-확장.md) 5번 "자료 화면 제안"과 [`../미결-사항.md`](../미결-사항.md)의 "자료 화면 방식" 항목을 대체한다.

## 한 문장

**컷편집을 완료하면 프로젝트가 "자료 화면" 단계로 넘어가고, 사용자가 인서트를 넣고 싶은 대본 구간을 지정하면,
시스템이 그 구간의 내용·앞뒤 문맥·역할을 보고 텍스트 / 이미지 / 영상 중 형태를 정해 만들고, FCPXML의 연결 클립으로 정확한 시각에 얹어 준다.**
영상은 Opus 5.5가 레퍼런스 라이브러리([`../../video-references/opus-5.5/`](../../video-references/opus-5.5/_META.md))를 참고해 코드로 만드는 모션그래픽이다.

FCP에서 사람이 자리를 찾아가 하나씩 넣을 필요가 없다. 연결 클립(`lane="1"`)으로 넣으면 FCP를 열었을 때 이미 제자리에 있다 (아래 "FCP 연계").

## 처음 구상과 무엇이 달라졌나

처음 구상: 컷편집 완료 → 컷 잠금 → 대본 드래그 → 그 구간용 이미지(Nano Banana/GPT) 또는 영상(Opus 5.5) 생성 → FCP에서 사람이 자리 찾아 넣기.

벤치마킹(OpusClip, Descript, Submagic, Captions, Synthesia, HyperFrames 등, 2026-10 조사)과 코드 확인 결과 다섯 가지를 바꾼다.

| # | 처음 구상 | 바꾼 것 | 이유 |
|---|---|---|---|
| 1 | FCP에서 수동 배치 | **FCPXML 연결 클립으로 자동 배치** | 현재 `export_fcpxml.py`가 이미 세그먼트별 타임라인 위치를 계산한다. 그 위에 `lane="1"` 자식만 붙이면 된다. 이게 가능하면 기능 가치가 몇 배 |
| 2 | 드래그가 유일한 입구 | ~~AI 제안 목록이 기본, 드래그는 보조~~ → **사용자 지정이 입구, 형태는 시스템이 결정** (10-09 사용자 결정) | 자리는 사람이 고르고(넣고 싶은 곳을 사용자가 가장 잘 안다), 그 자리를 어떤 형태로 채울지를 시스템이 판단한다. 대본 전체 자동 제안은 V4 보조 기능으로 미룸 |
| 3 | 이미지 or 영상 두 종류 | **텍스트 / 이미지 / 영상 3형태, 텍스트가 기본** (완성본 3편에서도 글자 인서트가 절반 이상 — [`../인서트-가이드.md`](../인서트-가이드.md)) | 이 채널은 논문·숫자·인용이 핵심. 이미지 모델은 한글을 틀리게 그리고, 틀린 글자 하나에 재생성이 필요하다. HTML 카드는 글자를 우리가 조판하니 **오타 0, 재생성 없이 글자만 수정**. Synthesia·ChatCut·Videotto가 이 방향 |
| 4 | 구간마다 따로 생성 | **채널 스타일 시트로 고정** | 클립마다 화풍이 흔들리는 "스타일 드리프트"가 가장 흔한 불만. `split_intro.py`의 `BRAND_STYLE`(크림 + 딥 바이올렛 #4A1B6C)을 확장해 모든 생성에 주입 |
| 5 | 컷편집 완전 잠금 | **잠그되, 자료 화면은 단어에 붙여 둔다** | 자료 화면의 위치를 타임라인 초가 아니라 원본 단어 번호(`wi`)로 저장하면, 혹시 컷을 다시 열어도 위치가 자동으로 따라온다. 잠금은 실수 방지용 UI이고 데이터가 깨지는 구조가 아니다 |

추가로 넣는 아이디어:
- **촬영 중 말로 남긴 표시 감지.** [`../촬영-가이드.md`](../촬영-가이드.md) 6장이 이미 "여기 그래프가 나옵니다"라고 말해 두라고 안내한다. 이런 발화를 찾아 1순위 제안으로 올린다
- **버전을 FCP에서 바꿔 끼우기.** 한 자리에 여러 버전을 만들었으면 FCP의 오디션(`<audition>`)으로 넣어, FCP 안에서 A/B를 고를 수 있게 한다
- **정적 미리보기 먼저, 비싼 렌더는 승인 후.** 모션그래픽은 대표 프레임 몇 장으로 먼저 보여 주고 승인한 것만 전체 렌더 (HeyGen Storyboard mode 방식)

## 사용 흐름

```
컷편집 검토 → [컷편집 완료] → ─ 자료 화면 단계 ─────────────────────────────────────
                               1. 대본에서 인서트 넣을 구간 드래그 → [+ 인서트]
                               2. 형태 결정 (자동, 구간당 LLM 1회): 텍스트 / 이미지 / 영상 / 실물 요청
                                  + 레이아웃·글자 초안·이유·다른 형태 대안 → 사용자가 그대로 두거나 바꿈
                               3. 생성 → 미리보기 (영상은 대표 프레임 먼저, 승인 후 전체 렌더)
                               4. 버전 고르기 · 글자 고치기
                               5. [FCP로 내보내기] → <이름>.fcpxml (컷 + 인서트)
```

### 1. 컷편집 완료와 잠금

- 지금은 `confirm()`이 `confirmed_at`만 찍고 이후 편집을 막지 않는다 (server.py `_apply`가 확인 안 함). 새로 **`stage: "cut" | "visuals"`** 를 `decisions.json`에 둔다
- `visuals` 단계에서는 컷 관련 단축키(C/V, Enter 살리기, 파형 편집)가 꺼지고, 대본은 **잘린 단어가 아예 안 보이는 "완성 대본"** 으로 보인다. 자료 화면은 남은 말 위에서만 고른다
- "컷편집으로 돌아가기"는 둔다(확인 모달). 돌아가도 자료 화면은 `wi` 기준이라 유지되고, 붙어 있던 단어가 잘리면 그 자료 화면만 "자리 사라짐"으로 표시
- 홈 카드 상태: 검토 중 → 컷 확정 → **자료 화면 중** → 내보냄

### 2. 자리 지정과 형태 결정

**자리 지정 (사용자)**: 검토 화면에 이미 있는 드래그 선택(`onMouseUp` → `select()`)을 재사용. 선택 후 `+ 인서트` 버튼.
구간은 문장 일부여도 되고 여러 문장이어도 된다. 위치는 `wi`(원본 단어 번호)로 저장.

**형태 결정 (`decide_insert.py`, 구간당 1회, Opus 5.5)** — 규칙은 [`../인서트-가이드.md`](../인서트-가이드.md) 8장
- 입력
  - 지정 구간 텍스트와 그 구간의 출력 길이(초)
  - 앞뒤 문맥: 앞 5문장·뒤 3문장 (구간이 질문인지 답인지, 예시의 시작인지 끝인지 판단)
  - 영상 안 위치: 지금 섹션(섹션 바 문구), 영상 전체 대본 요약(영상당 1회 만들어 캐시)
  - 주변 인서트: 앞뒤 30초 안에 이미 있는 인서트의 형태·시각 (같은 형태 연속, 너무 촘촘함 판단)
  - 인서트 가이드 본문 (프롬프트에 그대로 넣음)
- 출력: `{form, layer, layout, content, reason, alternatives[], warnings[]}`
  - `form`: `text` / `image` / `video` / `asset`(책 표지·논문 캡처·SNS 캡처·실제 영상처럼 만들면 안 되는 실물 → 사용자에게 파일 요청)
  - `layer`: 가이드의 5층 중 하나 (구조 / 요점 / 근거 / 장면 / 목소리)
  - `content`: 텍스트면 문구 초안(슬로건으로 다시 쓴 것), 이미지면 장면 묘사 + 얹을 글자, 영상이면 움직임 구성(장면별 무엇이 어떻게 바뀌는지)
  - `warnings`: "개인 일화 구간이라 원본 완성본들은 비워 둠", "8초 전에 같은 형태 인서트 있음", "숫자가 대본과 다름" 같은 주의
- 결정은 제안이다 (원칙 3). 사용자는 형태를 바꾸거나 글자를 고칠 수 있고, 바꾼 기록은 이후 판단 개선의 근거로 남긴다
- 숫자·연구 결과·인명은 대본에 있는 것만. 지어내지 않는다 (아래 6장 검증)

### 3. 무엇을 만드나 — 텍스트 / 이미지 / 영상

| 유형 | 만드는 법 | 글자 | 비용·시간(추정) | 쓰는 곳 |
|---|---|---|---|---|
| **텍스트** | 가이드 스타일대로 만든 HTML 템플릿(상단 요약·섹션 바·노란 코멘트·챕터 카드·인용 카드·누적 목록) + 결정 단계의 문구. Playwright → 투명 PNG(정지) 또는 ProRes 4444(쌓이는 목록·단어 하이라이트처럼 바뀌는 것) | 우리가 조판, 오타 0, 수정 즉시 | LLM 거의 0, 렌더 수 초 | 구조, 요점, 근거 요약, 편집자 코멘트 |
| **이미지** | 이미지 모델, 글자 없이, 스타일 고정. 삽화 또는 생성 사진. 글자(노란 대사·라벨)는 텍스트 레이어로 위에 얹음 | 이미지 안엔 넣지 않음 | 장당 약 $0.05, 약 30초(실측) | 예시 장면, 가상 인물, 비교 2장, 개념 삽화 |
| **영상** | Opus 5.5(effort high)가 레퍼런스를 보고 `seek(t)` 단일 HTML을 작성 → Playwright 프레임 렌더 → ProRes 4444 | 코드 안 글자, 수정 가능 | 개당 수 달러, 수 분 | 시간에 따라 바뀌는 것: 과정·단계, 인과 연쇄, 상태 변화, 숫자 변화 |
| **실물** | 만들지 않는다. 사용자에게 파일 요청(책 표지, 논문 캡처, SNS 캡처, 실제 촬영 영상), 받으면 레이아웃만 입혀 배치 | — | — | "이 책", 논문 언급, 설문 캡처, 다미 장면 |

**텍스트가 기본값이다.** 완성본에서도 가장 많고, 가장 싸고, 가장 안 틀린다. 이미지는 장면을 보여 줘야 할 때, 영상은 움직임이 아니면 설명이 안 될 때만.

**모션그래픽과 레퍼런스 라이브러리**
- [`../../video-references/opus-5.5/_META.md`](../../video-references/opus-5.5/_META.md)의 용도별 표에서 유형에 맞는 레퍼런스 1~2개를 고른다
- Opus에는 **레퍼런스의 프롬프트 구조 + 영상에서 뽑은 대표 프레임 6장**을 같이 준다. Claude API는 영상 자체를 못 받으므로 프레임으로 넘긴다
- 구조는 라이브러리에서 검증된 `seek(t)` 단일 HTML 패턴을 강제한다(조회 100만+ 사례, 프레임 단위 결정론 렌더라 재현·재시도가 쉽다)
- 프롬프트에 항상 넣는 규칙: 채널 스타일 시트, 1920×1080, 길이(구간 길이에 맞춤), "빈 화면 금지", "강조색 하나", 한글 폰트 지정
- 렌더 후 대표 프레임을 다른 모델이 검사 → 문제 있으면 1회 수정 (아래 검증)

**생성 사진 규칙** (10-09 사용자 결정: 스톡 대신 생성)
- 사진 안에 글자를 넣지 않는다. 글자는 카드 레이어(알파 MOV)로 따로 얹어 고칠 수 있게 한다
- **실존 인물은 생성하지 않는다.** 레퍼런스 7.05.57(캐롤 드웩)처럼 실제 인물이 필요하면 공개 사진을 사용자가 넣거나, 인물 없이 이름 카드만 쓴다
- 실사풍은 "AI 티"가 나기 쉬워 판정 모델 검사 항목에 손가락·얼굴·배경 글자 깨짐을 추가

- 속도 차이(약 10배)는 "버전 3개 보고 고르기" UX에 직접 영향
- 단, 종합 품질은 GPT가 앞선다. **V0에서 지금 편집 중인 영상의 실제 구간 10개로 두 모델을 A/B 해서 확정한다** (메모리 규칙: 유료 API 테스트는 진행 중인 영상으로)
- 한글 렌더링을 엄밀히 잰 공개 벤치마크는 없었다. 위 한글 평가는 재판매사·블로그 수치라 참고용

### 6. 검토와 검증 — 만드는 모델 ≠ 판정하는 모델

- **카드**: 글자가 대본의 해당 구간에 실제로 있는 말인지 코드로 대조(숫자·연도는 정확히 일치해야 함). 대본에 없는 숫자가 들어가면 생성 단계에서 막는다
- **삽화·모션**: 대표 프레임을 Sonnet 5(만든 쪽이 Opus면)에게 보여 주고 "이 구간 내용과 맞나 / 글자가 깨졌나 / 금지 목록 위반" 판정. 실패면 1회 재생성, 그래도 실패면 사용자에게 표시만 하고 멈춘다(원칙 3: 자동 복구 반복 안 함)
- **사용자 화면**: 대본 옆에 자리별 썸네일. 클릭하면 그 시점부터 원본 영상 위에 자료 화면을 겹쳐 재생(브라우저 미리보기, 렌더 없음). 버전 최대 3개, 글자 수정은 카드에서 바로

### 7. FCP 연계 — 자동 배치

**결론: 된다.** 확인한 근거와 방식:

- `export_fcpxml.py`가 이미 세그먼트별 타임라인 시작 프레임(`seg_offset_frames`)과 원본 시작(`start`)을 갖고 있다
- 자료 화면이 타임라인 T에서 시작하면, **그 시각을 포함하는 세그먼트 안에 자식으로** 넣는다:
  `자식.offset = 부모.start + (T − 부모.offset)` — 타임라인 시각이 아니라 **부모의 원본 시간 기준**이라는 게 흔한 함정. 모두 정수 프레임으로 계산 (Apple 문서 "Timing Attributes", 우리 마커 코드도 같은 좌표계)
- 자료 화면이 여러 세그먼트에 걸쳐도 된다 — 연결 클립은 부모 길이에 잘리지 않는다 (Apple 문서 원문 확인)
- 이미지: `<video>` 요소 + 프레임레이트 없는 still format. 영상: `<asset-clip>`, 시퀀스와 같은 fps
- 역할(role)로 묶는다: `자료화면.카드` / `자료화면.삽화` / `자료화면.모션` → FCP 타임라인 인덱스에서 한 번에 켜고 끄기
- 버전이 여러 개면 `<audition>`으로 넣어 FCP 안에서 바꿔 끼우기
- 알파 영상은 **ProRes 4444** (`prores_ks -profile:v 4444 -pix_fmt yuva444p10le`). FFmpeg 7.0 미만으로 만든 4444는 FCP에서 알파가 검게 나온다는 보고가 있어 **FFmpeg 7 이상을 요구**
- FCPXML 버전은 1.11 유지 (필요한 요소가 전부 1.10 DTD에 있음)

```xml
<asset-clip ref="vautoasset1" name="seg_005" offset="900900/30000s" start="1501500/30000s" duration="300300/30000s">
  <!-- 타임라인 1000프레임에 시작: 1500 + (1000 − 900) = 1600 -->
  <asset-clip ref="vis012" lane="1" offset="1601600/30000s" duration="450450/30000s"
              srcEnable="video" videoRole="자료화면.카드" name="012 수면 시간 비교"/>
</asset-clip>
```

**FCP에 넣은 뒤 하나만 다시 만들고 싶을 때** — 표준 FCPXML로 "이미 가져온 프로젝트에 하나만 갱신"하는 방법은 없다.
- 기본 운영: **자료 화면을 다 끝낸 뒤 한 번 내보내 FCP로 가져간다.** 내보내기 버튼에 "FCP에 가져온 뒤 다시 내보내면 FCP에서 한 작업은 새 프로젝트로 분리된다"를 적는다
- 늦은 수정: 파일 경로를 `video-edit/<이름>/visuals/012.mov`로 고정해 두고 덮어쓴 뒤 FCP의 **File > Relink Files**. 조건: 같은 fps, 길이가 원래 이상. 생성기가 이 계약을 지킨다. FCP 가져오기 설정이 "Leave files in place"여야 한다

### V0 1차 결과 (10-09, FCP 12.3, BS145)

우리 코드가 만든 FCPXML을 그대로 가져와 사용자가 눈으로 확인 — **4건 모두 성공**:
- ProRes 4444 알파(FFmpeg 9, `yuva444p`)가 반투명(alpha 150)까지 FCP에서 투명하게 보임
- 연결 클립이 세그먼트 경계를 넘어가도 끊기지 않음 (`offset = 부모.start + (T − 부모.offset)` 공식 확인)
- 정지 PNG: `<video>` + `FFVideoFormatRateUndefined` 포맷, asset `duration="0s"`, **`start` 생략 가능** (아래 4번 해결)
- `<audition lane="1">` 안에 자식 2개(자식 offset = audition offset)로 FCP에서 Y 키 버전 전환 (아래 1번 해결)
- 덤으로 발견한 기존 버그: 마지막 구간이 1프레임 미만이면 `export_fcpxml.py`가 영상 끝 다음 칸을 가리켜 FCP가 "미디어가 없는 유효하지 않은 편집"으로 거부 → 영상 끝에 맞춰 자르고 빈 구간은 버리게 수정
- 테스트 생성기: 세션 스크래치의 `v0_alpha_test.py` (V1에서 정식 코드로 옮김)

### V0에서 반드시 확인할 미확인 항목 (조사로 결론 못 냄)

1. 오디션·중첩 spine 안 자식의 offset 기준
2. `adjust-transform` scale이 배율(1=100%)인지 퍼센트인지 — 문서끼리 다름
3. 키프레임 시간 기준과 `adjust-blend`의 param 이름
4. 정지 이미지 `<video>`의 `start` 생략 가능 여부
5. 사용자 정의 역할(role)이 가져오기 때 자동 생성되는지
6. 덮어쓴 파일을 FCP가 Relink 없이 갱신하는지
7. HEVC 알파 (안 되면 ProRes 4444만 쓴다)
8. 좌우 반분할: 원본 클립 구간에 `adjust-transform` 위치 이동 + 세그먼트 쪼개기가 FCP에서 의도대로 보이는지
9. 글자 레이아웃을 FCP 타이틀(외곽선·그림자 포함)로 넣을 수 있는지
