# R2. 시작 마찰 제거 (알림·진행 화면)

상태: 🔄 우선순위 1 부분 완료 · 2(폴더 자동 생성·분할 촬영)는 10-01 완료 · **브라우저 먼저 열기만 미착수** · 배경: [`왜-이탈하는가.md`](왜-이탈하는가.md)

09-29: **처리 완료 알림**(`run.py`의 `notify()`, macOS `osascript`)은 구현 완료 - 전사~품질 루프까지 다 끝나고 검토 화면을 열기 직전에 뜬다. **브라우저를 먼저 여는 것(처리 중 진행 화면)은 이번엔 범위 밖으로 남겼다** — `Session.__init__`이 `transcript.json` 존재를 전제하고 있어(없으면 즉시 실패), 처리 시작과 동시에 서버를 띄우려면 Session이 "아직 처리 중"인 부분 상태를 견디도록 바꿔야 하고, `run.py`가 지금처럼 각 단계를 순차 `subprocess.run(check=True)`로 끝난 뒤 서버를 마지막에 여는 구조도 동시 실행 구조로 재설계해야 한다 — 라이브 브라우저 테스트 없이 하기엔 회귀 위험이 커서 미룸.

10-01: **폴더 자동 생성**·**여러 파일 분할 촬영 지원** 둘 다 구현 완료 (`run.py`의 `auto_create_project()`/`concat_segments()`) - 서버·검토 화면 쪽은 손대지 않는 범위라 위 "브라우저 먼저 열기" 항목과 무관하게 독립적으로 끝냈다.
- `python scripts/run.py` (폴더 인자 생략) → `videos/` 바로 아래 떨어진 mp4 하나를 찾아 그 이름으로 `videos/<이름>/raw.mp4`를 만든다. 둘 이상이면 어느 게 한 영상인지 추측하지 않고 사용자에게 직접 정리하도록 안내(최대 삭제 방침과 같은 이유로 - 조용히 잘못 묶지 않음)
- 프로젝트 폴더 안에 `raw.mp4`가 없고 대신 `01_intro.mp4`/`02_main.mp4`처럼 mp4가 2개 이상이면, 이름 순으로 이어붙여(`ffmpeg concat`, 무손실 스트림 복사) `raw.mp4`를 만든다. 원본 세그먼트는 지우지 않고 그대로 둔다
