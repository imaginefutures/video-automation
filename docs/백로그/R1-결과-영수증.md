# R1. 결과 영수증 — 매번 이득을 숫자로 보여준다

상태: ✅ 09-29 구현 완료 · 우선순위 1 (다음 촬영분 전) · 배경: [`왜-이탈하는가.md`](왜-이탈하는가.md)

`server.py`의 `Session.receipt()`가 확정 모달과 `~/.video-cut/history.jsonl`(채널 전체, 영상별 한 줄) 양쪽에 같은 계산을 공유한다. 검토 화면 첫 진입 시 사이드바에 "예상 N분"도 표시(`payload()`의 `review_estimate`, 카드당 20초 가정 - L2 실측 데이터가 쌓이면 교체 가능). BS145로 실제 확정까지 검증 완료(`decided_by`, `restored`, `review_sec` 등 정상 계산). 다음 영상부터 "지난 영상 대비" 비교가 실제로 뜬다.

**단순화한 부분**: `llm_cost_usd_est`·`processing_sec`(파이프라인 처리 시간)는 아직 트래킹 인프라가 없어 이번엔 제외 — 백로그/R8-실패-대응.md의 "영수증에 비용 추정 표시"와 함께 처리하는 게 자연스럽다. `seam_min_score`(이음새 최저 점수)는 현재 judge 스키마에 단일 점수 필드가 없어 `seam_flag_rate`(flag 비율)로 대체.

확정 모달에 이번 영상의 결과를 보여주고, 채널 누적 기록에 한 줄 추가한다.

```
이번 영상  24:47 → 22:31  (잘라낸 2분 16초)
자동 처리  NG 17 · 쉼 223 · 대화 블록 1     내가 판단한 것  9건
검토 시간  6분 40초   (지난 영상 11분 20초 ▼41%)
누적       4편 · 검토 시간 평균 ▼  · 신고된 오삭제 0건
```

- 검토 시간은 `actions.log`의 첫 결정 ~ 확정 타임스탬프로 계산 (이미 기록 중, 추가 계측 없음)
- 확정 시 `~/.video-cut/history.jsonl`에 한 줄 기록: 영상, 원본 길이, 결과 길이, 자동 처리 수, 사람 결정 수, 검토 시간, 신고된 오삭제 수, 처리 비용 추정. **[`R4-학습-가시화.md`](R4-학습-가시화.md)·[`R7-프로젝트-홈.md`](R7-프로젝트-홈.md)의 데이터 기반**
- 검토 화면 첫 진입 시 "검토 항목 9건, 예상 5분"을 먼저 보여준다. 막막함을 없애는 게 목적
- 성공 기준: 2편째부터 "지난 영상 대비" 수치가 나오고, 사용자가 그걸 본다
