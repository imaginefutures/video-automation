# 07. 구현 계획

---

## 1. 단계

| 단계 | 내용 | 선행 | 완료 기준 |
|---|---|---|---|
| **P0** 기준선과 평가 데이터 | BS145 v2 검토·확정 완료, 손상 주입 세트, `eval_seams.py`, `rules/` 분리 | — | 06 문서의 V1~V11을 잴 수 있음. 현재 검토 시간 기준선 확보 |
| **P1** 음향 지도와 스냅 | `audio_map.py`, 스냅, 숨소리 인식, 비전사 소리 검출 | P0 | V1, V2, V10 통과 |
| **P2** 최대 삭제 라우팅과 부분 루프 | route + flag 형식, 초안 조립, 대안·관문·교차 판정·선택·반복 | P1 | V3, V4, V9, V11 통과. BS145에서 경고 없는 복원 0 |
| **P3** 전체 루프 | 결과물 표현, PD·시청자 평가, 결합, 재투입 | P2 | V5~V8 통과 |
| **P4** 검토 화면 | 두 층 큐, 카드, 한 키 루프, 대안 키, 이음새 릴, 변경분 재검증, 영수증 | P2 (P3 없이도 시작 가능) | 새 영상에서 검토 시간이 기준선보다 짧음 |
| **P5** 지식 층과 학습 | L2 기록, few-shot 검색, L1 규칙 확장, 규칙 제안, 내 규칙 화면 | P4 | 2편째부터 규칙 제안이 나오고, few-shot에 L2 사례가 들어감 |

P4는 P2가 끝나면 P3와 병렬로 진행할 수 있다. P5의 L2 기록 부분(`cases.jsonl` 쓰기)은 데이터를 일찍 쌓기 위해 P4와 함께 넣는다.

### 2.3 데이터 형식 호환
- 기존 영상의 `ng.json`(AUTO_SAFE/REVIEW/KEEP)은 읽을 때 변환한다: AUTO_SAFE → `CUT`, REVIEW → `CUT` + `restore`, KEEP → `KEEP`.
- 기존 prefs(version 1, `ng_case` 횟수)는 version 2의 `stats`로 옮긴다.

## 3. 비용과 시간 (24분 영상, 추정치, P0 이후 `llm_calls.jsonl`로 실측)

| 구간 | 추가 LLM 호출 | 추가 시간 |
|---|---|---|
| P1 음향 지도·스냅 | 0 | +20~40초 |
| P2 부분 루프 | 이음새 40~60개 × 대안 ≤ 7 → 묶음 호출 약 5~15회/반복, 최대 3회 + 재전사 1~3회 | +2~4분 |
| P3 전체 루프 | PD 1 + 시청자 1 (+ 재질의 소량), 최대 2회 | +1~3분 |
| **합계** | | **+3~6분, LLM 비용 영상당 1~2달러 내외 예상** |

재전사는 Scribe 요금이 추가된다. 이음새 클립을 묶어 보내므로 영상당 수 분 분량의 오디오 수준이다.

## 4. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 평가자가 실제 품질을 반영하지 못함 | 루프가 엉뚱한 방향으로 최적화 | P0 검증을 먼저 통과해야 루프를 켬 (06 문서) |
| 최대 삭제로 flag가 너무 많아짐 | 검토가 오히려 늘어남 | 빠른 확인 층 분리, flag 정밀도 지표, 규칙 제안으로 flag 축소 |
| 경고 없는 복원 발생 | 신뢰 붕괴 | 최우선 수정, L0 반례 승격, 해당 유형 기준값 재조정 |
| 재전사가 한국어 짧은 클립에서 불안정 | G2 오탐 | 앞뒤 문맥을 1.5초 → 2.5초로 늘려 비교, 정규화 규칙 보강. 그래도 불안정하면 G2를 점수 항목으로 강등 |
| 루프가 진동 | 처리 시간 낭비 | 진동 감지 시 고정 + flag (02 문서 2.7) |
| 모델 ID 변경·지원 종료 | 호출 실패 | 모델 ID를 `rules/defaults.yaml`로 모으고, 실패 시 해당 단계만 결정론 결과로 대체하고 알림 ([`../백로그/R8-실패-대응.md`](../백로그/R8-실패-대응.md)) |
| 두 평가자 지적이 거의 같음 | 관점 분리가 무의미 | V8로 감지, 시청자 입력과 페르소나 재설계 |
| L2 사례가 편향됨 (한 영상의 특이 취향) | few-shot이 다음 영상을 왜곡 | 영상당 사례 수 상한, 최근 가중치, 반대 방향 예시 필수 |

## 5. 미결 사항

- [ ] **지루한 구간 자동 삭제 여부**: 현재는 시청자 평가의 `boring`을 제안 카드로만 둔다. 내용 편집까지 최대 삭제 방침에 넣을지
- [ ] **`Enter` 키 배정**: 복원 후보 카드에서 가장 잦은 동작("삭제 유지")을 `Enter`로 바꿀지. 첫 두 편의 `actions.log` 동작 비율로 결정
- [ ] **전체 루프 재실행 시점**: 처리 단계에서만 돌릴지, 사용자 검토 후 확정 직전에 한 번 더 돌릴지 (시간 +1~3분)
- [ ] **PD·시청자 평가의 thinking 사용**: V5~V6에서 켠 것과 끈 것을 비교해 결정
- [ ] **숨소리 기본값**: 통째로 지우기(현재 기획) vs 남기기. 채널 스타일 확인 필요
- [ ] **시청자 페르소나 세부**: 채널 실제 시청자층 정보 (연령대, 주 시청 환경)
- [ ] **추임새 어휘 확장 범위**: "음/어/아" 외에 "그니까", "이제", "약간" 등을 L0 후보로 넣을지, L2 통계 기반 제안으로만 늘릴지
