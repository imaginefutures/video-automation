# 02. 품질 루프 — 부분 루프와 전체 루프

자동 컷 초안(01 문서 9단계)을 받아, 검토 화면에 넘기기 전에 스스로 고치는 구조다.

---

## 1. 구조

```
draft_cuts.json
      │
      ▼
 ┌─ 부분 루프 (이음새 단위) ─────────────────────────────┐
 │  패킷 → 대안 → 관문 → 교차 판정 → 점수 → 선택           │
 │  바뀐 이음새와 양옆만 재검사 · 최대 3회                  │
 └──────────────────────┬────────────────────────────────┘
                        ▼
 ┌─ 전체 루프 (영상 단위) ───────────────────────────────┐
 │  결과물 표현 → PD 평가 ∥ 시청자 평가 ∥ 객관 지표         │
 │  결합 → 추가 컷·지적 이음새를 부분 루프로 · 최대 2회      │
 └──────────────────────┬────────────────────────────────┘
                        ▼
             restore_queue.json (검토 화면)
```

**역할 분담**
- 부분 루프는 "이 컷 하나가 매끄럽게 들리고 읽히는가"를 본다.
- 전체 루프는 컷들이 모였을 때만 드러나는 문제를 본다. 흐름 단절, 전체 리듬, 먼 반복, 앞에서 잘린 내용을 뒤에서 참조하는 경우, 그리고 부분 루프가 놓친 덜 지운 곳이다.

---

## 2. 부분 루프

### 2.1 대상 선정

| 이음새 종류 | 대상 여부 |
|---|---|
| NG, 화자 블록, 추임새, 비전사 소리, 전체 맥락 컷 | 전부 |
| 쉼 트림 | 1차 음향 점수(2.5의 음향 항목만)가 0.7 미만인 것만 |
| 전체 루프가 되돌려 보낸 이음새 | 전부 |

### 2.2 이음새 패킷

```
[CUT 12] NG-B · 신뢰도 0.71 · 복원 후보 · 컷 생성: claude-sonnet-5
앞 문맥(유지)  …아이의 자존감이 잘 서기 위해서는
잘린 부분      나에 대한, 음. 자존감이 잘 서기 위해서는
뒤 문맥(유지)  나에 대한 믿음이 필요해요.
결과 문장      …아이의 자존감이 잘 서기 위해서는 나에 대한 믿음이 필요해요.
음향           레벨 차 +1.2dB · 컷 지점 무성 · 숨소리 1회 · F0 연속
```

- 앞·뒤 문맥은 각각 이음새에서 가장 가까운 문장 경계까지, 최대 2문장이다.
- 잘린 부분은 컷이 길면(30단어 초과) 앞 15단어 … 뒤 15단어로 줄이고 전체 길이를 표시한다.

### 2.3 대안 생성 (결정론)

| 대안 | 내용 | 자동 적용 가능 |
|---|---|---|
| 원안 | 초안 그대로 (1차 스냅 적용됨) | ✅ |
| 정밀 스냅 | 경계를 영교차점으로, 컷 바깥 쪽 쉼에서 에너지 최저점까지 확장 | ✅ |
| 앞/뒤 한 단어 확장 | 컷을 한 단어 넓힘 | ✅ (방침 1) |
| 잔여 조각 흡수 | 컷 바로 옆의 추임새·비전사 소리·2음절 이하 단어 조각까지 포함 | ✅ |
| 앞/뒤 한 단어 축소 | 컷을 한 단어 좁힘 | ✅ |
| 취소 | 컷 없음 | 관문 탈락 시에만 |

대안은 이음새당 최대 7개다. 확장과 축소는 한 단어까지만 하고, 더 필요하면 다음 반복에서 한 단어씩 더 간다.

### 2.4 관문 (통과/탈락)

| 관문 | 방법 | 초기 기준 (06 문서에서 캘리브레이션) |
|---|---|---|
| G1 음절 절단 없음 | 컷 경계 ±20ms의 RMS | 룸톤 기준 +6dB 이하 |
| G2 잔여음 없음 | 이음새 앞뒤 1.5초를 렌더링해 Scribe로 재전사하고 기대 결과 문장과 비교 | 정규화 후 추가·누락 음절 0 |
| G3 숨소리 처리 | 음향 지도의 숨소리 구간과 컷 경계의 겹침 | 숨소리를 가르지 않음, 숨소리 2회 연속 없음 |
| G4 말소리 보존 | 컷 안에 VAD 말소리가 있는데 대응하는 전사 단어가 컷 대상이 아닌 경우 | 0 |

**재전사 비용 줄이기**: 이음새 클립(각 3초)을 1.5초 무음을 사이에 두고 하나의 오디오로 이어붙여 한 번에 보낸다. 결과 타임스탬프로 클립별로 나눈다. 모든 대안을 보내지 않고 G1·G3·G4를 통과한 대안만 보낸다.

### 2.5 교차 판정과 점수

**교차 판정** (G1~G4를 통과한 대안만)
- 판정 모델은 그 컷을 만든 모델과 다르게 한다. 규칙은 [4. 모델 교차](#4-모델-교차) 참고.
- 이음새 20~30개를 한 호출로 묶고 병렬로 호출한다.
- few-shot: L0의 좋은/나쁜 이음새 예시 + L2에서 사용자가 "어색해서 복원한" 이음새 (04 문서).

체크리스트와 출력 (대안마다)

```json
{
  "seam_id": 12, "alt": "extend_after_1",
  "grammar_ok": true,            // C1 결과 문장이 문법적으로 완결되는가
  "duplicate_left": false,       // C2 같은 말의 두 시도가 여전히 둘 다 남았는가
  "reference_broken": false,     // C3 "그래서/이게" 등이 가리키던 대상이 잘렸는가
  "info_lost": "none",           // C4 none | minor | major — 잘린 부분에만 있는 정보
  "info_lost_what": "",
  "note": "잔여 '나에 대한, 음.'까지 흡수하면 자연스럽게 이어짐"
}
```

**점수** (0~1, 가중치는 초기값이며 06 문서에서 캘리브레이션)

| 항목 | 내용 | 가중치 |
|---|---|---|
| 음향 연속성 | 앞뒤 200ms 레벨 차, F0 불연속, 룸톤 차이 | 0.4 |
| 문장 연결 | C1·C2·C3 (하나라도 실패하면 0) | 0.4 |
| 리듬 | 이음새 앞뒤 쉼 길이가 문맥별 목표 범위([`../현재-설계/무음-리듬.md`](../현재-설계/무음-리듬.md)) 안인지 | 0.2 |

### 2.6 선택 규칙

1. G1~G4를 통과하고 C1~C3을 만족하는 대안만 남긴다.
2. 그중 **가장 많이 지우는 대안**을 고른다. 삭제량이 같으면 점수가 높은 쪽을 고른다.
3. 선택한 대안의 C4가 `minor`이면 `flag: restore`, `major`이면 `flag: restore` + 우선순위 상향이다.
4. 선택한 대안의 점수가 기준(초기 0.7) 미만이면 `flag: restore`를 붙이고 사유에 "이음새 점수 낮음"을 쓴다.
5. 조건을 만족하는 삭제 대안이 없으면:
   - 관문은 통과했지만 C1~C3만 실패한 대안이 있으면, 그중 점수가 가장 높은 것을 적용하고 `flag: restore`를 붙인다.
   - 모든 삭제 대안이 관문에서 탈락하면 `취소`를 적용하고 `flag: delete`(삭제 후보)를 붙인다.

### 2.7 반복과 종료

- 한 번의 반복에서 바뀐 이음새와 그 양옆 이음새만 다시 2.2부터 검사한다 (바뀐 컷이 이웃 이음새의 문맥을 바꾸기 때문이다).
- 종료 조건 (하나라도 만족하면 종료)
  - 바뀐 이음새가 없음
  - 3회 도달
  - 같은 이음새가 두 대안 사이를 오감 (진동). 이 경우 점수가 높은 쪽으로 고정하고 `flag: restore`를 붙인다.

## 3. 전체 루프

### 3.1 결과물 표현 (로컬)

모든 컷을 적용한 결과를 두 형태로 만든다.

**PD용**: 원본 전사 위에 컷을 표시한 형태

```
…아이의 자존감이 잘 서기 위해서는 ~~나에 대한, 음. 자존감이 잘 서기 위해서는~~⟦C12 NG-B 0.71⟧ 나에 대한 믿음이 필요해요.
```

**시청자용**: 결과물만. 잘린 내용과 컷 표시는 없다.

```
[03:12] 아이의 자존감이 잘 서기 위해서는 · 나에 대한 믿음이 필요해요. ·· 그러면 이 믿음은
[03:18] 어디서 오느냐. ⟨숨 없이 급하게 이어짐⟩ 연구에 따르면…
```

- 쉼 표시: `·` 0.1~0.3초, `··` 0.3~0.6초, `···` 0.6초 이상
- 음향 번역 표시: 이음새 점수의 음향 항목이 나쁜 경우에만 붙인다.

| 음향 수치 | 표시 |
|---|---|
| 레벨 차 ≥ +4dB | ⟨갑자기 소리가 커짐⟩ |
| 레벨 차 ≤ -4dB | ⟨갑자기 소리가 작아짐⟩ |
| 쉼 < 0.08초 + 앞이 문장 끝 | ⟨숨 없이 급하게 이어짐⟩ |
| F0 하강(문장 끝 억양) 직후 문장이 이어짐 | ⟨끝난 듯하다 이어짐⟩ |
| 룸톤 차이 큼 | ⟨배경 소리가 바뀜⟩ |

- 시청자용 표현의 `[mm:ss]`는 결과물 기준 시간이다. 평가 결과를 이음새로 되돌리기 위해 결과 시간 ↔ 이음새 id 매핑을 함께 저장한다.

### 3.2 평가 (병렬)

| 평가 | 모델 | 입력 | 상세 |
|---|---|---|---|
| PD 평가 | Opus 5.5 | PD용 표현 + 편집 규칙 + L1 규칙 + L2 요약 | 03 문서 |
| 시청자 평가 | Fable 5.1 | 시청자용 표현 + 페르소나 | 03 문서 |
| 객관 지표 | 로컬 | 결과물 타임라인 | 3.3 |

24분 영상의 전사는 약 1.5만~2만 자라 한 호출에 들어간다. 더 긴 영상은 5분 단위로 나누되 앞뒤 30초를 겹쳐서 보낸다.

### 3.3 객관 지표 (LLM 없음)

| 지표 | 계산 | 쓰임 |
|---|---|---|
| 말 속도 | 결과물 1분 창별 음절/초 | 기준 분포(BS145 사람 편집본)의 상위 5%를 넘는 창 → "빽빽함" 지적과 교차 확인 |
| 쉼 분포 | 문맥별 쉼 길이 히스토그램 | 기준 분포와의 차이. 크면 L1 목표치 조정 제안 |
| 이음새 최저 점수 | 모든 이음새 점수의 최솟값 | 종료 조건, 영수증 |
| 하위 10% 점수 | 하위 10% 이음새의 평균 | 추세 모니터링 |

### 3.4 결합과 재투입

결합 규칙은 03 문서 4장. 결합 결과는 셋 중 하나다.
- **추가 컷**: 초안에 새 컷을 넣고 해당 이음새를 부분 루프로 보낸다.
- **이음새 재검사**: 지적 사유를 패킷에 덧붙여 부분 루프로 보낸다. 대안에 "쉼 늘리기"(유지 쉼 +0.1초, +0.2초)를 추가한다.
- **flag 부여 또는 상향**: 루프 없이 복원 후보 큐로 보낸다.

### 3.5 종료

- 새 지적이 없음, 또는 이음새 최저 점수 ≥ 0.7이고 두 평가 모두 severity high 지적이 없음, 또는 2회 도달.
- 2회째에도 남은 지적은 모두 flag를 달아 큐로 보낸다. 루프는 포기해도 사용자에게는 정보가 남는다.

## 4. 모델 교차

### 4.1 원칙
- 어떤 판정도 **판정 대상을 만든 모델이 하지 않는다.**
- 전체 루프의 두 평가자는 서로 다른 모델이다.
- 루프가 반복될 때 판정 모델은 고정한다. 반복마다 모델을 바꾸면 점수 변화가 개선인지 모델 차이인지 구분할 수 없다.

### 4.2 배정표

| 역할 | 모델 | 모델 ID |
|---|---|---|
| NG 분류 (기본) | Sonnet 5 | `claude-sonnet-5` |
| NG 분류 (에스컬레이션) | Opus 5.5 | `claude-opus-5-5` |
| 화자 블록 줄 역할 | Sonnet 5 | `claude-sonnet-5` |
| 전체 맥락 검토 | Opus 5.5 | `claude-opus-5-5` |
| 쉼 문맥 분류 | Haiku 4.5 | `claude-haiku-4-5-20251001` |
| 이음새 교차 판정 — Sonnet이 만든 컷 | Opus 5.5 | `claude-opus-5-5` |
| 이음새 교차 판정 — Opus가 만든 컷 | Sonnet 5 | `claude-sonnet-5` |
| 이음새 교차 판정 — 결정론이 만든 컷 (쉼, 비전사 소리) | Sonnet 5 | `claude-sonnet-5` |
| PD 평가 | Opus 5.5 | `claude-opus-5-5` |
| 시청자 평가 | Fable 5.1 | `claude-fable-5-1` |
| 재전사 대조 | Scribe | (LLM 아님) |

현재 코드의 `claude-opus-5`는 `claude-opus-5-5`로 갱신한다 ([`../미결-사항.md`](../미결-사항.md) 해소).

### 4.3 호출 설정
- 구조화 출력 호출은 전부 `thinking` 비활성화 (기존 원칙, [`../현재-설계/시스템-개요.md`](../현재-설계/시스템-개요.md) 모델 배정)
- 단, PD 평가와 시청자 평가는 영상 전체를 읽고 판단하므로 thinking 사용 여부를 06 문서의 검증에서 비교해 결정한다.
- 모든 LLM 호출의 입력·출력·모델·토큰 수를 `edit/llm_calls.jsonl`에 기록한다 (비용 추정과 평가자 검증용).
