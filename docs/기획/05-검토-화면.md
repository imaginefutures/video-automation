# 05. 검토 화면 — 복원을 빠르게 결정하기

**2026-10-02 정정**: 이 문서가 설계한 카드 목록(판단 필요/빠른 확인 두 층을 카드로 나열)과 선택 팝업은
10-02에 폐기하고 "읽기→추적→듣기 3단계"(텍스트 편집 → 파형 세부 편집 → 듣기)로 교체했다. 실제 동작
중인 화면은 [`../현재-설계/검토-화면.md`](../현재-설계/검토-화면.md)를 따른다. 아래 2장의 **두 층 분류
기준**(판단 필요/빠른 확인, PD·시청자 평가 배지)과 4.3절 **이음새 릴**은 여전히 유효하다 — 바뀐 건 그걸
카드 목록으로 보여주던 방식뿐이다.

품질 루프의 결과를 사용자가 가장 짧은 시간에 확인하고 복원 여부를 정하게 하는 화면 설계다. 기존 화면 구조([`../현재-설계/검토-화면.md`](../현재-설계/검토-화면.md), [`../design-system.md`](../design-system.md))를 유지하고, 사이드바의 "검토 필요" 큐와 팝업을 바꾼다.

---

## 1. 목표

- 항목 하나를 **키 한 번**으로 끝낸다.
- 카드만 보고 결정할 수 있다. 본문을 뒤지지 않는다.
- 진짜 판단이 필요한 항목과 한 번 들어보기만 하면 되는 항목을 나눈다.

---

## 2. 복원 후보 큐

### 2.1 두 층

| 층 | 내용 | 처리 방식 |
|---|---|---|
| **판단 필요** | 두 관점이 모두 지적, 정보 손실 의심, 판정 엇갈림, 사용자가 자주 복원하는 유형, 삭제 후보 | 카드를 하나씩 결정 |
| **빠른 확인** | flag는 있지만 두 평가 모두 통과했고, 사용자가 한 번도 복원한 적 없는 유형 | 이음새 릴로 연속 재생. 거슬리는 곳에서만 멈춤 |
| 제안 | 지루한 구간 등 내용 편집 제안, 아웃테이크 별표 제안, 규칙 제안 | 맨 아래. 무시해도 됨 |

### 2.2 정렬 (판단 필요 층 안에서)
1. 두 관점 모두 지적
2. 정보 손실 `major`
3. 판정이 엇갈림
4. L2에서 사용자가 자주 복원한 유형
5. 신뢰도 낮은 자동 삭제
6. 삭제 후보

같은 순위에서는 영상 시간순이다. 사용자가 영상 흐름을 따라가며 볼 수 있도록 한다.

### 2.3 사이드바 상단
```
검토 8건 · 예상 4분        빠른 확인 23건 (2분 릴)
```
예상 시간은 L2의 카드 유형별 평균 결정 시간으로 계산한다. 사례가 없으면 카드당 20초로 가정한다.

## 3. 카드

```
┌──────────────────────────────────────────────────────┐
│ NG-B · 03:12                  PD ⚠ 정보 누락  시청자 ✓ │
│                                                        │
│ …자존감이 잘 서기 위해서는                               │
│ ~~나에 대한, 음. 자존감이 잘 서기 위해서는~~               │
│ 나에 대한 믿음이 필요해요.                               │
│                                                        │
│ 결과  …잘 서기 위해서는 나에 대한 믿음이 필요해요.         │
│ 이유  같은 정보 반복 (신뢰도 0.71)                        │
│                                                        │
│ [⇧Enter 삭제 유지]  [1 앞만 살림]  [2 전부 살림]  [Enter] │
└──────────────────────────────────────────────────────┘
```

- 윗줄: 종류, 시간, 두 관점 배지 (03 문서 5장). 배지를 누르면 평가자의 사유가 보인다.
- 가운데: 이음새 패킷. 잘린 부분은 기존 본문처럼 취소선과 회색(`--cut`)으로 표시한다.
- 선택지는 부분 루프가 만든 대안에서 최대 3개를 뽑는다. 선택지마다 이음새 오디오를 미리 렌더링해 둔다.
- 삭제 후보 카드는 방향이 반대다: `[⇧Enter 유지 확정] [Enter 삭제]`

---

## 4. 조작

### 4.1 한 키 루프
```
J  → 다음 카드로 이동 + 본문 해당 위치 선택 + 이음새 자동 재생
   → 듣고 결정: Enter / ⇧Enter / 1 / 2 / 3
   → 자동으로 다음 카드로 이동 + 자동 재생
```
결정하면 바로 다음 카드로 넘어가므로, `J`는 건너뛸 때만 누른다.

### 4.2 키 배정

| 키 | 동작 | 기존 대비 |
|---|---|---|
| `Enter` | 팝업 버튼에 표시된 동작 (복원 후보 카드에서는 "살리기") | 유지 |
| `⇧Enter` | 삭제 유지 확정 | 유지 |
| `1` `2` `3` | 대안 선택 | 🆕 |
| `Shift+←` / `Shift+→` | 선택한 컷을 한 단어씩 좁히기/넓히기 | 🆕 |
| `J` | 다음 카드 (건너뛰기) | 자동 재생 추가 |
| `Space` / `X` | 듣기 / 이음새 듣기 | 유지 |
| `Z` | 정밀 조정 (파형) | 유지. 스냅이 들어가면 쓸 일이 줄어듦 |
| `R` | 이음새 릴 시작/정지 | 🆕 |
| `⌘Z` / `⌘⇧Z` | 되돌리기 / 다시 실행 | 유지 |

**미결**: 복원 후보는 대부분 "삭제 유지"로 끝날 것이므로, 가장 잦은 동작을 `Enter`로 바꿀지 결정해야 한다. 첫 두 편의 `actions.log`에서 동작 비율을 보고 정한다 (07 문서).

### 4.3 이음새 릴
- 빠른 확인 층의 모든 이음새를 앞뒤 1.5초씩 이어서 연속 재생한다. 23건이면 약 70초다.
- 재생 중에는 화면에 현재 이음새의 결과 문장만 크게 보여준다.
- 거슬리는 곳에서 `Enter`를 누르면 릴이 멈추고 그 이음새가 카드로 열린다.
- 선택 사항으로 "전체 자동 컷 릴"도 둔다 (flag 없는 컷까지 전부). 처음 몇 편에서 신뢰를 쌓는 용도다.

## 5. 기타 사이드바

### 5.1 ~~내 규칙 (L1)~~ → 구조적 의심 패턴

**2026-10-01 개정**: "내 규칙"(승인한 L1 규칙 목록, 규칙 제안 배너, "지난 영상에서 배운 규칙" 세션
배너)은 개인화 폐기로 전부 없앤다 — [`04-지식-층과-학습.md`](04-지식-층과-학습.md),
[`../남은-개발.md`](../남은-개발.md) "폐기됨". 대신:

- **구조적 의심 패턴**: 같은 구조적 태그로 결정이 한쪽으로만 쏠린 항목이 있으면 영수증에 "구조적
  의심 패턴 N건 — 버그일 수 있어요 [보기]"만 표시한다. 사용자가 끄고 켤 수 있는 규칙이 아니라
  **읽기 전용 정보**다 — 아무것도 자동으로 바뀌지 않는다.

### 5.2 품질 루프 요약 (접힌 아코디언)
- 부분 루프: 자동 개선 건수(스냅·확장·축소·잔여 흡수), 반복 횟수
- 전체 루프: PD 지적 수, 시청자 지적 수, 추가 컷 수
- 이음새 최저 점수와 그 위치 (클릭하면 이동)
- 대부분의 사용자는 열지 않는다. 신뢰가 흔들릴 때 근거를 확인하는 용도다.

## 6. 확정

### 6.1 변경분 재검증
- 사용자가 복원·조정한 이음새에만 관문 G1·G3·G4를 다시 돌린다 (G2 재전사와 LLM은 쓰지 않음).
- 걸리면 자동 스냅을 한 번 시도하고, 그래도 걸리면 확정 모달에 "3곳에서 소리가 끊길 수 있음 [듣기]"를 보여준다. 확정은 막지 않는다.

### 6.2 확정 모달 = 영수증
```
이번 영상   24:47 → 21:58  (잘라낸 2분 49초)
자동 처리   컷 312 · 자동 개선 23 · 추가 컷(PD) 4
내 결정     복원 2 / 8건 · 빠른 확인 23건 통과
검토 시간   4분 10초   (지난 영상 6분 40초 ▼37%)
배운 것     새 규칙 제안 1개 [보기]
누적        5편 · 경고 없는 복원 0건
```
- 미검토 flag 항목이 있으면 수를 보여준다 (SKILL.md 규칙).
- 같은 내용을 `~/.video-cut/history.jsonl`에 한 줄로 기록한다.

```json
{"video":"BS146","confirmed":"2026-10-03T14:30:11+09:00","raw_sec":1487,"result_sec":1318,
 "cuts_auto":312,"auto_fixes":23,"pd_added":4,"flagged":31,"restored":2,"restored_unflagged":0,
 "user_added_cuts":1,"review_sec":250,"seam_min_score":0.74,"llm_cost_usd_est":1.4,"processing_sec":610}
```

## 7. 계측

`actions.log`(기존)에 다음 이벤트를 추가한다.
- `card_open`, `card_decide` (카드 id, 동작, 키, 소요 시간)
- `reel_start`, `reel_stop` (멈춘 이음새)
- `badge_open` (어느 평가자의 사유를 봤는지)
- `rule_toggle`, `rule_suggest_accept`, `rule_suggest_dismiss`

이 데이터로 느린 카드 유형과 쓰이지 않는 기능을 찾는다 (06 문서).
