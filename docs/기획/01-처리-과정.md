# 01. 처리 과정 — 요청부터 확정까지

"videos/<이름> 컷편집 해줘"라고 요청했을 때 거치는 모든 단계다.
표기: 🆕 새 단계 · ✏️ 기존 단계 변경 · (표시 없음) 기존 그대로

---

## 한눈에 보기

```
[A] 준비        0 요청 접수 → 1 정리 → 2 전사 → 3 음향 분석
[B] 컷 초안     4 화자 블록 → 5 NG(전체→부분 2단계) → 6 추임새 → 8 무음 → 9 초안 조립
[C] 부분 루프   10 이음새마다: 패킷 → 대안 → 관문 → 교차 판정 → 선택 (최대 3회)
[D] 전체 루프   11 PD 평가 + 시청자 평가 + 객관 지표 → 재투입 (최대 2회)
[E] 검토        12 복원 후보 큐 → 알림 → 사용자 검토
[F] 확정        13 변경분 재검증 → FCPXML · preview · 영수증 → 14 학습
```

단계별 캐시 원칙은 유지한다. `edit/`에 산출물이 있으면 그 단계는 건너뛴다. 루프 단계(10, 11)는 입력 파일의 해시를 산출물에 기록해, 앞 단계가 바뀌었을 때만 다시 돈다.

## [A] 준비

### 0. 요청 접수
- `run.py`가 폴더와 원본을 확인한다. 분할 촬영 파일(`01_*.mp4`, `02_*.mp4`)이 있으면 순서대로 이어붙인다 ([`../백로그/R2-시작-마찰-제거.md`](../백로그/R2-시작-마찰-제거.md)).
- `edit/`의 캐시 상태를 확인하고 실행할 단계를 정한다.
- 🆕 브라우저를 먼저 열어 단계별 진행 상황을 보여준다 (`/api/status`). 사용자는 기다리지 않는다.

### 1. 정리 → `edit/clean.mp4`
- 타임코드 트랙(tmcd)과 메타데이터를 제거하고 faststart를 적용한다. 스트림 복사라 무손실이다.

### 2. 전사 → `edit/transcript.json`
- ElevenLabs Scribe로 단어 단위 타임스탬프와 화자를 얻는다.

### 3. 음향 분석 → `edit/prosody.json`, 🆕 `edit/audio_map.json`
- 기존: 단어별 F0(피치)와 RMS(에너지). NG 분류의 근거로 쓴다.
- 🆕 **음향 지도**: 영상 전체에 대해 한 번 계산하고 이후 모든 단계가 재사용한다. 로컬 연산이고 API 비용은 0이다.

| 항목 | 방법 | 쓰는 곳 |
|---|---|---|
| RMS 포락선 | 10ms 프레임 | 스냅, 관문, 이음새 점수 |
| 목소리 구간 (VAD) | 에너지 + 스펙트럼 기반. 필요하면 Silero VAD | 비전사 소리 검출(6), 관문(10) |
| 숨소리 구간 | 피치 없음 + 광대역 + 150~500ms + 말소리보다 낮은 레벨 | 무음(8), 관문(10) |
| 룸톤 기준 레벨 | 무성 구간 RMS의 하위 백분위 | 관문 기준선 |
| 단어 경계 보정 후보 | 각 단어 경계 ±80ms 안의 에너지 최저점과 그 근처 영교차점 | 스냅(9, 10) |

## [B] 컷 초안 — "잘라도 되는 건 전부 자른다"

이 구간의 모든 단계는 결과를 `route`(`CUT` / `KEEP`)와 `flag`(`restore` 복원 후보 / `delete` 삭제 후보 / 없음)로 낸다. 적용 전에 L1 사용자 규칙을 먼저 확인한다 (04 문서).

### 4. 화자 블록 ✏️ → `edit/speaker_blocks.json`
- 대화 형태(짧은 줄이 화자 사이를 오감, 전환 밀도 ≥ 0.4)로 카메라 밖 대화 블록을 찾는다. 줄마다 역할(지시/재시도/최종/내용)을 붙인다. 모델은 Sonnet 5이고 few-shot을 쓴다.
- ✏️ "최종"과 "내용" 줄만 남기고 나머지는 `CUT`으로 둔다. 역할 판정의 신뢰도가 0.75 미만인 줄은 `CUT` + `restore`로 둔다.
- NG보다 먼저 실행한다 (5단계 Stage 1이 이미 잡힌 블록을 건너뛰기 위해).

### 5. NG 탐지 → 분류 → 라우팅 ✏️ → `edit/ng.json`
**2026-09-30 하향식 재설계** (결정-이력.md 09-30 "하향식 재설계" 참고 — 기존 45초 창 기반 국소 탐지가
같은 문단 안에서 문장을 2~4번 고쳐 말하는 재시작 사슬조차 후보로 못 만드는 문제를 실측으로 확인해
방향을 뒤집었다): 국소 창을 넓히는 대신, 사람 편집자처럼 **전체를 먼저 보고 좁혀온다**.

1. **Stage 1 "전체를 넓게"** (`detect_regions.py`) — 원본 대본을 800단어 청크(150단어 겹침)로 나눠
   Opus 5.5가 각 청크를 체계적으로 훑으며 재시작·카메라 밖 대화·필러 몰림 등 의심 구간을 **대략적인
   범위**로만 표시한다. 정확한 경계는 정하지 않는다. 단어 절단·3단어 내 중복 같은 결정론적 신호는
   LLM 호출 없이 별도로(공짜로) 먼저 잡아 표시해 준다.
2. **Stage 2 "부분을 좁게"** (`classify_region.py`) — Stage 1이 표시한 구간마다 앞뒤 문맥(단어 id
   포함)을 확대해서 보여주고, 정확한 단어 경계와 case(A~F)를 이 단계에서 처음 확정한다. 먼 재진술이면
   참고용으로 그 다른 쪽 텍스트도 같이 보여준다. Sonnet 5가 기본, B 케이스나 신뢰도 0.80 미만은
   Opus 5.5로 올린다. few-shot을 쓴다 (04 문서). 발음 실수 탐지(ASR 저신뢰도 클러스터)는 별도
   채널로 유지되며 같은 방식으로 판정된다.
3. **라우팅** (`route_candidates.py`, 기준값은 06 문서의 캘리브레이션으로 확정)

| 분류 결과 | route | flag |
|---|---|---|
| CUT, 신뢰도 ≥ 0.75 | `CUT` | — |
| CUT, 신뢰도 < 0.75 | `CUT` | `restore` |
| 5초 넘는 구간 | `CUT` | `restore` |
| B, 같은 정보인지 불확실 | `CUT` | `restore` |
| KEEP, 신뢰도 ≥ 0.55 (C 강조 반복, D 재진술·나열 등) | `KEEP` | — |
| KEEP, 신뢰도 < 0.55 | `CUT` | `restore` |
| REVIEW, OTHER | `CUT` | `restore` |
| **Stage 1의 전체 맥락 스캔이 찾은 구간(모든 case)** | `CUT` | **신뢰도와 무관하게 항상 `restore`** |

C와 D 케이스는 신뢰도가 높을 때만 살린다. 정상 발화라서 지울 근거 자체가 없기 때문이다. 마지막 줄은
2026-09-30 BS167 실측 반례로 추가됐다 — Stage 1이 찾은 구간은 "구간의 존재 자체"부터 LLM 자신의
추론이라, 국소 힌트나 발음 실수 탐지처럼 독립적인 기계적 신호로 사전 검증되지 않았다. 신뢰도만으로는
안 걸러지는 오판(같은 사람이 만들고 같은 계열 모델이 확인하는 judge≠maker 위반)이 실제로 flag 없이
잘리는 사고를 냈다 - 그래서 이 경로만은 신뢰도와 무관하게 항상 flag한다.

### 6. 추임새 ✏️ → `edit/ng.json`에 병합
- **단독 추임새** (`detect_filler_candidates.py`, "음/어/아" + ASR이 문장부호로 떼어 놓은 경우):
  항상 `CUT` + `restore`로 보낸다. L1의 말버릇 목록에 있는 단어는 `KEEP`으로 둔다. 어휘 확장("그니까",
  "이제" 등)은 L2 통계를 보고 사용자 승인으로 한다.
- (전사 안 된 소리 VAD 탐지는 아직 미착수 - 미결 사항 참고)

### 8. 무음 리듬 ✏️ → `edit/pauses.json`
- 쉼 문맥 분류(Haiku 4.5)와 문맥별 목표 길이는 기존 그대로다 ([`../현재-설계/무음-리듬.md`](../현재-설계/무음-리듬.md)).
- ✏️ **숨소리 인식**: 쉼 안에 숨소리가 있으면 통째로 지우거나 통째로 남긴다. 기본은 통째로 지우고 목표 길이만큼만 남긴다. L1에서 사용자가 숨소리 유지를 골랐으면 남긴다.
- ✏️ **경계**: 남길 구간을 쉼 한가운데가 아니라 에너지가 가장 낮은 위치에 둔다. 목표 길이는 L1 값이 있으면 그 값을 쓴다.

### 9. 🆕 초안 조립 → `edit/draft_cuts.json`
- 4~8단계의 모든 `CUT`을 하나의 목록으로 합치고, 겹치거나 붙은 컷을 병합한다.
- 모든 컷 경계를 음향 지도의 보정 후보로 1차 스냅한다. 기존 15ms 안쪽 여유(`build_edl.py`)는 없앤다.
- 컷마다 다음을 기록한다.

```json
{
  "cut_id": 12,
  "kind": "ng",                 // ng | block | filler | noise | context | pause
  "raw_start": 312.418, "raw_end": 314.902,
  "word_range": [1041, 1049],
  "route": "CUT", "flag": "restore",
  "flag_reasons": ["신뢰도 0.71 < 0.75"],
  "evidence": "B: 같은 정보 반복, 뒤 시도가 더 명확",
  "confidence": 0.71,
  "made_by": "claude-sonnet-5",
  "sources": ["ng[17]"]
}
```

- 컷 사이에 남는 접점마다 이음새를 만든다. 이음새가 [C] 단계의 단위다.

## [C] 부분 루프 — 이음새마다 매끄럽게 → `edit/seams.json`

상세 설계는 [02-품질-루프.md](02-품질-루프.md).

**대상**: 쉼 트림이 아닌 모든 이음새, 그리고 1차 음향 점수가 기준 미만인 쉼 트림 이음새. BS145 기준 40~60개로 예상한다.

| 단계 | 내용 | 비용 |
|---|---|---|
| 10-1 패킷 | 앞 문맥, 잘린 부분, 뒤 문맥, 결과 문장, 음향 수치, 컷 근거를 묶는다 | 로컬 |
| 10-2 대안 | 원안, 스냅, 앞·뒤 한 단어 확장, 잔여 조각 흡수, 앞·뒤 한 단어 축소, 취소 | 로컬 |
| 10-3 관문 | 음절 절단, 잔여음(재전사 대조), 숨소리 처리. 하나라도 걸리면 그 대안은 탈락 | 로컬 + Scribe |
| 10-4 교차 판정 | 컷을 만든 모델과 다른 모델이 문법 연결, 중복 잔존, 지시어 끊김, 정보 손실을 판정 | LLM (20~30개씩 묶음) |
| 10-5 선택 | 관문을 통과하고 연결 조건을 만족하는 대안 중 **가장 많이 지우는 것** | 로컬 |
| 10-6 반복 | 바뀐 이음새와 그 양옆만 다시 검사. 최대 3회, 바뀐 게 없으면 종료 | — |

- 정보 손실은 탈락 사유가 아니다. 해당되면 `flag: restore`로 표시하고 사유를 남긴다.
- 삭제하는 대안이 전부 관문에서 탈락하면 원래 발화를 살리고 `KEEP` + `flag: delete`(삭제 후보)로 올린다.

## [D] 전체 루프 — 영상 전체를 두 관점에서 → `edit/global_review.json`

상세 설계는 [02-품질-루프.md](02-품질-루프.md)와 [03-두-관점-평가.md](03-두-관점-평가.md).

| 단계 | 내용 | 모델 |
|---|---|---|
| 11-1 결과물 표현 | 결과 전사 + 쉼 길이 표시 + 이음새 음향 이상을 "들리는 느낌"으로 번역한 표시 | 로컬 |
| 11-2 PD 평가 | 원본, 잘린 부분, 근거, 편집 규칙, L1 규칙을 보고 덜 지운 곳·과다 삭제·아웃테이크 후보를 찾음 | Opus 5.5 |
| 11-3 시청자 평가 | **결과물만** 보고 어색한 점프, 리듬, 반복감, 지루한 구간을 찾음 | Fable 5.1 |
| 11-4 객관 지표 | 말 속도, 쉼 분포(사람 편집본 대비), 이음새 점수 최저값과 하위 10% | 로컬 |
| 11-5 결합 | 두 평가를 결합 규칙에 따라 처리 (03 문서) | 로컬 |
| 11-6 재투입 | 추가 컷과 지적된 이음새만 [C]로 되돌림. **정확히 1회**(2026-09-30 단순화 - 여러 라운드를 세션에 걸쳐 반복하면 ng.json에 판단이 누적돼 검증이 오염되는 문제를 겪음, 06 문서 6.1절) | — |

- PD가 찾은 "덜 지운 곳"은 추가 컷으로 자동 적용한다 (방침 1).
- 시청자가 찾은 "지루한 구간"은 자동으로 자르지 않고 **제안 카드**로만 올린다. NG나 무음 정리가 아니라 내용 편집이기 때문이다 (07 문서 미결 사항).

## [E] 검토

상세 설계는 [05-검토-화면.md](05-검토-화면.md).

### 12-1. 복원 후보 큐 → `edit/restore_queue.json`
- 정렬 순서
  1. 두 관점 모두 지적
  2. 정보 손실 의심
  3. 판정이 엇갈림
  4. L2에서 사용자가 자주 복원한 유형
  5. 신뢰도 낮은 자동 삭제
  6. 삭제 후보
  7. 제안 카드 (지루한 구간 등)
- 한 번도 복원된 적 없는 유형의 flag 항목은 "빠른 확인" 층으로 내린다.
- 카드마다 선택지별 이음새 오디오를 미리 렌더링해 둔다.

### 12-2. 알림
- macOS 알림을 보낸다. 예: "BS146 준비됨 · 복원 후보 8건 · 예상 4분"
- 예상 시간은 L2의 카드 유형별 평균 결정 시간으로 계산한다.

### 12-3. 사용자 검토
- 카드를 따라가며 복원 여부를 정한다. 이음새 자동 재생, 번호 키 선택지, 이음새 릴을 쓴다.
- 결정마다 L3(`decisions.json`)와 L2(`cases.jsonl`)에 기록한다.

## [F] 확정과 학습

### 13. 확정
1. 🆕 **변경분 재검증**: 사용자가 복원하거나 조정한 이음새에만 10-3 관문을 다시 돌린다. 스냅, 유성음, 숨소리만 보고 재전사와 LLM은 쓰지 않아 몇 초면 끝난다. 관문에 걸리면 자동 스냅을 한 번 시도하고, 그래도 걸리면 확정 전에 알린다.
2. 미검토 flag 항목이 남아 있으면 그 수를 알린다 (SKILL.md 규칙).
3. EDL → FCPXML → preview.mp4
4. 🆕 영수증을 보여주고 `~/.video-cut/history.jsonl`에 한 줄 기록한다 (05 문서).

### 14. 학습
상세 설계는 [04-지식-층과-학습.md](04-지식-층과-학습.md).
- L1 통계(단계별·케이스별 복원율)를 갱신한다.
- 이번 세션에서 수락한 패턴 규칙에 대해 "앞으로도 적용할까요?"를 묻고, 예를 누르면 L1 규칙으로 저장한다.
