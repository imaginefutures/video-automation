# 자동 컷편집 품질 루프 기획 — 개요

작성: 2026-09-29
문서 지도: [`../README.md`](../README.md) · 서비스 철학: [`../서비스-개요와-철학.md`](../서비스-개요와-철학.md). 이 폴더는 [`../현재-설계/NG-판별.md`](../현재-설계/NG-판별.md)(자기검증 포함), [`../현재-설계/시스템-개요.md`](../현재-설계/시스템-개요.md)(모델 배정), [`../현재-설계/검토-화면.md`](../현재-설계/검토-화면.md)(개인화·패턴 제안)를 대체·확장하는 상세 기획이다.

## 1. 왜 하는가

사용자의 가장 큰 요구는 **시간 단축**이다. 시간을 줄이는 길은 두 가지뿐이다.

1. 초기 자동 컷편집이 정확해서 고칠 게 적다
2. 고칠 게 있어도 쉽고 빠르게 검토·결정할 수 있다

이 기획은 두 가지를 한 구조로 푼다. 자동 컷을 만든 뒤 **잘린 결과가 자연스러운지 스스로 검증하고 고치는 루프**를 돌리고, 그 과정에서 나온 근거를 그대로 검토 화면의 카드로 넘긴다. 처리 시간이 몇 분 늘어나는 것은 감수한다.

## 2. 핵심 방침

| # | 방침 | 비고 |
|---|---|---|
| 1 | **자동 수정은 최대한 지우는 방향이다.** 근거가 있으면 전부 잘라 두고, 애매한 것도 잘라 둔 채 "복원 후보"로 표시한다 | 사용자 결정 (09-29). 사용자는 무엇을 **살릴지**만 결정한다 |
| 2 | **안전장치는 삭제량이 아니라 들리는 손상을 막는다.** 음절 절단, 잔여음, 숨소리 반토막은 어떤 경우에도 허용하지 않는다 | 관문 (02 문서) |
| 3 | **만드는 모델과 평가하는 모델을 다르게 한다** | 같은 모델은 자기 결과를 잘했다고 한다 |
| 4 | **LLM 판정만으로 통과시키지 않는다.** 파형 수치와 재전사 대조를 반드시 함께 쓴다 | |
| 5 | **부분(이음새)과 전체(영상)를 모두 검토한다.** 전체는 편집자(PD)와 시청자 두 관점으로 따로 본다 | 02, 03 문서 |
| 6 | **영상 점수는 평균이 아니라 가장 나쁜 이음새로 판정한다** | 오삭제 하나가 신뢰를 무너뜨린다 |
| 7 | **반복에는 상한이 있다.** 개선이 없으면 즉시 멈춘다 | 부분 최대 3회, 전체 정확히 1회 (09-30 단순화 — 6장 결정 이력 참고) |
| 8 | **사용자 피드백은 개인 취향이 아니라 보편적 버그를 찾는 신호로만 쓴다.** 자동 라우팅을 사용자별로 바꾸는 개인화는 하지 않는다 — 바뀌는 건 개발자가 회귀 게이트를 거쳐 고친 L0 기본값뿐이다 | 04 문서 (2026-10-01 개인화 폐기, 구조적 버그 탐지로 대체) |
| 9 | **채택 기준은 점수가 아니라 검토 건수·시간 감소다** | [`../서비스-개요와-철학.md`](../서비스-개요와-철학.md) 원칙 3 유지 |
| 10 | **오디오를 직접 듣는 모델은 쓰지 않는다** | 사용자 결정 (09-29). 텍스트 + 파형 수치 + 재전사로 한다 |

### 기존 원칙과 달라지는 점

[`../서비스-개요와-철학.md`](../서비스-개요와-철학.md) 원칙 2의 "애매하면 덜 지운다"는 방침 1로 바뀐다. "정상 발화 보호"는 **자동 판단**이 아니라 **복원 후보 표시와 쉬운 복원**으로 보장한다. 신뢰 지표도 "오삭제 0"에서 **"경고 없는 복원 0"**(표시하지 않은 자동 삭제를 사용자가 복원한 건수)으로 바뀐다 (06 문서).

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 컷 | 결과물에서 빠지는 원본 구간 하나 |
| 이음새 | 컷 때문에 새로 맞붙는 두 유지 구간의 접점. 품질 루프의 기본 단위 |
| 이음새 패킷 | 이음새 하나를 판정하기 위한 묶음: 앞 문맥, 잘린 부분, 뒤 문맥, 결과 문장, 음향 수치, 컷 근거 |
| 대안 | 한 이음새에 대해 경계를 달리한 후보안 (원안, 스냅, 확장, 축소, 취소) |
| 관문 | 통과/탈락만 있는 검사. 점수와 무관하게 하나라도 걸리면 그 대안은 버린다 |
| 복원 후보 | 자동으로 잘랐지만 사용자가 살릴 가능성이 있어 검토 큐에 올린 컷 |
| 삭제 후보 | 지워야 할 근거가 있지만 어떻게 잘라도 관문을 못 넘어 살려 둔 구간. 복원 후보의 반대 방향 |
| 부분 루프 | 이음새 단위로 대안을 만들고 골라 다시 검사하는 반복 |
| 전체 루프 | 결과 영상 전체를 PD·시청자 관점으로 평가하고 지적된 곳을 부분 루프로 되돌리는 반복 |
| L0 | 스킬 기본값(관문·임계값·few-shot) — 개발자가 회귀 게이트를 거쳐 바꾸는 유일한 층. 2026-10-01 이전엔 L1(사용자 규칙)~L3(영상 결정)까지 있었으나 개인화 폐기로 L0만 남음 (04 문서) |
| 구조적 의심 | 사용자 결정이 같은 구조적 태그에서 한쪽으로만 쏠려, 개인 취향이 아니라 보편적 버그로 보이는 패턴. 자동 라우팅은 안 바꾸고 개발자 검토로만 보냄 (04 문서) |

## 5. 현재 대비 무엇이 바뀌나

| 영역 | 현재 | 이 기획 |
|---|---|---|
| 라우팅 | AUTO_SAFE / REVIEW / KEEP. 애매하면 REVIEW | `CUT` / `KEEP` + `flag`(복원 후보·삭제 후보). 애매하면 `CUT` + 복원 후보 |
| 경계 | Scribe 타임스탬프에서 안쪽 15ms | 음향 지도 기반 스냅 (에너지 최저점, 영교차점, 숨소리 인식) |
| 자기검증 | NG 자동 삭제만, 남은 텍스트만 보고, 강등만 | 모든 컷의 이음새 패킷을 교차 모델이 판정하고 대안을 골라 고침 |
| 전체 검토 | 전체 맥락 검토 1회 (먼 재진술 찾기) | 위에 더해 결과물 전체를 PD·시청자가 평가하는 루프 |
| 무음 | 쉼의 한가운데를 자름 | 숨소리를 통째로 처리, 에너지 최저점에 경계 |
| few-shot | NG 분류에 고정 예시 6개 | L0 고정 예시만(사용자별 동적 검색 없음) — 구조적 의심에서 승격된 예시가 늘어남 |
| 사용자 결정 | 검토 화면 기본값에만 반영 | 구조적 의심 탐지로 개발자에게 전달. **자동 라우팅은 안 바뀜** (2026-10-01 개인화 폐기 — 04 문서) |
| 검토 카드 | 판정 근거 한 줄 | 이음새 패킷 + PD·시청자 판정 배지 + 번호 키 선택지 |

※ 이 표의 라우팅/경계/자기검증/전체검토/few-shot 행은 09-29 당일 중 이미 구현 완료됨 — "현재"가 아니라 이력으로 읽을 것. "이 기획" 칸이 실제 현재 동작이다.

## 6. 결정 이력

| 날짜 | 결정 |
|---|---|
| 09-29 | 자동 수정은 최대 삭제 방향, 사용자는 복원을 결정 |
| 09-29 | 부분 루프와 전체 루프를 모두 둔다 |
| 09-29 | 모델을 섞어 쓴다 (만드는 모델 ≠ 평가하는 모델) |
| 09-29 | 전체 평가는 PD 관점과 시청자 관점으로 분리 |
| 09-29 | 오디오 입력 모델은 추가하지 않는다 |
| 09-30 | NG 탐지를 상향식(국소탐지→분류→사후전체검토)에서 하향식(Stage1 전체를 넓게→Stage2 부분을 좁게) 2단 구조로 재설계. 전체 루프 재투입은 최대 2회에서 정확히 1회로 단순화 |
| 10-01 | 사용자별 개인화 학습(L1 사용자 규칙, L2 few-shot) 전면 폐기 — 보편적 버그가 개인 취향으로 흡수돼 묻히는 결함 때문. "구조적 의심 탐지"(피드백에서 버그 패턴만 추려 개발자에게 알리고 자동 라우팅은 안 바꿈)로 대체 (04 문서, `../결정-이력.md`) |
