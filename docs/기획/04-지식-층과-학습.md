# 04. 지식 층과 학습 — 기본 규칙, 사용자 규칙, 사용자 결정

스킬이 제공하는 기본 알고리즘·규칙과 사용자가 쓰면서 내린 결정이 어디에 저장되고, 어떻게 합쳐지고, 어디에 쓰이는지 정한다.

---

## 1. 현재 상태와 문제

| 자산 | 지금 쓰이는 곳 | 문제 |
|---|---|---|
| few-shot | NG 분류(`classify_region.py`)의 고정 예시 6개 + L2 사용자 사례(`fewshot.retrieve`) | 정적 예시는 안 바뀜. L2는 2026-09-30부터 `server.py`의 `confirm()`이 `learn_from_session.py`를 fire-and-forget으로 호출해 자동으로 쌓임(전엔 사람이 수동 실행해야만 늘었음) |
| 개인 선호 `~/.video-cut/prefs/<사용자>.json` | 검토 화면을 열 때 REVIEW 항목의 기본값(`server.py`) | NG 케이스별 cut/keep 횟수뿐. 파이프라인과 LLM은 보지 못함 |
| 패턴 제안 (`pattern_suggest.py`) | 세션 안에서만 | 다음 영상으로 넘어가지 않음 |
| `decisions.json` | 그 영상의 재현용 + `learn_from_session.py`가 확정 시 읽어 L2로 요약 | 파이프라인의 라우팅 임계값 자체는 여전히 안 바뀜 |
| 알고리즘 상수 (임계값, 목표치) | 각 스크립트에 하드코딩 | 어떤 게 안전 관문이고 어떤 게 바꿔도 되는 기본값인지 구분 없음 |

사용자가 내린 결정의 대부분이 검토 화면 안에서 끝나고, 다음 영상의 자동 컷에는 거의 반영되지 않는다.

---

## 2. 네 개의 층

| 층 | 내용 | 위치 | 누가 바꾸나 |
|---|---|---|---|
| **L0 스킬 기본** | 알고리즘, 편집 원칙, 케이스 정의 A~F, 임계값, 쉼 목표 기본값, 기본 few-shot | 저장소 `rules/` | 개발자만. 회귀 게이트 통과 필수 |
| **L1 사용자 규칙** | 사람이 승인한 명시적 규칙 | `~/.video-cut/prefs/<사용자>.json` | 사용자 승인으로만 |
| **L2 사용자 사례** | 모든 결정을 문맥과 함께 누적한 기록. 규칙이 아니라 근거 자료 | `~/.video-cut/cases/<사용자>.jsonl` | 자동 누적 |
| **L3 영상 결정** | 이 영상의 최종 상태 | `videos/<이름>/edit/decisions.json` | 사용자 (이 영상 한정) |

### 2.1 우선순위

```
L3 영상 결정  >  L1 사용자 규칙  >  L0 기본값
                                    L0 관문은 무엇으로도 못 바꿈
L2는 규칙이 아니다 → few-shot, 통계, 큐 정렬의 재료로만 쓴다
```

### 2.2 L0의 두 종류

`rules/` 안에서 파일로 분리한다.

| 파일 | 내용 | 사용자가 덮어쓸 수 있나 |
|---|---|---|
| `rules/gates.yaml` | 관문 G1~G4의 기준 (음절 절단, 잔여음, 숨소리, 말소리 보존), 경계 보호 거리 | ❌ 불가 |
| `rules/defaults.yaml` | 라우팅 임계값, 쉼 목표치, 추임새 어휘, 루프 반복 상한, 이음새 점수 가중치와 기준 | ✅ L1로 덮어씀 |
| `rules/fewshot_base.jsonl` | 단계별 기본 few-shot (현재 6개를 옮기고 단계별로 확장) | ➖ 덮어쓰지 않고 L2와 함께 씀 |
| `rules/editorial.md` | 채널 편집 원칙 문장 (PD 평가와 NG 분류 프롬프트에 들어감) | ➖ L1 규칙이 뒤에 덧붙음 |

지금 스크립트에 흩어진 상수(예: `route_candidates.py`의 0.75, `plan_pauses.py`의 목표치, `build_edl.py`의 15ms)를 이 파일들로 옮긴다.

## 3. 저장 형식

### 3.1 L1 `~/.video-cut/prefs/<사용자>.json` (현재 형식을 확장)

```json
{
  "version": 2,
  "overrides": {                       // rules/defaults.yaml 덮어쓰기
    "pause.targets.NORMAL": 0.22,
    "pause.keep_breath": false
  },
  "rules": [                           // 승인된 규칙
    {
      "id": "r3",
      "text": "조사만 바뀐 형태론적 수정(E)은 복원 후보로 올리지 말고 그냥 삭제",
      "applies_to": { "stage": "ng", "case": "E" },
      "effect": { "flag": null },
      "origin": { "from": "pattern_suggest", "video": "BS146", "decisions": 5 },
      "created": "2026-10-03",
      "enabled": true,
      "hits": 12                       // 이후 영상에서 적용된 횟수
    }
  ],
  "keep_words": ["그니까"],            // 말버릇 (추임새로 자르지 않음)
  "viewer_persona": "3세 아이를 키우는 부모, 모바일, 1배속",
  "stats": {                           // L2에서 집계한 요약 (확정 시 갱신)
    "ng.B": { "cut": 14, "restore": 3, "flagged_restore": 3, "unflagged_restore": 0 },
    "filler": { "cut": 40, "restore": 6 }
  }
}
```

`rules[].effect`로 할 수 있는 건 정해진 몇 가지뿐이다: route 바꾸기(`CUT`/`KEEP`), flag 붙이기/떼기, 쉼 목표 바꾸기. **관문을 끄는 효과는 없다.**

### 3.2 L2 `~/.video-cut/cases/<사용자>.jsonl` (한 줄에 결정 하나)

```json
{
  "ts": "2026-10-03T14:22:05+09:00",
  "video": "BS146",
  "stage": "ng", "case": "B", "cut_id": 12,
  "packet": { "before": "…", "removed": "…", "after": "…", "result": "…" },
  "auto": { "route": "CUT", "flag": "restore", "confidence": 0.71, "made_by": "claude-sonnet-5",
            "pd": "ok", "viewer": "jump" },
  "user": { "action": "restore", "via": "card_key_3", "boundary_delta_ms": null },
  "signal": "strong",
  "decision_sec": 6.4
}
```

- `packet`이 있어야 few-shot으로 쓸 수 있다. 이음새 패킷을 그대로 저장한다.
- `decision_sec`는 카드가 열린 뒤 결정까지 걸린 시간이다. 예상 검토 시간 계산과 느린 유형 파악에 쓴다.

## 4. 사용자 결정 신호

새 방침에서는 검토 항목이 삭제된 상태로 시작하므로, 신호마다 의미가 다르다.

| 신호 | 강도 | 의미 | 쓰임 |
|---|---|---|---|
| 복원 (자동 삭제 → 살림) | 강 | 과다 삭제 | 정밀도 개선. flag 없는 컷이었다면 **경고 없는 복원** (최우선 신호) |
| 직접 추가 삭제 | 강 | **자동이 놓친 컷.** 재현율을 개선할 유일한 재료 | 탐지 규칙과 PD 평가 개선 |
| 삭제 유지 확정 (`⇧Enter`) | 강 | 자동 판단이 맞음 | few-shot 긍정 예시 |
| 경계 조정 (파형, 단어 확장/축소) | 중 | 판단은 맞고 경계가 틀림 | 스냅 알고리즘 개선, `boundary_delta_ms` 통계 |
| 쉼 게이지 조정 | 중 | 리듬 취향 | 쉼 목표치 제안 |
| 미검토 통과 | 약 | 약한 동의 | 통계에만. few-shot에는 쓰지 않음 |

## 5. few-shot을 쓰는 곳

**원칙**: 사람의 판단을 흉내 내야 하는 LLM 단계에는 쓰고, 편향 없이 봐야 하는 단계에는 쓰지 않는다.

| 단계 | few-shot | 구성 |
|---|---|---|
| 4 화자 블록 줄 역할 | ✅ | L0 예시 + L2에서 사용자가 복원한 줄 |
| 5 NG 분류 | ✅ **핵심** | L0 3개 + L2 검색 3개 |
| 6 추임새 (LLM을 쓰게 될 경우) | ✅ | L2에서 이 사용자가 살린 말버릇 사례 |
| 7 전체 맥락 검토 | ✅ 소량 | L0 예시("큐", "컷!") + L2에서 복원한 맥락 컷 2개 |
| 8 쉼 분류 (Haiku) | ❌ | 담화 표지로 충분. 취향은 L1 목표치로 반영 |
| 10 이음새 교차 판정 | ✅ | L0 좋은/나쁜 이음새 예시 + L2에서 "어색해서 복원한" 이음새 |
| 11 PD 평가 | ✅ 규칙 위주 | L1 규칙을 문장으로 + L2 복원 사례 요약 최대 10개 |
| 11 시청자 평가 | ❌ **의도적으로 제외** | 페르소나만 |
| 패턴 제안 | ✅ | 이번 세션의 연속 결정 |

### 5.1 L2에서 사례를 고르는 규칙

1. **후보 범위**: 같은 단계, 같은 케이스 (NG면 A~F)
2. **유사도**: 잘린 부분과 앞뒤 문맥의 문자 n-gram 유사도. 임베딩 의존성은 두지 않고, 사례가 수백 건을 넘으면 다시 검토한다.
3. **반대 방향 최소 하나**: 삭제 사례만 넣으면 모델이 한쪽으로 쏠린다. 복원 사례와 삭제 유지 사례를 반드시 섞는다.
4. **뒤집힌 사례 우선**: 사용자가 자동 판단을 뒤집은 사례(복원, 추가 삭제)가 그대로 둔 사례보다 정보량이 많다.
5. **최근 가중치**: 최근 사례일수록 가중치를 준다. 취향은 변한다.
6. **중복 제거**: 같은 문구의 사례는 하나만.
7. **평가 누수 방지**: 검증(06 문서)할 때는 평가 대상 영상의 사례를 검색에서 뺀다.

L2 사례가 부족하면(해당 케이스 3건 미만) L0 기본 예시로 채운다.

### 5.2 few-shot의 형식

사례를 프롬프트에 넣을 때 **사용자 결정임을 명시**한다.

```
[이 채널 운영자의 실제 결정 — B 케이스]
잘린 부분: "이게 중요한 이유는요"
뒤 문맥: "이게 왜 중요하냐면요, 아이가…"
자동 판단: CUT (0.78)  →  운영자 결정: 삭제 유지
```

## 6. 결정의 수명 주기

```
[검토 중] 결정 발생
   ├─▶ L3 decisions.json 즉시 기록
   ├─▶ L2 cases.jsonl에 패킷 + 자동 판단 + 결정 + 소요 시간 기록
   └─▶ 같은 방향 연속 3회 → 패턴 제안 배너 → 수락하면 이 영상의 남은 항목에 적용

[확정 시]
   ├─▶ L1 stats 갱신 (단계별·케이스별 복원율, 경고 없는 복원 수)
   ├─▶ 세션에서 수락한 패턴 → "앞으로도 적용할까요?" → 예를 누르면 L1 rules에 저장
   ├─▶ 조건을 만족한 통계 → 규칙 제안 생성 (6.2) → 다음 세션 시작 배너로
   └─▶ 영수증에 "이번에 배운 것" 표시

[다음 영상 처리 시]
   ├─▶ L1 overrides/rules/keep_words → 4~9단계 라우팅에서 결정론적으로 적용
   ├─▶ L2 사례 → 각 LLM 단계의 few-shot (5장)
   └─▶ L2 통계 → 복원 후보 큐 정렬, "빠른 확인" 층 분리, 예상 검토 시간

[개발자 경로: L2 → L0 승격]
   경고 없는 복원 = 자동이 자신 있게 틀린 것
   → gold 반례 fixture 후보 → 개발자 검토 → 회귀 게이트 → L0 수정
```

### 6.1 자동으로 바뀌는 것과 승인이 필요한 것

| 변화 | 방식 |
|---|---|
| few-shot 예시 교체 | 자동 (매 영상 L2에서 새로 고름) |
| 복원 후보 큐 정렬, 빠른 확인 층 분리 | 자동 |
| 예상 검토 시간 | 자동 |
| 케이스 기본 행동 변경 | 제안 → 사용자 승인 |
| flag 기준값 조정 | 제안 → 사용자 승인 |
| 쉼 목표치 조정 | 제안 → 사용자 승인 |
| 말버릇 목록 추가 | 제안 → 사용자 승인 |
| L0 알고리즘·관문·기본값 | 개발자 + 회귀 게이트 |

### 6.2 규칙 제안이 생기는 조건 (초기값)

| 제안 | 조건 |
|---|---|
| "이 유형은 복원 후보에서 빼고 그냥 삭제" | 해당 유형 flag 항목 10건 이상, 복원율 5% 미만 |
| "이 유형은 기본 유지" | 해당 유형 10건 이상, 복원율 80% 이상 |
| "이 단어는 말버릇이라 유지" | 같은 추임새 5건 이상, 복원율 70% 이상 |
| "일반 쉼 목표를 0.25 → 0.22초로" | 해당 문맥 쉼을 사용자가 조정한 건 20건 이상, 조정 방향이 80% 이상 한쪽, 중앙값 차이 0.02초 이상 |

제안은 한 세션에 최대 2개만 보여준다. 근거가 된 사례를 눌러 볼 수 있어야 한다.

### 6.3 규칙이 틀렸을 때

- 사용자가 L1 규칙이 적용된 항목을 되돌리면 그 규칙의 `hits` 옆에 `reverts`를 센다.
- `reverts / hits`가 20%를 넘으면 규칙을 끄자고 제안한다.
- 검토 화면 "내 규칙"(05 문서)에서 언제든 끄고 켤 수 있다.

---

## 7. 여러 사용자

- 사용자 구분은 기존과 같다 (`VIDEO_CUT_USER` 또는 OS 계정).
- L1과 L2는 사용자별이다. 편집자가 여럿이면 각자의 취향이 따로 쌓인다.
- L0는 공유한다. 한 사용자의 경고 없는 복원이 L0에 반영되면 모든 사용자에게 적용되므로, 승격은 반드시 개발자 검토를 거친다.
