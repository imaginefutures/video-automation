# 03. 두 관점 평가 — PD와 시청자

전체 루프(02 문서 3장)의 두 평가자 설계다. 두 평가자는 **보는 정보부터 다르다.** 이 차이가 설계의 핵심이다.

---

## 1. 왜 두 관점인가

| | PD(편집자) | 시청자 |
|---|---|---|
| 질문 | 잘라야 할 걸 제대로 잘랐나? | 이 영상이 자연스럽게 들리나? |
| 아는 것 | 원본, 잘린 부분, 컷 근거, 편집 규칙, 이 사용자의 취향 | 결과물뿐 |
| 강점 | 덜 지운 곳, 과다 삭제, 규칙 위반 | 흐름 단절, 리듬, 반복감, 지루함 |
| 약점 | 잘린 내용을 알아서 결과물의 어색함을 "이해해 줌" | 무엇이 잘렸는지 몰라 정보 손실은 못 봄 |

한 평가자로 둘을 다 하게 하면 PD의 지식이 시청자의 감각을 오염시킨다. 잘린 부분을 본 모델은 "여기는 잘려서 이렇게 된 거구나" 하고 넘어가지만, 실제 시청자는 그걸 모른다. 그래서 **시청자 평가자에게는 잘린 내용, 컷 근거, 사용자 사례를 절대 주지 않는다.**

---

## 2. PD 평가

### 2.1 설정
- 모델: Opus 5.5 (`claude-opus-5-5`)
- 입력: PD용 결과물 표현(02 문서 3.1), 채널 편집 규칙(L0), 이 사용자의 규칙(L1)을 문장으로, 사용자 복원 사례 요약(L2, 최대 10개)

### 2.2 페르소나

> 너는 과학·논문 근거 기반 육아 강의 채널의 전담 편집자다. 이 채널의 원칙: 재촬영은 마지막 시도만 남긴다. 강조 반복과 교육적 재진술은 살린다. 카메라 밖 대화는 모두 지운다. 아래는 이 채널의 편집 원칙이다: {`rules/editorial.md`}

(2026-10-01: 개인화 폐기로 "운영자 취향"(L1 규칙·L2 요약) 주입은 뺐다. 채널 편집 원칙은 전부 사용자별이 아니라 L0 — 개발자가 승인한 고정 문구만 쓴다. [`04-지식-층과-학습.md`](04-지식-층과-학습.md))

### 2.3 찾는 것

| 유형 | 정의 | 예 |
|---|---|---|
| `missed_cut` | 지워야 하는데 남은 것: NG, 말더듬, 먼 재진술, 카메라 밖 발화, 촬영 신호 | "큐" 다음에 남은 "네 시작할게요" |
| `over_cut` | 지웠는데 잘린 부분에만 있는 정보가 있거나, 규칙상 살려야 하는 것 (C, D 케이스) | 두 번째 시도에 없는 숫자가 첫 시도에 있었음 |
| ~~`rule_conflict`~~ | ~~L1 사용자 규칙과 어긋난 처리~~ | **2026-10-01 폐기** — L1 사용자 규칙 자체가 없어져 개념이 성립 안 함. `global_review.py`의 `PDFinding.type`은 `missed_cut`/`over_cut` 2종뿐 |

### 2.4 출력 형식

```json
{
  "findings": [
    {
      "type": "missed_cut",
      "word_range": [2201, 2206],       // 원본 단어 인덱스
      "cut_id": null,                   // over_cut면 대상 컷 id
      "reason": "촬영 준비 발화. 강의 내용과 무관",
      "confidence": 0.9,
      "severity": "high"                // high | medium | low
    }
  ]
}
```

## 3. 시청자 평가

### 3.1 설정
- 모델: Fable 5.1 (`claude-fable-5-1`). PD와 다른 모델이다.
- 입력: 시청자용 결과물 표현(02 문서 3.1)과 페르소나뿐. **few-shot도 쓰지 않는다.** 사용자 사례를 넣으면 PD의 복사본이 된다.

### 3.2 페르소나

> 너는 3세 아이를 키우는 부모다. 퇴근길 지하철에서 휴대폰으로 이 육아 강의 영상을 1배속으로 보고 있다. 아래는 영상에서 들리는 말을 받아 적은 것이다. `·`은 짧은 쉼, `··`은 중간 쉼, `···`은 긴 쉼이고, `⟨ ⟩`는 들을 때 느껴지는 소리의 변화다. 보다가 "어?" 하고 걸리는 곳, 너무 빨라서 따라가기 힘든 곳, 늘어져서 넘기고 싶은 곳, 같은 말을 또 듣는 느낌이 드는 곳을 솔직하게 짚어라. 문제없으면 없다고 하라.

페르소나는 L1에 채널 시청자 정보(연령대, 주 시청 환경)로 저장해 바꿀 수 있다.

### 3.3 찾는 것

| 유형 | 정의 |
|---|---|
| `jump` | 앞뒤가 안 이어지거나 갑자기 다른 얘기로 넘어가는 느낌 |
| `unclear` | 무슨 말인지 이해가 안 됨 (지시어 대상이 없음, 앞 내용을 모르면 이해 불가) |
| `rushed` | 너무 빽빽해서 숨 쉴 틈이 없음 |
| `dragging` | 늘어짐 (쉼이 길거나 말이 느림) |
| `repetition` | 조금 전에 들은 말을 또 듣는 느낌 |
| `boring` | 내용이 지루해서 넘기고 싶은 구간 |
| `audio_glitch` | ⟨ ⟩ 표시 때문에 거슬리는 곳 (미구현 — 실제 `ViewerFinding.type`은 `jump`/`unclear`/`rushed`/`dragging`/`repetition`/`boring` 6종뿐) |

### 3.4 출력 형식

```json
{
  "findings": [
    {
      "type": "jump",
      "result_time": [198.2, 203.5],    // 결과물 기준 초
      "quote": "필요해요. 연구에 따르면",
      "reason": "믿음이 어디서 오는지 묻고 바로 연구로 넘어가 연결이 끊긴 느낌",
      "severity": "medium"
    }
  ],
  "overall": { "flow": 4, "pace": 3, "comment": "중반부가 조금 빠름" }   // 1~5
}
```

`result_time`은 02 문서 3.1의 매핑으로 이음새 id와 원본 단어 범위로 바꾼다. 매핑되는 이음새가 없으면(예: 원래 말 자체가 어색함) 정보성 지적으로만 기록한다.

## 4. 결합 규칙

※ 아래는 설계 목표다. 실제 구현(`global_review.py`, 2026-09-29/30 결정)은 더 단순하다 —
`missed_cut`만 새 ng 후보(`route: CUT`, 항상 `flag: restore`)로 추가되어 부분 루프(assemble_draft.py
→ seam_refine.py 1회 재실행)로 자동 재투입된다. `over_cut`(PD)와 시청자 `jump`/`unclear`는
부분 루프로 돌아가지 않고 `final_cuts.json`과 `ng.json`에 **flag만 갱신**(역전파)해 검토 화면에 바로
반영한다. 시청자의 `rushed`/`dragging`/`repetition`/`boring`은 `global_review.json`에 지적으로
기록만 되고 자동 처리(쉼 재조정 재검사, PD 재질의, 제안 카드 등)는 없다. `rule_conflict`는
2026-10-01에 개인화(L1 사용자 규칙) 자체를 폐기하면서 개념이 성립하지 않게 됐다 —
[`04-지식-층과-학습.md`](04-지식-층과-학습.md), [`../남은-개발.md`](../남은-개발.md) "폐기됨" 참고.
(`outtake`는 10-01에 기능 자체를 제거했다 — PD가 "웃긴 NG"를 찾아 별표 제안하던 것과 사용자가 직접
켜던 별표 큐 모두.)

같은 위치(같은 이음새 또는 원본 범위가 겹침)에 대한 두 평가를 합친다.

| PD | 시청자 | 처리 | 방향 |
|---|---|---|---|
| `missed_cut` | 없음 | 추가 컷 자동 적용 → 부분 루프 | 더 지움 |
| `missed_cut` | `repetition` / `jump` / `unclear` | 추가 컷 자동 적용 → 부분 루프. 두 관점이 같은 방향 | 더 지움 |
| `over_cut` | 없음 | `flag: restore` (보통 우선순위) | — |
| `over_cut` | `jump` / `unclear` | `flag: restore` **최우선** | — |
| 없음 | `jump` / `unclear` / `audio_glitch` | 이음새 재검사 → 부분 루프 (쉼 늘리기 대안 추가). 해결 안 되면 `flag: restore` | 조정 |
| 없음 | `rushed` | 해당 구간의 쉼 목표를 한 단계 늘린 대안으로 재검사 | 조정 |
| 없음 | `dragging` | 해당 구간의 쉼 목표를 한 단계 줄인 대안으로 재검사 | 더 지움 |
| 없음 | `repetition` | PD에게 해당 구간만 재질의 (missed_cut인가?) → 예면 추가 컷, 아니면 정보성 기록 | — |
| 없음 | `boring` | **제안 카드**만 (자동 삭제 안 함) | — |

**우선순위 원칙**
- 두 관점이 같은 방향이면 자동으로 적용한다.
- 두 관점이 엇갈리면 사용자에게 보여준다. 엇갈린 항목이 사용자가 봐야 할 가장 가치 있는 항목이다.
- 시청자 지적만 있을 때는 삭제 판단을 뒤집지 않고 이음새만 조정한다. 시청자는 무엇이 잘렸는지 모르기 때문이다.

## 5. 두 평가의 결과가 검토 화면에 보이는 방식

카드마다 배지를 단다.

| 배지 | 뜻 |
|---|---|
| `PD ✓` | PD 평가 통과 |
| `PD ⚠ 정보 누락` | over_cut 지적 |
| `시청자 ✓` | 시청자 평가 통과 |
| `시청자 ⚠ 끊김` / `⚠ 급함` / `⚠ 늘어짐` / `⚠ 반복` | 시청자 지적 |
| `두 관점 엇갈림` | 결합 규칙상 사람 판단 필요 |

배지를 누르면 평가자의 `reason`이 그대로 보인다.

---

## 6. 검증 (06 문서와 연결)

- PD 평가: 손상 주입 세트의 `over_cut`·`missed_cut` 유형 검출률을 잰다.
- 시청자 평가: 손상 주입 세트의 `jump`·`rushed` 유형 검출률, 그리고 **사람 편집본에 대한 지적 수가 자동 결과보다 적은지**를 본다.
- 두 평가자가 서로 다른 것을 잡는지 확인한다. 두 평가자의 지적이 90% 이상 겹치면 관점 분리가 작동하지 않는 것이므로 입력과 페르소나를 다시 설계한다.
