# 06. 검증과 측정 — 평가자를 먼저 검증한다

품질 루프의 성패는 점수와 평가자가 실제 품질을 반영하는지에 달려 있다. 평가자가 틀리면 루프는 엉뚱한 방향으로 최적화된다. **이 문서의 P0 검증은 루프 구현 전에 한다.**

---

## 1. 무엇을 검증하나

| 대상 | 질문 |
|---|---|
| 관문 G1~G4 | 들리는 손상을 잡는가, 멀쩡한 이음새를 잘못 탈락시키지 않는가 |
| 이음새 점수 | 사용자가 고친 이음새에 낮은 점수를 주는가 |
| 교차 판정 | 문장 연결 문제와 정보 손실을 잡는가 |
| PD 평가 | 덜 지운 곳과 과다 삭제를 잡는가 |
| 시청자 평가 | 흐름·리듬 문제를 잡는가, PD와 다른 것을 잡는가 |
| 루프 전체 | 검토 건수와 시간이 줄어드는가 |

### 2.2 손상 주입 세트 (🆕 `references/seam_mutations/`)

BS145의 정상 이음새(사람 편집본에서 가져옴)에 일부러 결함을 만든다. 결함마다 정답 라벨이 있으므로 평가자별 검출률을 잴 수 있다.

| 손상 | 만드는 방법 | 잡아야 할 평가자 | 개수 |
|---|---|---|---|
| M1 음절 절단 | 경계를 단어 안쪽으로 30~60ms 이동 | G1, G2 | 20 |
| M2 잔여음 | 지운 단어의 끝 40~80ms를 남김 | G2 | 20 |
| M3 숨소리 반토막 | 숨소리 중간에 경계 | G3 | 10 |
| M4 중복 잔존 | 재시작의 두 시도를 모두 남김 | 교차 판정 C2, PD `missed_cut` | 15 |
| M5 정보 손실 | 새 정보가 있는 문장을 삭제 | 교차 판정 C4, PD `over_cut` | 15 |
| M6 지시어 끊김 | "이게"가 가리키던 문장을 삭제 | 교차 판정 C3, 시청자 `unclear` | 10 |
| M7 리듬 과밀 | 1분 구간의 쉼을 전부 0.05초로 | 시청자 `rushed`, 객관 지표 | 5 |
| M8 카메라 밖 발화 잔존 | 화자 블록의 지시 줄을 남김 | PD `missed_cut` | 5 |
| M0 정상 (대조군) | 손상 없음 | 모두 "문제없음"이어야 함 | 40 |

## 3. 검증 항목과 통과 기준 (초기 목표)

| # | 검증 | 방법 | 통과 기준 |
|---|---|---|---|
| V1 | 관문 검출률 | M1~M3에 G1~G3 실행 | 각 95% 이상 |
| V2 | 관문 오탐 | M0에 G1~G4 실행 | 탈락 5% 이하 |
| V3 | 교차 판정 검출률 | M4~M6 | 각 80% 이상 |
| V4 | 교차 판정 오탐 | M0 | 문제 지적 10% 이하 |
| V5 | PD 평가 | M4, M5, M8을 섞은 결과물 전체 | 각 유형 80% 이상 |
| V6 | 시청자 평가 | M6, M7을 섞은 결과물 전체 | 각 유형 70% 이상 |
| V7 | 사람 편집본 우위 | 사람 편집본과 자동 결과를 같은 평가자에 넣음 | 사람 편집본의 지적 수 ≤ 자동 결과 |
| V8 | 관점 분리 | V5·V6에서 두 평가자의 지적 겹침 | 90% 미만 (너무 겹치면 분리가 무의미) |
| V9 | 점수 타당성 | BS145 v2에서 사용자가 고친 이음새 vs 고치지 않은 이음새의 점수 | 고친 쪽 평균이 뚜렷이 낮음, 순위 AUC 0.75 이상 |
| V10 | 경계 정확도 | 자동 컷 경계와 사람 편집본 컷 경계의 차이 | 스냅 도입 후 중앙값이 현재보다 작음 |
| V11 | 교차 모델 효과 | 같은 모델 판정 vs 교차 모델 판정을 M4~M6에서 비교 | 교차 쪽 검출률 ≥ 같은 모델 |

기준을 못 넘으면 루프를 켜지 않는다. 해당 평가자의 입력·프롬프트·모델을 고친 뒤 다시 잰다.

### 3.1 기준값 캘리브레이션
다음 값은 V1~V9 데이터로 정한다.
- 관문 G1의 dB 기준, G2의 허용 오차
- 라우팅 신뢰도 기준 — `route_candidates.py`의 `CUT_CONFIDENCE_MIN = 0.75`, `KEEP_CONFIDENCE_MIN = 0.55`(09-30 확정값. 09-29엔 0.80이었으나 BS145+BS167 gold 대조 결과 `action=KEEP`이 신뢰도 [0.55, 0.80) 구간에서 강제 CUT+flag 되던 29건 중 26건(90%)이 실제로는 gold-KEEP이었음을 확인해 하향)
- 이음새 점수 가중치와 기준 (0.7)
- 쉼 트림 이음새를 부분 루프에 넣는 기준 (0.7)

정하는 원칙: **경고 없는 복원이 0이 되는 선에서 flag 수가 가장 적은 값**을 고른다.

## 4. 운영 지표

`~/.video-cut/history.jsonl`과 `actions.log`에서 계산한다.

| 지표 | 계산 | 목표 |
|---|---|---|
| **경고 없는 복원** | flag 없는 자동 컷을 사용자가 복원한 건수 | **항상 0.** 한 건이라도 생기면 최우선 수정 |
| 영상당 검토 시간 | 첫 카드 열기 ~ 확정 | 편마다 ▼ |
| 영상당 판단 필요 카드 수 | 판단 필요 층 카드 수 | ▼ |
| flag 정밀도 | flag 항목 중 실제 복원된 비율 | ▲ (너무 낮으면 flag가 헛경고) |
| 사용자 추가 컷 | 사용자가 직접 추가로 자른 건수 | ▼ (재현율 지표) |
| 카드당 결정 시간 | 유형별 `decision_sec` 중앙값 | ▼ |
| 처리 시간 | 요청 ~ 검토 준비 | 12분 이내 |
| 영상당 LLM 비용 | `llm_calls.jsonl` 합산 | 추세 관찰 |

"오삭제 0"([`../백로그/왜-이탈하는가.md`](../백로그/왜-이탈하는가.md) 측정)은 "경고 없는 복원 0"으로 바뀐다. 방침 1(최대 삭제)에서는 복원 자체는 정상 동작이고, 문제는 도구가 **경고 없이** 틀리는 것이다.

## 5. 회귀 게이트 (🆕 `scripts/eval_seams.py`)

프롬프트, 모델, 기준값, 알고리즘을 바꿀 때마다 돌린다.

```bash
uv run python scripts/eval_seams.py            # V1~V11 전체
uv run python scripts/eval_seams.py --quick    # 결정론 항목(V1, V2, V10)만, LLM 비용 0
```

- 결과는 `references/eval_runs/<날짜>-<변경 요약>.json`에 저장하고, 직전 실행과 나란히 비교해 출력한다.
- 하나라도 통과 기준 아래로 내려가면 실패로 표시한다. 자동으로 막지는 않고 변경한 사람이 판단한다.
- L2에서 승격한 경고 없는 복원 반례는 `references/gold_data_v2/regressions/`에 쌓이고, 게이트에 자동으로 포함된다.

## 6. 채택 판단

[`../서비스-개요와-철학.md`](../서비스-개요와-철학.md) 원칙 3대로, 새 기능은 **검토 건수와 시간이 줄었을 때** 채택한다.

| 단계 | 비교 | 채택 조건 |
|---|---|---|
| 경계 스냅 (P1) | BS145: 현재 경계 vs 스냅 경계 | V10 개선, V2 통과 |
| 부분 루프 (P2) | BS145 v2 검토 기준선 vs 부분 루프 적용 결과로 재검토 | 판단 필요 카드 감소, 경고 없는 복원 0 |
| 전체 루프 (P3) | 부분 루프만 vs 부분 + 전체 | 사용자 추가 컷 감소 또는 판단 필요 카드 감소 |
| 검토 화면 (P4) | 같은 영상, 기존 화면 vs 새 화면 | 검토 시간 감소 |
| 학습 (P5) | 영상 N편째의 검토 시간 추세 | 편마다 감소 |

같은 영상을 두 번 검토하면 두 번째가 빨라지는 학습 효과가 있다. P2~P4 비교는 가능하면 새 영상으로 하고, BS145로 할 때는 이 점을 감안해 해석한다.

### 6.1 A/B 비교는 반드시 깨끗한 상태에서 다시 만든다 (🆕 2026-09-30 실수에서 발견)

**실수**: `route_candidates.py`의 KEEP 임계값을 고쳐 효과를 재려고, 이미 `global_review.py`를 여러 차례(이전 세션의 병합 정책 실험 등) 돌려놓은 백업 위에서 `assemble_draft.py → seam_refine.py → global_review.py`만 다시 실행해 비교했다. `global_review.py`의 PD/시청자 평가는 **결정론적이지 않고 멱등하지도 않다** — 이미 반영된 `missed_cut`이 있어도 그 사실을 모른 채 매번 원문 전체를 다시 훑으므로, 돌릴 때마다 "새로운" 후보를 계속 찾아 `ng.json`에 누적된다. 그 결과 BS167 재검증에서 자동 컷 분량이 239s→303s로 늘어 정밀도가 떨어졌는데, 이게 KEEP 임계값 수정 때문인지 이전 세션들이 남긴 `global_review` 라운드가 누적된 탓인지 한동안 구분이 안 됐다(패치한 20개 항목 중 19개는 실제로 의도대로 바로잡혔음에도 전체 지표는 나빠 보이는 혼선이 생김).

**규칙**: 파이프라인 코드(라우팅 임계값, 병합 정책, 프롬프트 등)를 바꾼 뒤 gold 비교로 효과를 재려면, **반드시 `route_candidates.py`부터 새로 시작한다** — 캐시된 `ng_classified.json`(Stage 2 `classify_region.py`의 분류 결과, LLM 재호출 없이 재사용 가능)을 입력으로 `ng.json`을 통째로 다시 만들고, 이후 단계인 `detect_filler_candidates.py → assemble_draft.py → seam_refine.py → global_review.py`(09-30 재설계로 `whole_context_review.py`는 삭제됨 — 전체 맥락 스캔은 `detect_regions.py`/`classify_region.py`로 흡수됨)를 이 세션에서 **정확히 한 번씩만** 실행한 뒤 비교한다. (`scripts/run.py` 기준 전체 파이프라인 순서는 `detect_regions.py → classify_region.py → route_candidates.py → detect_filler_candidates.py → assemble_draft.py → seam_refine.py → global_review.py`다.) 이전 백업(특히 `global_review.json`이 이미 존재하는 `edit.backup-*`)에서 일부 단계만 이어서 재실행하는 것은 "무엇을 바꿨는지"와 "몇 번 더 루프를 돌렸는지"가 뒤섞여 A/B 비교 자체가 무효가 된다. 반례가 의심되면 `ng.json`의 `label` 필드별 개수(특히 `GLOBAL_REVIEW_MISSED_CUT`)를 세어 비교 대상 두 상태가 정말 "그 코드 변경 하나만" 다른지 먼저 확인한다.
