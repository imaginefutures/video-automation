## 1. 제품 성격 / Design Read
- **유형**: 랜딩페이지도 대시보드도 아닌, 영상 편집자가 컷 제안을 빠르게 검토·확정하는 **내부 정밀 작업 툴**.
- **조작 방식**: 대부분 키보드로 이뤄진다 - `J`(다음 제안), `⌘Z`/`⌘⇧Z`(되돌리기/다시 실행), `Space`(재생), `X`(이음새), `Z`(정밀 조정), `Del`/`Enter`(삭제/살리기), `Esc`.
- **최우선 기준**: 가독성/가시성. 장시간 전사문을 읽고 ms 단위로 반복 조정하는 작업이므로, 장식보다 고대비·명확한 상태 구분이 우선이다.
- **레퍼런스**: Vercel의 "근백색 캔버스 + 근흑색 잉크 + 단일 accent" 시스템.

## 3. 컬러 토큰
`web/index.html` `:root`의 실제 값. 새 컴포넌트는 반드시 이 변수만 사용하고 hex를 직접 쓰지 않는다.

| 변수 | 값 | 용도 |
|---|---|---|
| `--bg` | `#ffffff` | 페이지/전사문 배경 |
| `--panel` | `#fafafa` | 사이드바 배경 |
| `--surface-2` | `#f5f5f5` | 팝업/모달/게이지 트랙 (떠 있는 표면) |
| `--ink` | `#171717` | 본문 텍스트 |
| `--muted` | `#666666` | 보조/캡션 텍스트 |
| `--line` | `#ebebeb` | 기본 보더 |
| `--line-strong` | `#a1a1a1` | 강조 보더 |
| `--cut` | `#a1a1a1` | 삭제된(cut) 단어 취소선 |
| `--proposal-bg` / `--proposal-line` | `#ffefcf` / `#ab570a` | 삭제 제안(proposal) 하이라이트 |
| `--gauge-bg` / `--gauge-fill` | `#f0f0f0` / `#d4d4d4` | 무음 게이지 트랙/기본 fill |
| `--gauge-user` / `--gauge-rule` | `#0070f3` / `#a1a1a1` | 사용자 조정 게이지 / 규칙 기반 게이지 |
| `--accent` / `--accent-soft` / `--accent-ink` | `#0070f3` / `#d3e5ff` / `#ffffff` | 브랜드 accent, 옅은 배경, accent 위 텍스트 |
| `--accent-strong` | `#0066dd` | 16px처럼 큰 크기에서 `--accent`로는 대비가 부족한 강조 텍스트 (예: `.duration-row .edited .stat-val`) - `--accent` 대비 하락 시에만 쓰는 한 단계 진한 변형, 새 의미를 만들지 않는다 |
| `--danger` / `--danger-soft` / `--danger-ink` | `#ee0000` / `#f7d4d6` / `#ffffff` | 삭제 액션 |
| `--select` / `--select-soft` | `#0070f3` / `#d3e5ff` | 텍스트 선택 하이라이트 (accent와 동일값) |
| `--chip` / `--chip-hover` | `rgba(0,0,0,.045)` / `rgba(0,0,0,.08)` | 아이콘 버튼 배경 |

**예외 (의도적 하드코딩)**: 비디오 컨트롤 바, 툴팁(`#gtip`), 토스트(`#toast`)는 페이지 테마와 무관하게 `#171717` 배경 + 흰 텍스트로 고정한다. 콘텐츠 위에 떠 있는 일시적 요소라 항상 최대 대비가 보장돼야 하기 때문이다.

**추가 예외**: `#zoomStatus .sw.cut`(정밀조정 패널의 "잘림" 범례 스와치)는 대각선 해칭 패턴을 그리려고 `#bdbdbd`/`#f2f2f2`를 직접 쓴다 - 이 스와치 하나에만 쓰이는 장식적 패턴이라 새 토큰을 만들지 않았다(3회 미만 반복은 추상화하지 않는다는 원칙, §12 참고). 테두리 색은 기존 `--gauge-fill`과 값이 같아 `var(--gauge-fill)`로 바꿨다.

## 4. 시맨틱 컬러 락
| 색 | 의미 | 절대 다른 의미로 쓰지 않는다 |
|---|---|---|
| 파랑 (`--accent`) | 확정 · 선택(selection) · 재생헤드 · 사용자 조정 게이지 | 유일한 브랜드 accent. 페이지 전체에서 "긍정/활성" 의미로만 |
| 빨강 (`--danger`) | 삭제 액션 전용 | 경고·강조 용도로 재사용 금지 |
| 호박색 (`--proposal-*`) | 검토 대기 중인 삭제 제안 하이라이트 전용 | |

accent를 **배경에 solid로 채울 때**만 흰 텍스트(`--accent-ink`/`--danger-ink`)를 쓴다 (`#0070f3`/`#ee0000` 위 흰 텍스트 대비 ≈4.55:1, WCAG AA 통과). 인라인 하이라이트(제안/선택 배경)는 옅은 `-soft` 배경 위에 기본 `--ink`를 그대로 얹는다 - 라이트 캔버스라 이 조합은 컴포넌트별 계산 없이 항상 충분한 대비가 나온다.

## 5. 타이포그래피
- **UI/본문**: `-apple-system, "Geist", "Inter", "Pretendard", "Apple SD Gothic Neo", sans-serif`. Geist/Inter는 한글 미지원이라 한글 글리프는 자동으로 Pretendard로 폴백된다.
- **숫자/기술 라벨** (`--mono`): `"Geist Mono", ui-monospace, SFMono-Regular, Menlo, Monaco, monospace`. 타임스탬프, duration, 게이지 숫자에 적용 - 정확도가 중요한 값은 등폭 글꼴로 자릿수가 흔들리지 않게 한다.
- 카탈로그의 `Developer Mono`(JetBrains Mono + IBM Plex Sans) 페어링에서 "모노+산세리프, 기술적·정밀함" 컨셉만 취했고, 실제 폰트 파일은 로컬 리뷰 서버가 외부 Google Fonts 요청 없이 동작하도록 시스템 폰트 스택으로 대체했다.

## 6. 간격 / 반경
| 변수 | 값 | 용도 |
|---|---|---|
| `--r-sm` | `6px` | 작은 인풋/뱃지 |
| `--r-md` | `8px` | 버튼/카드 기본 |
| `--r-lg` | `12px` | 팝업/모달 |
| `--r-full` | `9999px` | 확정 버튼, 아이콘 버튼(pill/원형) |

**Shape Consistency Lock**: 확정 버튼과 되돌리기/다시 실행 아이콘 버튼만 `--r-full`(pill/원)을 쓴다. 그 외 카드·인풋은 `--r-sm`~`--r-md`(6~8px), 큰 팝업/모달/패널(`#modal`/`#helpPop`/`#zoomPanel`/`#videoWrap`)은 `14px`를 쓴다 (실측값 기준 - `--r-sm`(6px)·`--r-lg`(12px) 토큰은 선언만 있고 `var()`로 실제 참조되는 곳이 없다. `6px`·`12px` 값 자체는 코드 곳곳에 하드코딩으로 맞게 쓰이고 있어 "범위"는 지켜지지만, 토큰 정의가 죽은 코드다).

## 7. 컴포넌트 규칙
- **팝업(선택 팝업/도움말/확정 모달/정밀조정 패널)**: 모두 `position: fixed` + 상단 `.drag-handle`로 어디로든 이동 가능. 새로 열릴 때(다른 선택, 재확정 등)는 항상 원위치로 재계산된다.
- **게이지 라벨**(`.g .lbl`): 파랑 fill(`--gauge-user`) 위에서는 `--accent-ink`(흰색)로 자동 전환 - 파랑 위 기본 `--ink`(검정)는 대비 미달이라 별도 규칙(`.g.user .lbl`)으로 처리한다.
- **파형 캔버스**(`<canvas>`): CSS 변수를 못 읽으므로 JS에서 동일 팔레트를 hex로 직접 지정한다. 실제로 쓰는 값은 `#4d4d4d`(파형), `#0070f3`(재생헤드/선택 구간 - `--accent`와 동일 의미), `#8f8f8f`(비선택 단어 라벨), `#666666`(잘림 구간 라벨과 파형 로딩 중 안내문 - `--muted`와 동일 의미) 4개다 - 값이 바뀌면 `:root`와 JS 양쪽을 함께 갱신해야 한다. (`#ee0000`/`--danger`는 캔버스에서 전혀 쓰이지 않는다 - §4 시맨틱 컬러 락대로 삭제 액션 버튼에만 쓰인다.)
- **스크롤 진행률 바**(`#scrollProgress`): `#main`(대본이 실제로 스크롤되는 컨테이너) 상단에 `position: sticky`로 고정. 시맨틱은 `role="slider"`(클릭/드래그/화살표 키로 값을 바꾸는 조작형 컨트롤이라 읽기 전용 `progressbar`가 아님) + `aria-valuetext`로 "N퍼센트 읽음 · 검토 대기 M건"까지 읽어준다. 시각 트랙은 3px로 얇지만 클릭 히트 영역은 24px(WCAG 2.2 AA Target Size 최소값)로 별도로 잡는다. 위에 얹히는 틱(`.tick`)은 "검토 필요" 큐의 미해결 항목 위치를 표시 - 색은 §4의 호박색(`--proposal-line`, 대기)/`--line-strong`(해결됨) 그대로 재사용하고, 새 의미를 만들지 않는다. 각 틱은 `title`로 유형·상태를 밝히고(다른 인라인 힌트와 동일한 관습, 예: `.note` 아이콘) 클릭하면 사이드바 카드를 눌렀을 때와 같은 위치로 점프한다 - 틱 하나의 히트 영역(10px)은 24px에 못 미치지만, 같은 기능을 하는 24px 이상 카드가 사이드바에 이미 있어 WCAG 2.2 Target Size의 "동일 기능의 대체 컨트롤" 예외에 해당한다.

## 8. 모션 토큰
babyscience-landing-web·marketing-recipe 두 프로젝트 모두 "지속시간·이징을 매번 새로 정하지 않고 고정 토큰에서 고른다"는 원칙을 공유한다. 같은 원칙을 이 문서에도 적용한다 - 단 새 값을 발명하지 않고, `web/index.html`에 이미 쓰이는 값에 이름만 붙였다 (기존 동작 변경 없음).

| 토큰 | 값 | 용도 | 현재 코드 |
|---|---|---|---|
| `--duration-instant` | 80ms linear | 재생헤드처럼 실시간 값을 뒤쫓는 요소 - 사용자 조작에 대한 "즉시 반응"이 아니라 연속값 추적이라 이징 없이 linear | `#scrollProgress .fill` width transition |
| `--duration-fast` | 120~160ms ease | 마이크로 피드백 (카드 active 링, 셰브론 회전) | `.review-card` box-shadow, `#pauseHead .chev` transform |
| `--duration-base` | 200ms ease | 패널 펼침/접힘 (높이 기반) | `#pausePanel` max-height |
| `--duration-float` / `--ease-out` | 150~220ms, `cubic-bezier(.2,.8,.2,1)` | 뜨는 패널의 등장/퇴장 (opacity+transform) | `#helpPop`, `#zoomPanel` |

- **비선형 이징은 하나만 쓴다**: `cubic-bezier(.2,.8,.2,1)`(`--ease-out`) 하나로 통일하고, 값 추적용(`--duration-instant`)만 예외적으로 `linear`. babyscience의 "이징 하나 + 드문 예외" 원칙과 동일.
- **소급 통일은 하지 않는다**: `120ms`와 `160ms`처럼 미세하게 어긋나는 기존 값을 지금 강제로 맞추지 않는다 - 두 원본 프로젝트 공통 규칙대로, 다음에 해당 컴포넌트를 실제로 건드릴 때 `--duration-fast`로 정리한다.
- **코드 미반영 표시**: 위 이름들은 아직 `:root`에 커스텀 프로퍼티로 선언돼 있지 않다(하드코딩 ms 값 그대로). 이 문서 서두의 "코드와 어긋나면 코드가 기준" 원칙에 따라, `:root` 선언이 실제로 추가되기 전까지는 이 표를 참고용 이름 매핑으로만 쓴다.

## 9. Elevation(그림자) 토큰
babyscience의 "색면 우선, 그림자는 드물게" + "고정 티어 몇 개로만 쓰고 새 rgba 값을 임의로 만들지 않는다" 원칙 적용. 마찬가지로 기존 값을 묶어 이름만 붙였다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--shadow-sm` | `0 6px 16px -4px rgba(0,0,0,.18)` | 작게 뜬 아이콘 버튼 (`#btnHelp`) |
| `--shadow-md` | `0 16px 40px -12px rgba(0,0,0,.18~.22)` | 선택 팝업(`#pop`), 도움말 패널(`#helpPop`) |
| `--shadow-lg` | `0 20~24px 50~60px -12~-14px rgba(0,0,0,.22~.25)` | 확정 모달(`#modal .box`), 정밀조정 패널(`#zoomPanel`) |

- **의도적 예외**: `#videoWrap`(플로팅 비디오 미리보기)만 `rgba(0,0,0,.7)`로 훨씬 진하다 - 스크롤되는 대본 텍스트 위에 항상 떠 있어야 해서 다른 뜬 요소보다 강한 분리가 필요하기 때문이다. babyscience가 예외를 코드 옆이 아니라 문서에 명시적으로 못박는 방식을 그대로 따른다.
- 그림자는 계층을 만드는 보조 수단이지 주 수단이 아니다 - 실제 계층 구분은 3장의 색 토큰(`--bg`/`--panel`/`--surface-2`)과 1px 보더가 담당한다 (babyscience §7 색면 우선 원칙과 동일).
- 8장과 마찬가지로 아직 `:root` 변수로 선언되지 않은 이름 매핑이다.

## 10. z-index 토큰
marketing-recipe의 "z-index는 하나의 정렬된 토큰 스케일로만 쓰고 하드코딩 숫자를 금지한다" 원칙 적용. 이 프로젝트는 이미 사실상 순서가 맞는 스케일을 쓰고 있었으므로(겹치는 순서를 손으로 맞춰온 결과), 이름만 공식화한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--z-sticky` | 7 | 스크롤 진행률 바 |
| `--z-video` | 8 | 플로팅 비디오 미리보기 |
| `--z-popup` | 10 | 선택 팝업(`#pop`) |
| `--z-tooltip` | 11 | 게이지 툴팁(`#gtip`) |
| `--z-modal` | 20 | 확정/에러 모달 |
| `--z-panel` | 24 | 정밀조정 패널(`#zoomPanel`) |
| `--z-float-btn` | 25 | 도움말 버튼/패널 |
| `--z-toast` | 30 | 토스트 |

- marketing-recipe는 이 스케일을 자동화된 e2e 테스트로 강제한다(화이트리스트 밖 하드코딩 숫자가 나오면 실패). 이 도구는 1인용 로컬 툴이라 테스트 인프라를 새로 만들 이득이 크지 않다고 판단, **자동 강제는 적용하지 않는다** - 대신 이 표를 유일한 출처로 두고, 새 오버레이를 추가할 때 여기서 고르거나 표에 줄을 추가하는 방식으로 규율을 유지한다.

## 11. 접근성 체크리스트
기존 항목:

- [x] 키보드만으로 전체 조작 가능 (§1 단축키 목록)
- [x] `prefers-reduced-motion` 대상 애니메이션 없음 (드래그/페이드는 사용자 조작에 대한 직접 반응이라 임의 지속 애니메이션이 아님)

marketing-recipe의 접근성 베이스라인에서 가져온 항목 (2026-09-29 코드 반영):
- [x] Esc가 모든 오버레이를 닫는다 (`#modal`, 정밀조정 패널, 선택 해제)

## 12. 검토했지만 적용하지 않은 것
babyscience-landing-web·marketing-recipe의 원칙 중, 이 도구의 성격(1인용 로컬 정밀 작업 툴)과 맞지 않아 의도적으로 적용하지 않은 것들.

- **`window.confirm()` 재사용 (marketing-recipe 원칙)**: 파괴적 액션 확인은 커스텀 모달(`confirmModal()`)을 계속 쓴다. 브라우저 네이티브 confirm은 "이 페이지가 추가 대화상자를 표시하지 않도록 함" 체크박스가 있어, 한 번 체크하면 같은 localhost 오리진의 모든 이후 방문에서 안전장치가 조용히 꺼진다 - 코드 주석에 이미 남긴 이유.
- **카드 대신 밴드 사용 (babyscience 원칙)**: 대상이 아니다. babyscience의 규칙은 마케팅 페이지에서 카드 배경과 페이지 배경의 명도차가 작아 "붕 떠 보이는" 문제를 겨냥한다. 이 도구는 `--proposal-bg`(#ffefcf)처럼 카드 배경이 페이지 배경과 확실히 달라 같은 문제가 없다.
- **좌/중/우 3단 화면 분할, 버튼 배치 5문항 결정 트리 (marketing-recipe 원칙)**: 대상이 아니다. 이 도구는 대본 컬럼 하나 + 플로팅 패널들 구조로, 여러 화면 슬롯을 나눠 규율할 필요가 없다.
- **z-index 위반을 잡는 자동 e2e 테스트 (marketing-recipe 원칙)**: 10장 참고 - 1인용 로컬 도구에 테스트 인프라를 새로 만들 이득이 없다고 판단해 문서화까지만 적용.
- **레거시 전체를 새 토큰으로 소급 적용**: 8~10장 토큰 모두 "새로 건드리는 코드부터 적용, 기존 코드 일괄 리팩터링은 하지 않는다"는 두 프로젝트 공통 원칙을 그대로 따른다.
