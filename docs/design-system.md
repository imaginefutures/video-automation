## 1. z-index 토큰
marketing-recipe의 "z-index는 하나의 정렬된 토큰 스케일로만 쓰고 하드코딩 숫자를 금지한다" 원칙 적용. 이 프로젝트는 이미 사실상 순서가 맞는 스케일을 쓰고 있었으므로(겹치는 순서를 손으로 맞춰온 결과), 이름만 공식화한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--z-sticky` | 7 | 스크롤 진행률 바 |
| `--z-video` | 8 | 플로팅 비디오 미리보기 |
| `--z-tooltip` | 11 | 게이지 툴팁(`#gtip`) |
| `--z-overlay` | 19 | 처리 진행 화면(`#pipelineProgress`) - 확인 모달(20)·토스트(30) 아래여야 중단 확인 모달이 가려지지 않는다. 떠 있는 동안 도움말 버튼(25)은 숨긴다 (10-06 polish, 이전엔 스케일 밖 9999) |
| `--z-modal` | 20 | 확정/에러 모달 |
| `--z-float-btn` | 25 | 도움말 버튼/패널 |
| `--z-toast` | 30 | 토스트 |

- marketing-recipe는 이 스케일을 자동화된 e2e 테스트로 강제한다(화이트리스트 밖 하드코딩 숫자가 나오면 실패). 이 도구는 1인용 로컬 툴이라 테스트 인프라를 새로 만들 이득이 크지 않다고 판단, **자동 강제는 적용하지 않는다** - 대신 이 표를 유일한 출처로 두고, 새 오버레이를 추가할 때 여기서 고르거나 표에 줄을 추가하는 방식으로 규율을 유지한다.


## 2. 접근성 체크리스트
기존 항목:
- [x] 본문 텍스트 대비: `--ink`(#171717) on `--bg`(#ffffff) ≈ 17.9:1
- [x] accent 버튼 텍스트: 흰색 on `--accent`/`--danger` ≈ 4.55:1 (AA, 정상 크기 텍스트 임계값에 근접 - 버튼 폰트를 더 작게 줄이지 말 것)
- [x] 키보드만으로 전체 조작 가능 (§1 단축키 목록)
- [x] `prefers-reduced-motion` 대상 애니메이션 없음 (드래그/페이드는 사용자 조작에 대한 직접 반응이라 임의 지속 애니메이션이 아님)
- [x] `--muted`(#666666) on `--bg`(#ffffff) ≈ 5.7:1 - AA(4.5:1)는 여유 있게 통과, AAA(7:1)에는 못 미친다. 작은 텍스트를 더 흐리게 내리지만 않으면 됨 (이전 §3에 `#767676`으로 잘못 기록돼 있던 걸 코드 기준으로 정정 - 실제 여유는 더 크다)
- [x] 스크롤 진행률 바(`#scrollProgress`): `role="slider"` + `aria-valuenow`/`aria-valuetext` + 화살표 키(←→↑↓/Home/End) 조작, 클릭 히트 영역 24px(WCAG 2.2 AA Target Size 최소), 개별 틱은 10px이지만 동일 기능의 24px 이상 대체 컨트롤(사이드바 검토 카드)이 있어 예외 적용

marketing-recipe의 접근성 베이스라인에서 가져온 항목 (2026-09-29 코드 반영):
- [x] Esc가 모든 오버레이를 닫는다 (`#modal`, 도움말 패널, 선택 해제)
- [x] 아이콘 버튼(`#btnUndo`/`#btnRedo`/`#btnHelp`)에 `title`과 별도로 `aria-label` 병기
- [x] `.review-card`는 `tabIndex=0`+키보드 핸들러(Enter/Space)만 쓰고 `role="button"`은 쓰지 않는다 (marketing-recipe 원칙 - 중첩 시맨틱·e2e 셀렉터 충돌 방지)
- [x] `#modal`(진짜 블로킹 오버레이)에 `role="dialog"`/`aria-modal="true"`. 비블로킹인 도움말 패널(`#helpPop`)에는 붙이지 않는다 (marketing-recipe의 Inspector-vs-canvas-popover 구분과 동일한 기준)
- [x] `#toast`에 `role="status"`/`aria-live="polite"` - 스크린리더가 저장/실행취소 알림을 읽는다


## 3. 검토했지만 적용하지 않은 것
babyscience-landing-web·marketing-recipe의 원칙 중, 이 도구의 성격(1인용 로컬 정밀 작업 툴)과 맞지 않아 의도적으로 적용하지 않은 것들.

- **`window.confirm()` 재사용 (marketing-recipe 원칙)**: 파괴적 액션 확인은 커스텀 모달(`confirmModal()`)을 계속 쓴다. 브라우저 네이티브 confirm은 "이 페이지가 추가 대화상자를 표시하지 않도록 함" 체크박스가 있어, 한 번 체크하면 같은 localhost 오리진의 모든 이후 방문에서 안전장치가 조용히 꺼진다 - 코드 주석에 이미 남긴 이유.
- **카드 대신 밴드 사용 (babyscience 원칙)**: 대상이 아니다. babyscience의 규칙은 마케팅 페이지에서 카드 배경과 페이지 배경의 명도차가 작아 "붕 떠 보이는" 문제를 겨냥한다. 이 도구는 `--proposal-bg`(#ffefcf)처럼 카드 배경이 페이지 배경과 확실히 달라 같은 문제가 없다.
- **좌/중/우 3단 화면 분할, 버튼 배치 5문항 결정 트리 (marketing-recipe 원칙)**: 대상이 아니다. 이 도구는 대본 컬럼 하나 + 플로팅 패널들 구조로, 여러 화면 슬롯을 나눠 규율할 필요가 없다.
- **z-index 위반을 잡는 자동 e2e 테스트 (marketing-recipe 원칙)**: 1장 참고 - 1인용 로컬 도구에 테스트 인프라를 새로 만들 이득이 없다고 판단해 문서화까지만 적용.
- **레거시 전체를 새 토큰으로 소급 적용**: DESIGN.md의 모션·그림자 단계와 1장 z-index 모두 "새로 건드리는 코드부터 적용, 기존 코드 일괄 리팩터링은 하지 않는다"는 두 프로젝트 공통 원칙을 그대로 따른다.


## 4. 변경 이력
1. **v1 - Notion(라이트, 웜페이퍼)**: 최초 사이드바 리디자인 때 채택.
2. **v2 - Raycast(다크)**: 키보드 중심 정밀 툴이라는 이유로 다크 command-tool 미학으로 전환. **가시성 문제로 반려됨** - 반투명 accent 오버레이, 근흑색 캔버스 위 회색 hairline, 밝은 accent 배경마다 텍스트색을 개별로 뒤집어야 했던 구조적 리스크가 원인.
3. **v3 - Vercel(라이트, 고대비)**: 근백색 캔버스 + 근흑색 잉크로 전환, accent를 4색에서 파랑 하나로 통합. 이 문서(§2)에서 `ui-ux-pro-max` 카탈로그로 교차 검증 완료.
4. **v3.1 - 크로스 프로젝트 원칙 반영**: babyscience-landing-web·marketing-recipe의 디자인 가이드를 읽고, 이 도구에 맞는 원칙만 추려 8~12장으로 추가(모션/그림자/z-index 토큰화, 접근성 체크리스트 보강, 적용 안 한 항목과 이유 명시). 색·레이아웃·팝업 구현 방식(포지션 고정 + 드래그 핸들)은 바꾸지 않았다 - 두 원본 프로젝트와 이 도구의 제품 성격이 다르다는 판단(12장 참고).
5. **v3.2 - 문서·코드 정합화**: v3.1 검수에서 나온 이탈을 코드에 반영. `--muted`/§6 범위/§7 파형 색 등 문서가 코드와 어긋났던 곳은 코드 기준으로 문서를 고쳤고, `#searchBox`의 `--r-full` 오용·캔버스 로딩 텍스트의 회색 불일치·`#0066dd` 미등재(→`--accent-strong` 토큰화)·범례 테두리의 `--gauge-fill` 중복 하드코딩은 코드를 고쳤다. §11 접근성 항목(아이콘 버튼 `aria-label`, `.review-card`의 `role="button"` 제거, `#modal`의 `role="dialog"`/`aria-modal`, `#toast`의 `role="status"`/`aria-live`)도 전부 반영 - 시각적 변화 없음.
6. **v4 - DESIGN.md로 이관** *(현재, 2026-10-06)*: 토큰·색·타이포·모양·그림자·모션·컴포넌트 규칙을 루트 [`DESIGN.md`](../DESIGN.md)(+ `.impeccable/design.json`)로 옮기고 이 문서에서는 지웠다 - 같은 규칙을 두 곳에 두지 않는다. 기준 은유 "편집자의 교정지"를 정했고, 빨강은 삭제 동작 전용으로 재확인, 처리 진행 화면의 다크 배경과 홈 화면의 빨간 실패 표시는 DESIGN.md의 Known Drift로 기록했다. 이관하며 실제 코드와 대조해 이미 없어진 선택 팝업(`#pop`)·정밀조정 패널(`#zoomPanel`) 관련 서술은 옮기지 않았다.
