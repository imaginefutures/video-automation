## 실행 중 발견한 테스트 스크립트 자체의 함정 (감사 신뢰성 메모)

1인 로컬 도구의 단어 드래그 선택은 커스텀 mousedown/mousemove 트래커가 아니라 **브라우저 네이티브
`window.getSelection()`**을 읽는 방식(`onMouseUp`, index.html:937-956)이라, 화면 밖(스크롤 안 된)
좌표에 `page.mouse.move`를 보내면 selection API는 값을 반환해도 `mouseup` 리스너가 대상 엘리먼트에
도달하지 못해 `select()`가 전혀 호출되지 않았다. 1차 실행에서 이 때문에 "정밀 조정 패널이 안 열림",
"수동 삭제가 안 먹힘" 같은 거짓 실패가 나왔고, `scrollIntoViewIfNeeded()`를 드래그 시작 전에 넣고
나서야 정상 재현됐다. 아래 findings는 전부 이 수정 이후 재실행(3회차, exit 0)과 후속 단독 검증
스크립트로 확인한 것만 담았다.

## Findings (신규)

### H-SKIP — 건너뛰기(skip) 기능이 UI 어디에도 남아있지 않음
- **Layer** Architecture · **Severity** High · **Surface** / 1440, 검토 팝업 전체
- **Persona** 시간 압박 큰 크리에이터 — 애매한 항목은 나중으로 미루고 우선 확실한 것부터 처리하고 싶음
- **Reproduce** 1) 아무 페이지 로드 2) J로 검토 항목 선택 3) 열린 팝업의 버튼을 전부 확인 4) `s` 키 입력해봄
- **Observed** 팝업 버튼은 `popPlay, popJoin, popToggle, popZoom, popStar, popKeepCut` 6개뿐(스크린샷
  `C4-skip-search.png`). 전역 키다운 핸들러(index.html:1711-1729)에도 skip에 대응하는 키가 없고,
  `contextmenu`/`dblclick` 핸들러도 카드 어디에도 없음. 그런데 서버는 `action: "skip"`을 ng/block
  양쪽 모두 완전히 지원하고(`scripts/server.py:433,496,499,513,515-520`), 클라이언트 코드 주석도
  "Skip only makes sense before a real decision exists... (see skipCurrent())"(index.html:1016-1022),
  "Skipped items aren't pending, so J moves past them (H3)"(index.html:1414)처럼 skip을 살아있는
  설계 요소로 서술한다. `skipCurrent()` 함수 자체도 코드베이스에 존재하지 않음(grep 결과 0건) —
  즉 이 기능은 서버·상태모델·CSS(`.review-card.st-skipped`)·상태 라벨(`STATUS_KO.skipped`)까지 전부
  살아있는데 오직 "누르는 방법"만 사라진 상태
- **Expected** 애매한 항목을 판단 보류할 수 있는 명시적인 버튼/단축키가 팝업에 있어야 함
  (H3 수정 당시 nextPending/isProposal 로직을 다시 짜면서 그 자리에 있던 트리거가 함께 빠진 것으로 보임)
- **Evidence** `pw/out/shots/C4-skip-search.png`, 팝업 버튼 목록 로그(`popButtonIds`), server.py의
  `{"cut": "삭제", "keep": "살리기", "skip": "건너뛰기"}` 매핑(line 433)이 죽은 코드가 된 상태
- **Suspected location** [index.html:376-381](../web/index.html#L376-L381) (`#pop` 버튼 목록에
  건너뛰기 버튼 누락), [index.html:1719](../web/index.html#L1719) (전역 keydown에 skip 키 없음)
- **Smallest patch**
  ```html
  <!-- #pop 안, popKeepCut 옆 -->
  <button id="popSkip" title="지금은 판단 보류 (나중에 J로 다시 나타남)">건너뛰기 <kbd>S</kbd></button>
  ```
  ```js
  $('#popSkip').addEventListener('click', () => { if (selReviewMatch) decideSkip(selReviewMatch); });
  // keydown 핸들러의 if(sel){...} 블록에 추가:
  if (e.key === 's') { e.preventDefault(); if (selReviewMatch) decideSkip(selReviewMatch); return; }
  ```
  (`decideSkip`은 `{type: selReviewMatch.kind, i/block_id: ..., action: 'skip'}`을 `decide()`에 넘기면 됨 — 서버는 이미 처리 가능)

### H-MODAL — 모든 모달에 접근성 이름 없음 (axe Serious, 하드 게이트)

## Hold this in your hands

1차 감사에서 고친 다섯 가지(H1~H5, C1)는 전부 그대로 잘 버티고 있다. 정밀 조정 패널은 이제 뭘
살리고 뭘 자르는지 정확히 보여주고, ⌘Z는 방금 한 결정만 정확히 짚어 되돌리고, 발화 블록은 J
한 번에 통째로 선택된다 — 약속이 지켜지고 있다는 뜻이다. 그런데 오늘 새로 더 깊이 들어가 보니,
이 도구가 "판단을 미룰 자유"를 조용히 잃어버렸다는 게 보인다. 서버도, 주석도, 상태 모델도 여전히
"건너뛰기"를 하나의 정당한 선택지로 대하는데, 정작 손을 뻗을 버튼이 없다. 시간에 쫓기는 사용자가
애매한 항목 앞에서 멈칫하는 순간 — 이 도구가 가장 잘 도와줘야 할 바로 그 순간에 — 선택지가
삭제/보류가 아니라 삭제/살리기 둘 중 하나로 강제된다. 접힌 아코디언 속에 숨은 8개의 입력도 비슷한
결이다: 마우스로는 안 보이니 문제없다고 넘어갔겠지만, 키보드로 훑는 사람에게는 화면에 없는 늪
지대다. 둘 다 하루면 고칠 수 있는 크기이고, 고치고 나면 "J와 Enter만 눌러도 믿을 수 있다"는 약속에
"애매하면 건너뛰어도 된다"는 조항까지 온전히 채워진다.

## 사용성 검토 (오류 너머 — 조작 용이성)

버그 수정과 별개로 "빠르게, 실수 없이 20여 건을 처리한다"는 목표에 비춰 직접 조작해보며 짚은 지점:

1. **사이드바 헤더가 스크롤에 딸려 사라지던 문제 → 고침.** J로 아래쪽 항목까지 이동하면
   `scrollIntoView`가 사이드바 전체(헤더 포함)를 스크롤시켜, 정작 큐를 한창 처리 중일 때 확정
   버튼과 진행률("N/M 완료")이 화면 밖으로 나가곤 했다. `.pad`+진행률을 `#sidebarSticky`로 묶어
   `position: sticky`로 고정 — 몇 항목을 처리하고 스크롤해도 확정 버튼과 진행률은 항상 그 자리에 있다.
2. **"지금 뭐가 남았는지" 한눈에 보기 → 이미 잘 풀려 있었다.** 처음엔 리뷰 카드가 완료된 것과
   대기 중인 것을 구분 없이 한 리스트에 섞어 보여줘 스크롤하며 눈으로 걸러야 하는 게 아닌가
   싶었는데, 실제로 써보니 `#scrollProgress`의 주황/회색 점(대기/완료)이 대본 전체 길이에 걸쳐
   "어디에 뭐가 남았는지"를 미리 보여주고, `reviewProgress`가 상시 노출되는 지금 구조로 충분히
   해소됨을 확인. 별도 "완료 항목 숨기기" 토글은 불필요 판단
3. **팝업의 결정 버튼이 도구 버튼들 사이에 묻히던 문제 → 설계가 아예 바뀌며 자연 해소.**

   훑을 때 시간이 걸렸는데, 이번에 건너뛰기/검토 완료/★가 팝업에서 리뷰 카드 쪽으로 옮겨가면서
   팝업엔 "듣기 도구"만 남고 결정은 카드에서 바로 하게 됨 — 두 역할이 공간적으로도 분리되어
   오히려 더 명확해짐
4. **남은 미세 조정 (우선순위 낮음, 급하지 않음):** 대기 중인 리뷰 카드는 버튼이 3개(건너뛰기/
   ✓ 검토 완료/☆ 엔딩용 후보)라 248px 폭 사이드바에서 한 줄에 다 안 들어가고 마지막 ★ 버튼이
   다음 줄로 밀림(`pw/out4/shots/final.png`). 기능엔 지장 없고 라벨도 명확해 급히 손댈 정도는 아니지만,
