# video-cut — 서비스 개요와 철학

상태: 핵심 문서, 항상 최신으로 유지한다. 원칙이 실제로 바뀔 때는 이 문서를 고치고 [`결정-이력.md`](결정-이력.md)에 날짜와 이유를 남긴다 — 덮어쓰지 않고 기록한다.
문서 지도는 [`README.md`](README.md).

## 한 문장

**강의형 토킹헤드 원본을 폴더에 넣으면, 텍스트 화면에서 몇 분 검토하고 확정하는 것만으로 Final Cut Pro에서 바로 마무리할 수 있는 러프컷이 나온다.**

## 사용자와 상황

- 과학·논문 근거 기반 육아 강의 채널 운영자 (레퍼런스: 베싸TV)
- 원본 10~25분, 화면 밖 PD/코치가 있을 때가 있음
- 마무리 도구는 Final Cut Pro. 편집 판단을 남에게 맡기지 않고 직접 확인하고 싶어 함
- 이 도구의 진짜 경쟁자는 다른 AI 편집기가 아니라 **"FCP에서 손으로 자르기"**다 — 왜 그런지와 대응은 [`백로그/왜-이탈하는가.md`](백로그/왜-이탈하는가.md)

## 원칙 — 바뀌지 않는 것

### 원칙 1. 마무리는 사람이 한다

자동으로 러프컷을 만들고 사람이 확인·마무리한다. 완전 자동 mp4는 만들지 않는다.

> 적용 범위: 촬영 원본 컷편집. 완성본을 여러 편으로 나누는 [주제별 분할](백로그/주제별-분할.md)은 구간 안쪽을 건드리지 않고 경계를 사람이 확정하므로 mp4를 직접 낸다 (10-08).

- 강의 콘텐츠는 잘못 잘린 한 문장이 영상 전체 신뢰도를 깎는다
- FCPXML은 원본의 구간 참조 목록이라 원본이 손상되지 않는다. 잘린 구간은 FCP에서 클립 경계를 트림하면 그대로 살아난다. 재렌더·재전사 불필요

### 원칙 2. 편집 원칙 (이전 Palmier 프로젝트에서 검증, 구현이 바뀌어도 유지)

1. **무음은 지우지 않고 리듬에 맞게 다듬는다.** 목표치는 [`현재-설계/무음-리듬.md`](현재-설계/무음-리듬.md)
2. **재촬영은 시간상 마지막 시도만 남긴다.** 명시적 촬영 규칙
3. **반복은 NG가 아니다.** 강조 반복, 교육적 재진술, 정상 나열, 조사·어미만 바뀐 수정은 의미 판단으로 구분한다 ([`현재-설계/NG-판별.md`](현재-설계/NG-판별.md) 케이스 분류)
4. **정상 발화는 결과물에서 잘리지 않는다. 자동화율보다 우선한다.**
   - 발화 경계에 10~20ms 여유 (구현: 컷 구간을 양쪽 15ms씩 안쪽으로 줄임)
   - 애매한 구간(검토 필요)은 **일단 지운 상태로 시작하고, 살릴지는 사용자가 결정한다** (09-29 변경, 아래). 보호 장치는 "애매하면 안 지운다"가 아니라 "애매한 건 전부 검토 큐에 올라가고, 한 키(`Enter`)로 살릴 수 있고, 확정 전에는 아무것도 최종이 아니다"이다
   - 자동 삭제(AUTO_SAFE)는 여전히 엄격하게 ([`현재-설계/NG-판별.md`](현재-설계/NG-판별.md) 라우팅). 검토 없이 지나가는 삭제는 그 기준을 통과한 것뿐
   - dB 기반 무음 검출은 추정일 뿐, 최종 확정은 사람이 듣는다

   > **09-29 결정 — 검토 필요는 기본 삭제.** 이전에는 검토 항목을 "유지된 채" 보여주고 사용자가 하나씩 지워야 했다. 이러면 검토를 안 한 항목은 NG가 그대로 남고, 사용자의 일이 "NG 찾아 지우기"가 된다. 바꾼 뒤에는 검토 항목(NG REVIEW 라우트, 추임새 후보 포함)과 발화 블록의 삭제 제안이 처음부터 잘린 상태로 시작하고, 사용자의 일은 "살려야 할 정상 발화 구하기"가 된다. 대가: 검토 없이 확정하면 애매한 구간이 잘린 채로 나간다 → 확정 버튼이 남은 검토 건수와 "모두 잘린 채로 나간다"는 사실을 먼저 알린다. 개인화([`현재-설계/검토-화면.md`](현재-설계/검토-화면.md))로 사용자가 늘 살리는 케이스는 다음 영상부터 기본값이 유지로 바뀐다

### 원칙 2b. 검토는 심플하게 3단계

자동 처리된 상태에서 시작해, 판단 종류별로 순서대로 간다 — 섞지 않는다.

1. **텍스트로 편집**: 본문만 읽으며 명백히 틀린 곳을 고친다
2. **파형 보고 세부 편집**: 잔음 의심 구간만 추적해 경계를 다듬는다
3. **들어보기**: 전체를 이어 들으며 확정한다

2026-10-02 결정. 이전엔 이 세 판단을 하나의 "선택→팝업→Enter" 루프로 묶어 처리해 느렸다 — 상세
설계·단축키는 [`현재-설계/검토-화면.md`](현재-설계/검토-화면.md).

### 원칙 3. 작업 방식 원칙

- **계획과 실행 분리.** 자동화는 "제안이 적용된 상태"까지만 만든다. LLM은 라벨만 붙이고 실행 권한이 없다. 확정은 사람이 웹에서 누른다
- **채택 기준은 "정확도가 올랐다"가 아니라 "내가 검토할 건수·시간이 줄었다"**
- 검토는 검토 대상만 모아서, 왜 봐야 하는지 근거를 붙여서
- 캐시된 작업은 다시 하지 않는다. 검증 실패 시 멈추고 자동 복구·추가 삭제는 하지 않는다
- 사람이 정정한 사례는 쌓이되, 규칙 변경은 사람이 승인한다 ([`현재-설계/검토-화면.md`](현재-설계/검토-화면.md) 개인화·패턴 제안)
- **문서도 이 원칙을 따른다.** 새 기획·새 결정은 기존 문서에 계속 이어 쓰지 않고 주제별 새 파일로 만든다. 진행 여부는 각 파일이 스스로 표시한다 (09-29 결정, [`결정-이력.md`](결정-이력.md))
- **기존 기능을 대체할 때는 옛 흔적을 같은 작업에서 지운다.** 새 기획·변경이 기존 스크립트·CLI 플래그·화면 요소·문서 절차와 같은 일을 하게 되면, "나중에 정리"로 미루지 않고 그 작업 안에서 함께 없앤다. 순서: (1) `SKILL.md`·`scripts/`·`web/`·`docs/` 전체를 코드 검색해 옛 진입 경로를 전부 찾는다 — 삭제가 위험해 보이는 이유는 대개 경로를 다 모르기 때문이고, 다 알면 지울 수 있다 (2) 각 흔적의 운명(삭제 / 새 방식으로 대체 / 영향 없음)을 정하고 "영향 없음"도 근거를 남긴다 (3) 자동/수동처럼 모드가 필요하면 **같은 화면 안의 설정**으로만 만들고, 모드마다 화면이나 경로를 따로 두지 않는다 (4) 정리 사실을 [`결정-이력.md`](결정-이력.md)에 날짜와 함께 남긴다. 둘 다 남기는 "병행"은 예외이며, 종료 조건(언제 누가 지우는지)을 정했을 때만 허용한다. 구체적인 대체 표 양식·커밋 메시지 필수 필드·정기 전수조사 절차는 [`교체-절차.md`](교체-절차.md)에 있다 (10-02)
