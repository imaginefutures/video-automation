## 1. 목표와 범위

### 1.1 한 문장

**강의형 토킹헤드 원본을 폴더에 넣으면, 텍스트 화면에서 몇 분 검토하고 확정하는 것만으로 Final Cut Pro에서 바로 마무리할 수 있는 러프컷이 나온다.**

### 1.2 사용자와 상황

- 과학·논문 근거 기반 육아 강의 채널 운영자 (레퍼런스: 베싸TV)
- 원본 10~25분, 화면 밖 PD/코치가 있을 때가 있음
- 마무리 도구는 Final Cut Pro. 편집 판단을 남에게 맡기지 않고 직접 확인하고 싶어 함
- 이 도구의 진짜 경쟁자는 다른 AI 편집기가 아니라 **"FCP에서 손으로 자르기"**다 (9장)

### 1.3 자동화 대상

| # | 대상 | 상태 |
|---|---|---|
| 1 | 컷편집: 재촬영(NG), 말더듬, 카메라 밖 대화, 무음 리듬 | ✅ |
| 1a | 컷편집: 재시작과 무관한 단독 추임새(음·어·아) | ✅ |
| 2 | 자막: 한국어 문장형, FCP 캡션 트랙 | ⬜ |
| 3 | 자료 화면: 키워드 카드·인용·논문/그래프 자리·삽화 제안 | ⬜ |
| 4 | 음량: -14 LUFS 정규화 | ⬜ |

### 1.4 범위 밖

- 완전 자동 mp4 출력 (2.1)
- 색보정, 최종 자막 디자인, 음악 — FCP 몫
- 스톡 B-roll 자동 삽입 (채널 스타일과 맞지 않음, 12장)

## 2. 원칙 — 바뀌지 않는 것

### 2.1 마무리는 사람이 한다

자동으로 러프컷을 만들고 사람이 확인·마무리한다. 완전 자동 mp4는 만들지 않는다.

- 강의 콘텐츠는 잘못 잘린 한 문장이 영상 전체 신뢰도를 깎는다
- FCPXML은 원본의 구간 참조 목록이라 원본이 손상되지 않는다. 잘린 구간은 FCP에서 클립 경계를 트림하면 그대로 살아난다. 재렌더·재전사 불필요

### 2.2 편집 원칙 (이전 Palmier 프로젝트에서 검증, 구현이 바뀌어도 유지)

1. **무음은 지우지 않고 리듬에 맞게 다듬는다.** 목표치는 5장 표
2. **재촬영은 시간상 마지막 시도만 남긴다.** 명시적 촬영 규칙
3. **반복은 NG가 아니다.** 강조 반복, 교육적 재진술, 정상 나열, 조사·어미만 바뀐 수정은 의미 판단으로 구분한다 (4.1)
4. **정상 발화는 결과물에서 잘리지 않는다. 자동화율보다 우선한다.**
   - 발화 경계에 10~20ms 여유 (구현: 컷 구간을 양쪽 15ms씩 안쪽으로 줄임)
   - 애매한 구간(검토 필요)은 **일단 지운 상태로 시작하고, 살릴지는 사용자가 결정한다** (09-29 변경, 아래). 보호 장치는 "애매하면 안 지운다"가 아니라 "애매한 건 전부 검토 큐에 올라가고, 한 키(`Enter`)로 살릴 수 있고, 확정 전에는 아무것도 최종이 아니다"이다
   - 자동 삭제(AUTO_SAFE)는 여전히 엄격하게 (4.3). 검토 없이 지나가는 삭제는 그 기준을 통과한 것뿐
   - dB 기반 무음 검출은 추정일 뿐, 최종 확정은 사람이 듣는다

   > **09-29 결정 — 검토 필요는 기본 삭제.** 이전에는 검토 항목을 "유지된 채" 보여주고 사용자가 하나씩 지워야 했다. 이러면 검토를 안 한 항목은 NG가 그대로 남고, 사용자의 일이 "NG 찾아 지우기"가 된다. 바꾼 뒤에는 검토 항목(NG REVIEW 라우트, 추임새 후보 포함)과 발화 블록의 삭제 제안이 처음부터 잘린 상태로 시작하고, 사용자의 일은 "살려야 할 정상 발화 구하기"가 된다. 대가: 검토 없이 확정하면 애매한 구간이 잘린 채로 나간다 → 확정 버튼이 남은 검토 건수와 "모두 잘린 채로 나간다"는 사실을 먼저 알린다. 개인화(6.4)로 사용자가 늘 살리는 케이스는 다음 영상부터 기본값이 유지로 바뀐다

### 2.3 작업 방식 원칙

- **계획과 실행 분리.** 자동화는 "제안이 적용된 상태"까지만 만든다. LLM은 라벨만 붙이고 실행 권한이 없다. 확정은 사람이 웹에서 누른다
- **채택 기준은 "정확도가 올랐다"가 아니라 "내가 검토할 건수·시간이 줄었다"**
- 검토는 검토 대상만 모아서, 왜 봐야 하는지 근거를 붙여서
- 캐시된 작업은 다시 하지 않는다. 검증 실패 시 멈추고 자동 복구·추가 삭제는 하지 않는다
- 사람이 정정한 사례는 쌓이되, 규칙 변경은 사람이 승인한다 (6.4 개인화, 6.5 패턴 제안)

## 3. 제품 형태와 사용 흐름

### 3.1 형태

- **Claude Code 스킬** (`~/.claude/skills/video-cut` 심링크). 자체 완결형 — video-use 등 외부 스킬에 의존하지 않는다 (video-use는 초기 참고 대상이었고 현재 코드는 쓰지 않음)
- **로컬 웹 검토 화면**: Python 표준 라이브러리 서버 + 단일 HTML. 판단은 전부 여기서 한다
- 확정 버튼이 서버에서 직접 FCPXML·미리보기를 만든다. Claude가 중간에 끼지 않는다
- Final Cut Pro는 **마무리 전용** (자막 스타일·자료 화면 배치·색). 컷 판단은 웹에서 끝난다

### 3.2 사용 절차

1. `videos/<이름>/raw.mp4`로 원본을 넣는다 (이름 자유, 한글 가능)
2. "videos/<이름> 컷편집 해줘" → 자동 처리 (BS145 24분 기준 수 분)
3. 브라우저 검토 화면에서 사이드바의 검토 항목만 처리 (6장)
4. **확정** → 폴더에 결과 생성
5. FCP에서 라이브러리 열기 → fcpxml을 브라우저 패널로 드래그

```bash
uv run python scripts/run.py videos/<이름>          # 전체 파이프라인 후 검토 화면
uv run python scripts/run.py videos/<이름> --serve  # 처리 건너뛰고 검토 화면만
uv run python scripts/run.py videos/<이름> --no-llm # API 비용 없이 결정론적 층만
```

### 3.3 폴더와 산출물

```
videos/<이름>/
  raw.mp4                   원본 (사용자가 넣음)
  <이름>.fcpxml             FCP용 결과 (확정 시)
  preview.mp4               720p 미리보기 (확정 시, 백그라운드)
  edit/
    clean.mp4               tmcd·메타데이터 제거본 (FCP 호환 필수, 브라우저 재생용)
    transcript.json         단어 단위 전사 + 화자
    prosody.json            단어별 F0·에너지
    speaker_blocks.json     카메라 밖 대화 블록 + 줄별 역할
    ng_candidates.json      NG 후보 (결정론적 탐지)
    ng_classified.json      LLM 분류 결과
    ng.json                 라우팅 결과 (AUTO_SAFE / REVIEW / KEEP)
    context_review.json     전체 맥락 검토 결과
    self_critique.json      자기검증 결과
    pauses.json             쉼 분류 + 추천 유지 길이
    decisions.json          사람의 모든 결정 (재현 가능한 기록)
    edl.json                확정된 컷 목록
    actions.log             결정·재생·UI 이벤트 로그 (한 줄 JSON, 타임스탬프 포함)

~/.video-cut/prefs/<사용자>.json   영상을 넘어 누적되는 케이스별 선호 (6.4)
```

단계별 캐시: `edit/`에 산출물이 있으면 그 단계는 건너뛴다. 다시 하려면 해당 파일을 지운다.

### 3.4 처리 파이프라인

```
raw.mp4
 0 정리          clean_media.py          tmcd·메타데이터 제거, faststart (스트림 복사, 무손실)
 1 전사          transcribe.py           ElevenLabs Scribe, 단어 단위, 화자 분리
 2 음향          prosody.py              librosa, 로컬 연산 (API 비용 0)
 3 화자 이탈     detect_speaker_blocks.py 대화 형태 구간 → 블록 + 줄별 역할      ※ 4보다 먼저
 4 NG            detect_ng_candidates.py → classify_candidates.py → route_candidates.py
                 → whole_context_review.py (45초 창 밖 재시작, 독백형 이탈)
                 → self_critique.py (자동 삭제 적용 후 어색한 곳 → REVIEW로 강등)
 5 무음          plan_pauses.py          쉼 문맥 분류 → 추천 유지 길이
 6 검토 화면     server.py + web/index.html
 7 확정          build_edl → export_fcpxml → render_preview (서버가 직접 실행)
```

화자 블록을 NG보다 먼저 돌리는 이유: 전체 맥락 검토가 이미 블록으로 잡힌 구간을 건너뛰어야 같은 구간이 두 번 보고되지 않는다.

## 4. NG 판별 설계 — 컷편집 품질의 핵심

원칙은 "잘라야 할 재시작"과 "살려야 할 반복"을 구분하는 것이고, 판단의 중심은 **내용(의미) 비교**다.

### 4.1 케이스 분류

| 케이스 | 정의 | 판단 근거 | 처리 |
|---|---|---|---|
| A. 실수 → 제대로 | 앞 시도에 오류가 있고 뒤에서 고침 | 두 시도 내용이 충돌. 편집어("아니", "어") 동반. 수정 단어에 음향 강조 | 앞 시도 삭제 |
| B. 말하기 → 더 잘 말하기 | 앞 시도도 맞지만 다시 말함 | **두 시도가 같은 정보인지 실제로 확인.** 새 근거·예시가 추가되면 NG 아님 | 같으면 앞 삭제 / 다르면 유지 / 애매하면 REVIEW |
| C. 강조 반복 | "정말 정말" | 어휘 범주, 운율 평행, 사이 쉼 짧음 | 유지 |
| D. 교육적 재진술·나열 | "다시 말하면", "첫째·둘째" | 담화 표지, 피치 리셋 없음 | 유지 |
| E. 형태론적 수정 | "하나의 → 하나를" | 어간 동일, 접사만 변경 | 경계가 깨끗하면(쉼 ≥ 0.15초) 틀린 단어 삭제, 붙여 말했으면 REVIEW |
| F. 미완성 후 방향 전환 | 문장을 버리고 다른 내용으로 | 앞 조각 미완결, 뒤와 무관 | 앞 조각 삭제 |

**B가 가장 어렵고 가장 중요하다.** 문자열 유사도로는 D와 구분할 수 없어서 LLM이 "전달하려는 정보가 같은가"를 명시적으로 판정하고, 항상 상위 모델로 에스컬레이션한다.

### 4.2 판별 신호

| 신호 | 내용 | 상태 |
|---|---|---|
| 텍스트 | 두 시도 전문, 앞뒤 문맥, 편집어, 담화 표지, 문장 완결·단어 절단, 내용 동일성 | ✅ |
| 음향 | 재시작 첫 단어 F0 리셋, 두 시도 F0 곡선 유사도, 수정 단어 에너지 증가, 경계 쉼 | ✅ `prosody.py`가 계산해 자연어 근거로 프롬프트에 넣음 |
| few-shot | 케이스별 예시 | ✅ 정적 6개. 검색 기반 전환은 10장 |
| 영상 프레임 | 시선 이탈, 자세 리셋 | ⬜ 선택 사항. 편당 $1 미만 추가라 비용은 결정 요인 아님. REVIEW 건수가 실제로 줄면 채택 |
| 출처 상태 | 후보 단어가 소스에 전체/부분으로 남았는지 | 이전 프로젝트 오류 9건 중 7건의 원인. 현재 구조(원본 직접 참조)에서는 발생하지 않음 |

### 4.3 탐지 → 분류 → 라우팅

1. **후보 탐지** (결정론적): 45초 창 안의 단어열 유사도 + 접두사 일치로 재시작 클러스터. 단어 절단·내부 반복도 후보
2. **분류** (LLM, 병렬): "화자가 의도한 최종 대본"을 먼저 복원하고 실제 전사와 대조. 출력은 케이스, 권장 행동, 삭제 범위, 근거, 신뢰도
3. **라우팅**

| 결과 | 조건 |
|---|---|
| AUTO_SAFE (자동 삭제 적용) | CUT, 신뢰도 ≥ 0.75, 케이스 A/B/E, 구간 ≤ 5초 |
| KEEP | KEEP, 신뢰도 ≥ 0.55 |
| REVIEW (기본 삭제 상태로 검토 큐에) | 나머지 전부. 신호가 갈림, B 애매, 구간이 길어 완성 문장이 섞였을 위험 |

AUTO_SAFE는 엄격하게. REVIEW는 잘린 상태로 시작하지만 전부 검토 큐에 뜨고 `Enter` 한 번으로 살린다(2.2-4). 오판의 최대 피해가 "검토 큐에서 살리기 한 번"이 되도록 설계한다.

### 4.4 하향식 체크 — 화자 이탈과 전체 맥락

BS145 원본↔편집본 정렬에서, 전체 삭제분의 64%(141초)가 재시작이 아니라 **화면 밖 코치의 실시간 지도 구간**이었다. 단어열에서 반복을 찾는 상향식 탐지로는 원리적으로 못 잡으므로 하향식 체크를 따로 둔다.

- **화자 블록** (`detect_speaker_blocks.py`): "말이 적은 화자 = 카메라 밖"은 틀렸다 (화자 라벨이 구간마다 바뀜). **대화 형태**(짧은 줄이 화자 간 번갈아, 전환 밀도 ≥ 0.4)로 잡는다. 블록 하나가 검토 항목 하나. 줄별로 지시/재시도/최종/내용 역할을 붙여 살릴 줄을 제안한다. 블록 뒤 두 줄도 문맥으로 준다
- **전체 맥락 검토** (`whole_context_review.py`): 전사 전체를 한 번에 읽고 45초 창 밖의 먼 재진술, 대화 형태가 아닌 독백형 이탈(예: 시작의 "큐", 끝의 "컷!")을 찾는다. 항상 REVIEW로만 보낸다
- 빈도가 낮아도 생략하지 않는다. 놓치면 방송 불가 수준의 실수다

### 4.5 자기검증

AUTO_SAFE 컷을 전부 적용한 뒤의 텍스트를 다시 읽혀 "어색하게 끊긴 곳"을 찾고, 해당 컷을 REVIEW로 강등한다. 강등만 하고 승격은 하지 않는다.

### 4.6 촬영 신호

"다시" + 2초 쉼을 두면 A·B 대부분이 결정론적으로 잡힌다. 가이드: `docs/촬영-가이드.md`.
**제약: 신호가 없는 영상도 똑같이 편집 가능해야 한다.** 신호는 정확도를 올리는 가산 요소이지 전제 조건이 아니다.

## 6. 검토 화면

**트랜스크립트가 곧 타임라인이다.** 영상을 보며 판단하지 않고, 텍스트 위에서 판단하고 소리로 확인한다. 디자인 규칙은 `docs/design-system.md`.

### 6.1 화면 구성

- **본문**: 두 상태뿐. 취소선(잘림) / 평범한 텍스트(유지). 검토 필요 항목도 기본 삭제라 취소선으로 보인다. 판단 근거가 있는 단어 옆에 작은 ⓘ. 단어 일부만 정밀 삭제되면 그 부분에만 빨간 줄, 잘린 단어 일부를 정밀 복원하면 그 부분에 파란 밑줄
- **왼쪽 사이드바**
  - 검토 필요: 결정이 필요한 항목이 카드로 ("○ 삭제됨 · 검토 대기"). 본문에는 색으로 따로 표시하지 않음
  - 발화 블록: 카메라 밖 대화. 클릭하면 본문에서 그 구간이 선택됨
  - 무음 리듬: 목표치 전역 조정 (아코디언)
  - 검색: 문구는 브라우저에서 즉시, 못 찾으면 서버가 의미 검색 ("셀리그만 이야기하는 부분")
- **우하단 `?`**: 전체 단축키

### 6.2 조작

| 조작 | 동작 |
|---|---|
| `J` | 다음 검토 항목으로 이동 → 자동 선택 + 팝업 (발화 블록은 블록 전체) |
| `Enter` | 팝업 버튼이 표시한 동작(삭제 또는 살리기) 실행. 검토 항목은 기본 삭제라 보통 "살리기". `Delete` 키는 쓰지 않음 |
| `⇧Enter` | 검토 항목의 삭제 유지(확정). 들어보고 삭제가 맞을 때. 사이드바에서 완료로 표시되고 개인화에 쌓임. 예전 "건너뛰기"는 없앰 — 그냥 `J`로 넘어가면 삭제된 채 대기로 남는다 |
| `Space` / `X` | 듣기 / 이음새 듣기 (컷 직전 + 직후를 이어서) |
| `Z` | 정밀 조정 (파형) |
| 드래그 | 아무 범위(쉼 포함)나 선택 → 팝업에서 삭제/살리기 |
| 취소선 클릭 | 그 덩어리 전체 선택 |
| 쉼 알약(게이지) | 길이에 비례. 드래그로 0~전체, 더블클릭은 추천값 |
| `⌘Z` / `⌘⇧Z` | 되돌리기 / 다시 실행 (같이 바뀐 결정까지) |

가상 재생: 브라우저가 clean.mp4를 직접 재생하며 잘린 구간을 건너뛴다. 컷 지점은 40ms 페이드 아웃 → 점프 → 60ms 복귀.

### 6.3 왜 이 형태인가 (폐기한 것들)

- FCP 마커 기반 검토 → 폐기. 48개 마커 = 결국 타임라인 전체를 훑어야 함
- 3색 표시(유지/자동 삭제/확인 필요) → 2색으로. 본문이 알록달록하면 "다 봐야 할 것 같은" 부담이 생김
- 오른쪽 큐 패널 → 폐기 후 왼쪽 사이드바 카드로 재구성
- 다크 테마 → 가시성 문제로 반려, 라이트 고대비로 확정

### 6.4 개인화 — 영상을 넘어 쌓이는 선호

사용자가 NG 케이스(A~F)별로 삭제/유지를 결정할 때마다 `~/.video-cut/prefs/<사용자>.json`에 누적한다. 같은 케이스에서 3회 이상, 75% 이상 한쪽으로 결정했으면 다음 영상부터 그 케이스의 REVIEW 항목에 사용자 기본값을 적용한다. 사용자가 반반으로 갈리면 계속 묻는다. 사용자 구분은 `VIDEO_CUT_USER` 환경변수 또는 OS 계정.

### 6.5 패턴 제안

한 세션에서 같은 케이스를 같은 방향으로 3번 연속 결정하면, LLM이 그게 일반화할 수 있는 규칙인지 판단해 배너로 제안한다 ("이후 이런 패턴은 자동으로 처리할까요?"). 사용자가 예를 눌러야만 적용된다. 현재는 **그 세션 안에서만** 유효하다 — 영상 간 규칙으로 승격하는 설계는 9장 R4.

### 6.6 모든 결정은 정답 데이터

`decisions.json`에 단어 범위, 종류, 원래 자동 라벨, 사람이 바꿨는지, 아웃테이크 별표를 기록한다. 같은 raw.mp4로 동일 결과를 재생성할 수 있다. `actions.log`에는 타임스탬프와 함께 모든 이벤트가 남아 검토 시간 측정에 쓸 수 있다.

## 7. 출력 사양

### 7.1 FCPXML

- 메인 스토리라인: 확정된 컷만 반영한 클립 시퀀스. `edit/clean.mp4`를 상대 경로로 참조하므로 폴더째 옮기면 어느 컴퓨터에서든 열림
- 확정 경로는 검토 마커 없이 내보낸다 (검토는 웹에서 끝남)
- 버전 1.11 (FCP 12.3에서 임포트 검증). 시간은 전부 정수 프레임 × frameDuration 유리수
- 필수 속성 (없으면 임포트 실패): `<sequence>`의 `audioLayout`·`audioRate`, `<format>`의 `colorSpace`, `<asset>`의 `videoSources`·`uid`
- 컷마다 3프레임 크로스 디졸브 (양쪽 핸들이 있을 때만). **FCP 임포트 확인 대기.** 실패 시 `--transition-frames 0`
- 다음 단계: 캡션 트랙(자막), connected clip(자료 화면), Roles(대화·자막·자료 분리)

### 7.2 preview.mp4

720p, 하드웨어 인코딩, 구간별 추출 후 이어붙임, 구간마다 30ms 오디오 페이드. 24분 원본 기준 1분 내외. 확정 직후 백그라운드 생성.

### 7.3 필수 전처리: clean.mp4

카메라 원본의 `tmcd`(타임코드) 데이터 트랙이 있으면 FCP가 파일을 미디어로 인식하지 못하고, 그 파일을 참조하는 FCPXML도 전부 실패한다. 파이프라인 0단계에서 항상 제거한다 (부록 A 참고).

### 8.3 LLM 재설계 효과

- 음향 근거가 실제 판단에 인용됨 ("피치 리셋이 동반되어 두 번째 시도가 실제 발화 시작")
- 전체 맥락 검토가 로컬 규칙이 전혀 못 보던 "큐"와 "컷!"을 찾음
- 자기검증이 대구 표현이 한쪽만 남은 어색한 컷 1건을 REVIEW로 강등
- 무음: 쉼 1,540개 중 LLM 분류 277개, 트림 223개로 247초 정리
- 음향 분석 소요: 24분 영상에 21초

### 8.4 알려진 한계

- 화자가 끊김 없이 말을 이어가면 **소음(물건 떨어지는 소리 등)은 텍스트 기반으로 원리적으로 못 잡는다.** 사용자 확인상 드물다. 대응은 10장 "오디오 이상탐지"
- 편집본에서 빠졌다고 전부 NG는 아니다 (호흡 정리, 주제 삭제). gold 자동 라벨링은 이유가 분명한 것만 확정한다
- 17:08~17:19 "오답"으로 보였던 구간은 채널의 **엔딩 아웃테이크 코너**였다. 지운 NG 일부를 영상 끝에 재구성하는 게 이 채널 스타일 → 아웃테이크 별표 기능과 9장 R6로 연결

## 9. 계속 쓰고 싶게 만드는 기획

### 9.1 문제 정의

이 도구의 경쟁자는 다른 AI 편집기가 아니라 **"그냥 FCP에서 손으로 자르기"**와 **"편집자에게 맡기기"**다. 사용자는 촬영을 마칠 때마다 이 도구를 켤지 말지를 다시 결정한다. 매번 이기려면 세 가지가 동시에 성립해야 한다.

1. **손으로 할 때보다 확실히 빠르다** — 그리고 그게 눈에 보인다
2. **결과를 믿을 수 있다** — 한 번의 오삭제를 발견하면 사용자는 모든 컷을 다시 확인하기 시작하고, 시간 이득이 사라지고, 떠난다
3. **쓸수록 더 빨라진다** — 지난 영상에서 가르친 것이 이번 영상에서 체감돼야 한다

셋 중 하나라도 무너지면 이탈한다. 특히 2번은 한 번 무너지면 회복이 거의 안 된다.

### 9.2 핵심 루프

```
촬영 ──▶ 넣기 ──▶ (알림) ──▶ 검토 ──▶ 확정 ──▶ 결과 영수증 ──▶ FCP 마무리
  ▲                            │                  │
  │                            ▼                  ▼
  └── 촬영 팁 1개 ◀── 배운 규칙이 쌓임 ◀── 결정 기록 (prefs, history)
```

루프를 한 바퀴 돌 때마다 **다음 바퀴의 검토가 짧아지고, 그게 숫자로 보여야** 한다. 이게 이 도구의 락인이다. 사용자의 편집 취향과 촬영 습관이 이 도구에 쌓이기 때문에, 다른 도구로 옮기면 처음부터 다시 가르쳐야 한다.

### 9.3 이탈 순간과 대응

| 이탈 순간 | 사용자의 속마음 | 대응 기획 |
|---|---|---|
| 촬영 직후 | "폴더 만들고 이름 바꾸고 명령어 치기 귀찮다" | R2 시작 마찰 제거 |
| 처리 대기 중 | 다른 일 하다 잊음 | R2 알림 + 진행 화면 |
| 검토 화면 첫인상 | "항목이 이렇게 많으면 손으로 하지" | R1 예상 소요시간, R4 자동 처리 근거 |
| 오삭제 발견 | "이제 다 다시 확인해야 하나" | R3 신뢰 장치 |
| 확정 후 FCP | "자막·자료화면은 결국 내가 다 하네" | R6 출력 확장 |
| 두 번째 영상 | "나아진 게 없는데?" | R1 영수증, R4 배운 것 가시화 |
| 촬영 공백 후 복귀 | "어떻게 쓰더라" | R7 프로젝트 홈 |
| 처리 실패 | "또 터졌네" | R8 실패 대응 |

### 9.4 기획 항목

#### R1. 결과 영수증 — 매번 이득을 숫자로 보여준다 ⭐ 1순위

확정 모달에 이번 영상의 결과를 보여주고, 채널 누적 기록에 한 줄 추가한다.

```
이번 영상  24:47 → 22:31  (잘라낸 2분 16초)
자동 처리  NG 17 · 쉼 223 · 대화 블록 1     내가 판단한 것  9건
검토 시간  6분 40초   (지난 영상 11분 20초 ▼41%)
누적       4편 · 검토 시간 평균 ▼  · 신고된 오삭제 0건
```

- 검토 시간은 `actions.log`의 첫 결정 ~ 확정 타임스탬프로 계산 (이미 기록 중, 추가 계측 없음)
- 확정 시 `~/.video-cut/history.jsonl`에 한 줄 기록: 영상, 원본 길이, 결과 길이, 자동 처리 수, 사람 결정 수, 검토 시간, 신고된 오삭제 수, 처리 비용 추정. **R4·R7의 데이터 기반**
- 검토 화면 첫 진입 시 "검토 항목 9건, 예상 5분"을 먼저 보여준다. 막막함을 없애는 게 목적
- 성공 기준: 2편째부터 "지난 영상 대비" 수치가 나오고, 사용자가 그걸 본다

#### R2. 시작 마찰 제거 ⭐ 1순위 (알림·진행 화면)

- **처리 완료 알림**: 전사·분류가 끝나면 macOS 알림 + 브라우저 자동 열기. `osascript` 한 줄
- **브라우저를 먼저 연다**: 처리 중에도 검토 화면을 띄우고 단계별 진행을 보여준다 (`/api/status` 이미 있음). 전사만 끝나면 본문은 먼저 읽을 수 있다
- (2순위) **폴더 자동 생성**: `videos/`에 아무 이름의 mp4를 넣고 스킬을 인자 없이 부르면, 아직 처리 안 된 영상을 찾아 폴더를 만들고 시작
- (2순위) **여러 파일 촬영 지원**: 촬영 가이드 7번은 `01_intro.mp4`, `02_main.mp4` 분할 촬영을 허용하지만 파이프라인은 `raw.mp4` 하나만 받는다. 순서대로 이어붙여 처리하도록 메운다 (가이드와 구현의 간극)

#### R3. 신뢰 장치 — 오삭제 0을 사용자가 확인할 수 있게 ⭐ 1순위 (이음새 릴)

- **확정 전 이음새 릴**: 모든 자동 컷 지점의 앞뒤 1.5초씩을 이어서 한 번에 재생한다 (40컷이면 약 2분). "혹시 잘못 잘린 게 있나"를 전수 확인하는 가장 빠른 방법. 가상 재생 인프라를 그대로 쓴다. 이상한 곳에서 `Enter`를 누르면 그 컷이 바로 선택된다
- **오삭제 신고**: 취소선 팝업에 "자동으로 잘못 잘렸음" 버튼. 누르면 복원 + 해당 케이스의 개인 선호를 한 단계 보수적으로 + `gold`에 반례 fixture로 기록. 사용자가 "고치면 다시는 안 틀린다"를 체감하게 하는 장치
- **안전 배지**: R1 영수증의 "신고된 오삭제 누적 0건"이 곧 신뢰 지표. 한 건이라도 생기면 숨기지 않고 보여주고, 어떻게 고쳐졌는지 링크
- **회귀 게이트** (10장): 프롬프트·임계값을 바꿀 때마다 gold 전체를 돌려 오삭제 0을 확인. 사용자에게 보이지 않지만 R3의 전제 조건

#### R4. 쓸수록 똑똑해지는 게 보이게 — 2순위 (3편 이상 쌓이면)

- **세션 시작 배너**: "지난 영상에서 배운 규칙 3개가 이번에 12건을 자동 처리했습니다 [보기]". 개인화(6.4)가 조용히 일하는 걸 드러낸다
- **규칙 장부**: 사이드바에 "내 규칙" 목록. 케이스별 선호(prefs)와 승인한 패턴 제안이 각각 언제·몇 번의 결정으로 생겼는지 보여주고, 끄기·되돌리기 가능. 통제감이 신뢰를 만든다
- **패턴 제안의 영구화**: 지금은 세션 안에서만 유효한 패턴 제안(6.5)을, 사용자가 "앞으로도"를 선택하면 prefs에 규칙으로 저장. 다음 영상의 분류 프롬프트 few-shot에도 우선 반영
- **검토 건수·시간 추세**: history.jsonl로 영상별 막대 그래프. "쓸수록 줄어든다"가 한눈에

#### R5. 촬영 ↔ 편집 피드백 루프 — 2순위

- 확정 후 영수증 아래에 **다음 촬영 팁 딱 1개**: "이번 검토 9건 중 5건은 신호 없는 재시작이었습니다. '다시' + 2초 쉼을 쓰면 자동 처리됩니다"
- 근거는 이번 영상의 REVIEW 사유 분포에서 촬영 습관으로 없앨 수 있는 가장 큰 항목 하나. 여러 개를 나열하지 않는다
- 추세: 신호 사용률, 신호 덕에 자동 처리된 건수. 사용자의 촬영 습관이 도구에 맞춰질수록 검토가 줄고, 도구를 바꿀 이유가 사라진다

#### R6. 한 번 검토로 더 많은 결과 — 3순위 (컷편집 안정 후)

확정 한 번으로 FCP에서 할 일이 줄어들수록 도구의 가치가 전체 편집 시간 대비 커진다. 전사·발화 경계·주제 전환 정보를 이미 갖고 있으므로 추가 검토 없이 뽑을 수 있는 것부터.

| 순서 | 산출물 | 재사용 자산 | 추가 비용 |
|---|---|---|---|
| 1 | 챕터 (`chapters.txt`, 유튜브 설명란 복붙) | 쉼 분류의 "주제 전환" 경계 | 거의 없음 |
| 2 | 엔딩 아웃테이크 코너 (별표 친 NG를 모은 FCP 컴파운드) | 아웃테이크 별표 (이미 있음) | 없음 |
| 3 | 자막 캡션 트랙 (4~7어절, 쉼·문장부호에서 끊기) | 단어 타임스탬프 | 없음 |
| 4 | 쇼츠 후보 (완결된 30~60초 구간 3개) | 발화 경계, 전체 맥락 LLM | 영상당 1회 호출 |
| 5 | 자료 화면 제안 (숫자·인용·논문 언급 문장에 카드 자리) | 전사, connected clip | 영상당 1회 호출 |
| 6 | 썸네일 후보 프레임 + 훅 문장 | 프레임 추출 | 선택 |

모두 "제안이 적용된 상태"까지만 만든다 (2.3). 자료 화면은 레퍼런스 영상 확보 후 스타일 결정 (11장).

**메모: R6-3(자막) 착수 시 검토할 것 — 워드바이워드 하이라이트 + 자동 이모지.** Submagic 벤치마크(경쟁 도구 조사, 2026-09-29)에서 확인: 말하는 순간의 단어만 강조되고(노래방 자막처럼), 문맥에 맞는 이모지가 자동 배치됨(수동 조정 없이 78% 정확도). 단어별 정확한 타임스탬프(Scribe)가 이미 있어서 구현 장벽 낮음 — 자막 청크 나누기(4~7어절)와 함께 스타일 결정 시 후보로 검토.

**결정 (2026-09-29): 하이라이트/쇼츠(R6-4)는 컷편집이 끝난 뒤 후속 기능으로 미룬다.**
- 이유: 지금 이 도구가 이겨야 할 대상은 "손으로 자르기"(9.1)다. 쇼츠 추출은 컷편집(4~8장)이 안정돼 "결과를 믿을 수 있다"(9.1의 2번 조건)가 먼저 성립해야 의미가 있다 — 본편 컷도 못 믿는데 거기서 하이라이트를 더 뽑는 건 순서가 바뀐 것
- 착수 조건: R6 표의 우선순위대로 챕터(1) → 아웃테이크(2) → 자막(3)까지 나온 뒤. 9.6의 3순위("검토 시간이 안정된 뒤")와 동일한 판단
- 지금 하지 않는 것: 별도 하이라이트/훅 탐지 LLM 패스, 세로 크롭, 쇼츠용 캡션 번인 — 전부 R6-4 착수 시점에 함께 설계
- 바뀌는 조건: 컷편집 자체(NG·쉼·화자블록) 검토 건수가 3편 이상 안정적으로 낮게 나오고, 자막(R6-3)까지 나온 뒤 재검토

#### R7. 프로젝트 홈 — 2순위

`/`에 영상 목록: 상태(처리 중 / 검토 중 N건 남음 / 확정 / 미리보기 준비됨), 확정일, 검토 시간. 클릭하면 이어서 검토. 촬영 공백 뒤 돌아와도 "어디까지 했더라"가 없다. 첫 진입 시 단축키 카드를 한 번 보여준다.

#### R8. 실패해도 떠나지 않게 — 2순위

- 단계 실패 시 브라우저에 원인(키 만료, ffmpeg 오류 등)과 재시도 버튼
- LLM 호출이 실패하면 해당 단계만 `--no-llm` 결정론적 결과로 자동 대체하고 "LLM 없이 처리됨, 검토 항목이 평소보다 많을 수 있음"을 표시. 검토는 항상 가능해야 한다
- 영수증에 영상당 처리 비용 추정을 표시해 "이거 계속 써도 되나" 걱정을 없앤다

### 9.5 측정

| 지표 | 계산 | 목표 방향 |
|---|---|---|
| 영상당 검토 시간 | `actions.log` 첫 결정 ~ 확정 | ▼ 편마다 |
| 영상당 사람 결정 수 | `decisions.json`의 `by: user` | ▼ |
| 자동 처리율 | 자동 결정 / 전체 결정 | ▲ |
| 신고된 오삭제 | R3 신고 버튼 | **항상 0.** 하나라도 생기면 최우선 수정 |
| 촬영 → 확정 리드타임 | raw.mp4 생성 시각 ~ 확정 | ▼ |
| 도구 사용률 | 촬영한 영상 중 이 도구로 확정한 비율 | 100% 유지. 이탈의 가장 정직한 신호 |

전부 `~/.video-cut/history.jsonl` 한 곳에서 계산한다.

### 9.6 우선순위

| 순위 | 항목 | 시점 |
|---|---|---|
| 1 | R1 영수증 + history.jsonl, R2 알림·진행 화면, R3 이음새 릴·오삭제 신고 | 다음 촬영분 전 |
| 2 | R4 규칙 장부·추세, R5 촬영 팁, R7 홈, R8 실패 대응, R2 폴더 자동 생성·분할 촬영 | 3편 이상 쌓였을 때 |
| 3 | R6 출력 확장 (챕터 → 아웃테이크 → 자막 → 쇼츠 → 자료 화면) | 검토 시간이 안정된 뒤 |

1순위를 먼저 하는 이유: 데이터(history)가 있어야 R4·R5·R7이 의미 있고, 신뢰(R3)가 없으면 나머지가 다 소용없다.

## 부록 B. 근거 연구

- Levelt (1983) *Monitoring and self-repair in speech* — 수정의 3단계 구조 (중단 → 편집어 → 수정)
- Levelt & Cutler (1983) *Prosodic marking in speech repair* — 실수 수정에는 운율 마킹, 표현 개선에는 없음 (A/B 구분 근거)
- Girand et al. *Classifying repeated words as planned or unplanned* — 어휘 범주로 강조 반복 97% 구분
- Zhang (2020) *The Prosody of Fluent Repetitions* — 유창한 반복은 쉼 길이·F0 곡선으로 구분
- Romana et al. (2023) — 텍스트+음향 결합이 단일 모달보다 우수, ASR 품질이 텍스트 기반의 상한
- Wu et al. (2026) — LLM 자기 수정 검출 F1 0.73, 도메인 주석이 충분하면 소형 파인튜닝 모델과 동등
- *Self-repair in Korean conversation* (East Asian Pragmatics) — 조사·어미 교체형 수정 (E 케이스 근거)
