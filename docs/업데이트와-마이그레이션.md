# video-cut — 업데이트와 마이그레이션

상태: ✅ 1차 구현 완료 (10-01, `결정-이력.md` 같은 날짜 항목). 설치 경로 통일 + 스키마 버전 체계 + `scripts/migrate.py`까지 끝났고, 실제 `MIGRATIONS` 변환 함수는 아직 비어 있다(지금 깨진 스키마가 없어서 - 아래 "구현 우선순위" 4번 참고).
문서 지도는 [`README.md`](README.md).

## 한 문장

**설치해서 쓰다가 코드가 업데이트돼도, 이미 각 영상 프로젝트에 쌓인 `edit/` 산출물과 `~/.video-cut/`의 전역 학습 데이터가 깨지지 않고 자동으로 따라온다.**

## 왜 필요한가 — 현재 상태의 위험

- **설치 경로가 두 개 공존한다.** [`SKILL.md`](../SKILL.md) "설치" 절의 수동 `git clone` + `ln -sfn`와, `.claude-plugin/marketplace.json`·`plugin.json`으로 추가된 `claude plugin` CLI 설치가 동시에 문서화돼 있다. 업데이트 방법이 경로마다 다르다 — [`서비스-개요와-철학.md`](서비스-개요와-철학.md) 원칙 3 "옛 진입 경로 공존 금지"에 바로 걸린다.
- **코드 버전은 있는데 데이터 버전이 없다.** `plugin.json`에 semver(`1.0.0`)는 있지만, 영상 프로젝트마다 쌓이는 `edit/*.json`(transcript, ng, final_cuts 등)과 전역 학습 데이터(`~/.video-cut/prefs/`, `cases/`, `history.jsonl`)는 버전 표시가 전혀 없다. 스키마가 바뀌어도 파일만 봐서는 구분이 안 된다.
- **캐시 존중 설계가 역으로 위험 요인이 된다.** "`edit/`에 산출물이 있으면 그 단계는 건너뛴다"는 설계(비용 절감 목적)가, 업데이트 후에는 "옛 버전 스키마를 새 코드가 그대로 읽어 조용히 틀리거나 죽는" 경로가 된다.
- **선례는 이미 있다.** 09-29 품질 루프 재설계 때 `videos/BS145.backup-pre-v2-20260929105827`처럼 폴더를 통째로 수동 복사해 백업했다. 이 패턴을 자동화하면 된다.

## 설계 원칙

- 마이그레이션은 조용히 실행하되 **무엇을 했는지는 반드시 출력** ("최대 삭제" 원칙과 같은 결 — 판단은 자동, 투명성은 필수)
- **비싼 단계(ElevenLabs 트랜스크립션)는 스키마가 안 바뀌는 한 절대 무효화하지 않는다** — 단계별 캐시 설계 유지, 버전도 파일 단위로 따로 관리
- 업데이트는 **사용자가 명시적으로 요청할 때만** 실행한다 (스킬 호출마다 자동 네트워크 체크 안 함 — 지연·프라이버시)
- 삭제 대신 백업 — 마이그레이션 불가능한 산출물은 지우지 말고 옮긴 뒤 재생성을 유도한다

## 구성 요소

### 1. 설치 경로 통일 — ✅ 완료

`claude plugin` CLI(`claude plugin marketplace add` + `claude plugin install`)를 정식 경로로 확정했다. `SKILL.md` "설치와 업데이트" 절의 수동 `git clone`+`ln -sfn`은 "CLI를 못 쓸 때의 대안"으로 격하. 업데이트는 `claude plugin update video-cut`(재시작 필요 — CLI가 직접 출력으로 안내한다).

### 2. 버전 체계 — ✅ 완료, 단 계획과 다르게 구현함

`plugin.json`의 semver는 기능 버전이고, 마이그레이션은 **파일별 스키마 버전**으로 따로 추적한다. 처음 계획은 각 JSON 안에 `"_schema_version"` 필드를 직접 넣는 것이었는데, `ng.json`·`final_cuts.json` 등 최상위가 **list**인 산출물이 있어서 dict 전용 필드를 끼워 넣을 수 없었다 — 대신 `edit/` 폴더 옆에 `.schema_versions.json` **사이드카**를 두는 쪽으로 바꿨다:

- `scripts/common.py`의 `SCHEMA_VERSIONS: dict[str, int]` — 파일명(예: `"ng.json"`) → 지금 코드가 그 파일을 쓰면 몇 버전인가. 전부 1부터 시작(이 체계 도입 시점의 기준선, 아직 스키마가 바뀐 적 없음)
- `common.write_json()`이 쓸 때마다 자동으로 `.schema_versions.json`에 기록 — 호출부(`route_candidates.py`, `seam_refine.py`, `global_review.py` 등)는 손댈 필요 없음
- 전역 `~/.video-cut/`는 논리적 이름(`prefs`/`history`/`cases`/`reported_bad_cuts`)으로 따로 추적(`scripts/migrate.py`의 `GLOBAL_CURRENT`) — 파일명이 사용자마다 달라서(`<사용자>.json`) 같은 사이드카 방식을 그대로는 못 씀

이렇게 하면 이번 릴리스에서 바뀐 파일만 재검증 대상이 되고, 안 바뀐 파일(예: 트랜스크립션)은 영향받지 않는다.

### 3. `scripts/migrate.py` — ✅ 완료

`run.py`(캐시 체크 전)·`server.py`(`serve()` 시작, 단독 실행 대비)·`setup.py`(`migrate_global()`)에 배선됨:

1. 대상 폴더에 `.schema_versions.json`이 아직 없으면(이 체계 도입 전부터 있던 프로젝트) **부트스트랩만 한다** — 지금 있는 파일을 전부 "호환됨"으로 간주해 사이드카를 새로 만들고, 아무것도 지우지 않는다. BS145로 실측 확인함
2. 사이드카가 있으면 기록된 버전과 `SCHEMA_VERSIONS`/`GLOBAL_CURRENT`를 비교해 뒤처진 파일만 처리
3. 버전 간 변환 함수가 있으면(`MIGRATIONS[("ng.json", 1, 2)]` 같은 식) 그 자리에서 데이터를 바꿔 다시 쓴다
4. 변환 함수가 없으면 — **프로젝트 캐시 파일**은 삭제가 아니라 백업한다: `edit/.backup/<파일명>.v<old>-<timestamp>.json`으로 옮기고 메시지를 출력 — 다음 실행이 그 단계부터 자연히 재생성한다(기존 캐시 로직 그대로, `run.py`/`server.py`는 하나도 안 고침). **전역 사용자 데이터**(재생성 불가)는 옮기지도 지우지도 않고 경고만 출력

### 4. 백업 규칙

09-29에 수동으로 했던 `videos/<이름>.backup-pre-v2-<timestamp>` 패턴을 폴더 전체가 아니라 **영향받는 파일 단위**로 자동화한다. 전체 폴더 백업보다 디스크를 덜 쓰고, 어떤 단계가 왜 날아갔는지 파일명에 그대로 남는다.

### 5. `.env` / API 키

`common.ensure_api_keys()`가 이미 "없는 키는 대화식으로 채운다"는 자가 치유 구조라 추가 작업 불필요하다 — 새 키가 `REQUIRED_API_KEYS`에 추가되기만 하면 기존 흐름이 그대로 처리한다.

### 6. 사용자 트리거 흐름 (`SKILL.md`에 추가할 절차)

"video-cut 업데이트해줘" / "업데이트 확인해줘" 요청 시 에이전트가:

1. 통일된 설치 경로의 업데이트 명령 실행 (`claude plugin update video-cut` 등)
2. 완료 후 아무 영상이나 하나 지정해 `scripts/migrate.py` 1회 호출 (또는 다음 `run.py` 호출에 맡기고 안내만)
3. 마이그레이션 출력(재생성 필요 단계 목록)을 사용자에게 그대로 전달

### 7. 변경 기록

마이그레이션이 포함된 변경은 [`결정-이력.md`](결정-이력.md)에 "마이그레이션:" 줄로 남긴다 (새 문서를 늘리지 않고 기존 append-only 로그 재사용). 1차 소스는 `migrate.py`의 `MIGRATIONS` 딕셔너리 자체.
