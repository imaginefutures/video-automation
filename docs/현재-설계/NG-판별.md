# NG 판별 설계 — 컷편집 품질의 핵심

상태: ✅ 동작 중 (2026-09-30 하향식 재설계 - 전체를 넓게 보고 부분을 좁혀오는 2단계 캐스케이드로 국소 탐지·전체 맥락 검토를 통합. BS145+BS167 정답지 대조 완료, BS145 정밀도 0.788·재현율 0.734(보정 0.795), BS167 정밀도 0.705·재현율 0.727(보정 0.750), 오삭제 flag 누락 0건 — [`검증-결과-BS145.md`](검증-결과-BS145.md), [`검증-결과-BS167.md`](검증-결과-BS167.md)). 검토 화면 배선은 아직 옛 3분류 어휘로 번역 중([`검토-화면.md`](검토-화면.md) 참고) — 자세한 예정은 [`../기획/`](../기획/00-개요.md)

원칙은 "잘라야 할 재시작"과 "살려야 할 반복"을 구분하는 것이고, 판단의 중심은 **내용(의미) 비교**다.

## 케이스 분류

| 케이스 | 정의 | 판단 근거 | 처리 |
|---|---|---|---|
| A. 실수 → 제대로 | 앞 시도에 오류가 있고 뒤에서 고침 | 두 시도 내용이 충돌. 편집어("아니", "어") 동반. 수정 단어에 음향 강조 | 앞 시도 삭제 |
| B. 말하기 → 더 잘 말하기 | 앞 시도도 맞지만 다시 말함 | **두 시도가 같은 정보인지 실제로 확인.** 새 근거·예시가 추가되면 NG 아님 | 같으면 앞 삭제 / 다르면 유지 / 애매하면 REVIEW |
| C. 강조 반복 | "정말 정말" | 어휘 범주, 운율 평행, 사이 쉼 짧음 | 유지 |
| D. 교육적 재진술·나열 | "다시 말하면", "첫째·둘째" | 담화 표지, 피치 리셋 없음 | 유지 |
| E. 형태론적 수정 | "하나의 → 하나를" | 어간 동일, 접사만 변경 | 경계가 깨끗하면(쉼 ≥ 0.15초) 틀린 단어 삭제, 붙여 말했으면 REVIEW |
| F. 미완성 후 방향 전환 | 문장을 버리고 다른 내용으로 | 앞 조각 미완결, 뒤와 무관 | 앞 조각 삭제 |

**B가 가장 어렵고 가장 중요하다.** 문자열 유사도로는 D와 구분할 수 없어서 LLM이 "전달하려는 정보가 같은가"를 명시적으로 판정하고, 항상 상위 모델로 에스컬레이션한다.

## 판별 신호

| 신호 | 내용 | 상태 |
|---|---|---|
| 텍스트 | 두 시도 전문, 앞뒤 문맥, 편집어, 담화 표지, 문장 완결·단어 절단, 내용 동일성 | ✅ |
| 음향 | 재시작 첫 단어 F0 리셋, 두 시도 F0 곡선 유사도, 수정 단어 에너지 증가, 경계 쉼 | ✅ `prosody.py`가 계산해 자연어 근거로 프롬프트에 넣음 |
| few-shot | 케이스별 예시 | ✅ 정적 6개. 검색 기반 전환은 [`../기획/04-지식-층과-학습.md`](../기획/04-지식-층과-학습.md) |
| 영상 프레임 | 시선 이탈, 자세 리셋 | ⬜ [`../백로그/영상-프레임-신호.md`](../백로그/영상-프레임-신호.md) |
| 출처 상태 | 후보 단어가 소스에 전체/부분으로 남았는지 | 이전 프로젝트 오류 9건 중 7건의 원인. 현재 구조(원본 직접 참조)에서는 발생하지 않음 |

## 탐지 → 분류 → 라우팅 (2026-09-30 하향식 재설계)

기존(45초/단어수 기준 국소 창 탐지 → 개별 분류 → 별도의 "전체 맥락 검토"로 사후 보완)은 같은
문단 안에서 문장 하나를 2~4번 고쳐 말하는 재시작 사슬조차 국소 창 밖이라 후보로 못 만드는
근본 문제가 있었다(`detect_regions.py` docstring, 결정-이력.md 09-30 "하향식 재설계" 참고).
사람 편집자처럼 **전체를 먼저 보고 부분으로 좁혀오는** 2단계로 뒤집었다.

1. **Stage 1 "전체를 넓게"** (`detect_regions.py`): 원본 대본을 800단어 청크(150단어 겹침)로
   나눠 Opus 5.5가 재시작·카메라 밖 대화·필러 몰림 등 의심 구간을 **대략적인 범위**로만 표시한다
   (정확한 경계는 아직 안 정한다). 단어 절단·3단어 내 중복 같은 결정론적 신호는 LLM 호출 없이
   별도로 먼저 잡는다(로컬 힌트).
2. **Stage 2 "부분을 좁게"** (`classify_region.py`): 표시된 구간마다 앞뒤 문맥(단어 id 포함)을
   확대해서 정확한 경계와 케이스를 이때 처음 확정한다. 먼 재진술이면 참고용으로 그 다른 쪽
   텍스트도 같이 보여준다("화자가 의도한 최종 대본"을 복원하는 원리는 그대로). 발음 실수 탐지
   (ASR 저신뢰도 클러스터, `detect_pronunciation_candidates.py`)는 별도 채널로 유지되며 이
   단계에서 같이 판정된다. 출력은 케이스, 권장 행동, 정확한 삭제 범위, 근거, 신뢰도.
3. **라우팅** (`route_candidates.py`)

| 결과 | 조건 |
|---|---|
| CUT, flag 없음 (자동 적용) | CUT, 신뢰도 ≥ 0.75, 케이스 A/B/E, 구간 ≤ 5초, **Stage 1 전체 스캔 출신이 아님** |
| KEEP, flag 없음 (자동 유지) | KEEP, 신뢰도 ≥ 0.55 (0.80에서 재하향 — BS145+BS167 실측: 0.55~0.79 구간의 KEEP 판단도 90% 정확했는데 옛 0.80 기준이 이걸 강제로 잘랐었다) |
| CUT + flag=restore (복원 후보로 검토 큐에) | 나머지 전부: 신뢰도 낮은 CUT/KEEP, B 케이스 LLM 자체 REVIEW, 화자 2명 이상 구간, 구간 5초 초과, **그리고 Stage 1의 전체 맥락 스캔이 찾은 구간은 신뢰도와 무관하게 항상 여기** |

route는 CUT/KEEP 둘뿐이고, "애매함"은 route가 아니라 flag로 표현한다. flag=restore 항목은 잘린 상태로 시작하지만 전부 검토 큐에 뜨고 `Enter` 한 번으로 살릴 수 있다 ([`../서비스-개요와-철학.md`](../서비스-개요와-철학.md) 원칙 2). 오판의 최대 피해가 "검토 큐에서 살리기 한 번"이 되도록 설계한다.

Stage 1 전체 스캔 출신을 항상 flag하는 이유: 그 구간의 "존재 자체"부터 LLM 자신의 추론이라, 국소
힌트나 발음 실수 탐지처럼 독립적인 기계적 신호로 사전 검증되지 않는다. BS167 실측에서 이 경로로
높은 신뢰도(0.85)가 나온 오판(서로 다른 두 문장을 "같은 내용 재진술"로 잘못 봄) 하나가 flag 없이
조용히 잘린 사고로 이어졌다 — judge≠maker 원칙이 이 경로에서는 신뢰도만으로 안 지켜진다는 뜻.

## 화자 이탈 (하향식 체크 중 남은 부분)

BS145 원본↔편집본 정렬에서, 전체 삭제분의 64%(141초)가 재시작이 아니라 **화면 밖 코치의 실시간
지도 구간**이었다. 단어열에서 반복을 찾는 국소 탐지로는 원리적으로 못 잡으므로 별도 채널을 둔다.

- **화자 블록** (`detect_speaker_blocks.py`): "말이 적은 화자 = 카메라 밖"은 틀렸다 (화자 라벨이 구간마다 바뀜). **대화 형태**(짧은 줄이 화자 간 번갈아, 전환 밀도 ≥ 0.4)로 잡는다. 블록 하나가 검토 항목 하나. 줄별로 지시/재시도/최종/내용 역할을 붙여 살릴 줄을 제안한다. 블록 뒤 두 줄도 문맥으로 준다. Stage 1보다 먼저 실행해 이미 잡힌 블록을 Stage 1이 건너뛰게 한다.
- (독백형 카메라 밖 이탈, 예: 시작의 "큐", 끝의 "컷!"은 이제 Stage 1의 CAMERA_DIRECTION/OFF_TOPIC 종류가 담당한다 - 옛 `whole_context_review.py`가 하던 역할.)
- 빈도가 낮아도 생략하지 않는다. 놓치면 방송 불가 수준의 실수다

## 이음새 부분 루프 (자기검증 대체)

`self_critique.py`(AUTO_SAFE 컷을 다시 읽혀 어색하면 REVIEW로 강등)를 2026-09-29에 대체했다. `assemble_draft.py`가 NG·화자블록의 모든 CUT을 합쳐 이음새 목록을 만들고, `seam_refine.py`가 이음새마다 두 가지를 독립적으로 본다.

1. **경계(결정론, `audio_map.py`)**: 기존 15ms 고정 패딩 대신, 컷 앞뒤의 실제 쉼(gap) 안에서 가장 조용한 지점을 찾아 거기로 경계를 옮긴다. 조용한 지점을 못 찾아도 컷을 취소하지 않고 15ms 패딩으로 되돌아가며, 그 사실만 flag에 남긴다 — **한 번 판단한 컷을 되돌리는 게 아니라 경계만 다듬는다**
2. **내용(LLM, 만든 모델과 다른 모델이 판정)**: 결과 연결이 문법적으로 자연스러운지, 같은 말이 중복으로 남는지, 지시어가 끊기는지, 정보가 손실되는지를 본다. Sonnet이 만든 컷은 Opus가, Opus가 만든 컷은 Sonnet이 검사한다

문제가 있으면(경계든 내용이든) `flag: restore`를 붙일 뿐 **컷을 취소하지 않는다** — 최대 삭제 방침 그대로다. 알려진 축소 범위(1차 구현, 지금은 이렇게 동작): G2(재전사 잔여음 검사) 없음, 대안은 원안/조용한 지점 스냅 둘 중 선택(확장·축소 대안 탐색 없음), 반복 없이 1회만.

## 촬영 신호

"다시" + 2초 쉼을 두면 A·B 대부분이 결정론적으로 잡힌다. 가이드: [`../촬영-가이드.md`](../촬영-가이드.md).
**제약: 신호가 없는 영상도 똑같이 편집 가능해야 한다.** 신호는 정확도를 올리는 가산 요소이지 전제 조건이 아니다.
