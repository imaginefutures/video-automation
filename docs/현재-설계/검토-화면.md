# 검토 화면

상태: ✅ 동작 중. **2026-10-02 전면 정정** — 아래는 10-01~10-02의 "읽기→추적→듣기 3단계" 재설계(`ca79220`
1.7.0, 1.8.0, 1.9.0)와 옛 카드 큐·선택 팝업 제거(10-02) 이후 실제 화면 기준으로 다시 썼다. 이전 판(두
층 카드 큐, `J`/`Enter`/`⇧Enter` 단일 루프, `Z` 모달)은 [`../기획/05-검토-화면.md`](../기획/05-검토-화면.md)에
설계로만 남아 있고 화면에는 없다.

## 방향 — 심플하게 3단계

**자동 처리된 상태에서 시작해, 판단 종류별로 3단계를 순서대로 거친다.** 세 단계를 한 번에 섞지 않는다 —
"텍스트로 명백한 것"과 "귀로만 확인되는 것"과 "전체로 들어야 아는 것"은 서로 다른 속도로 판단하는데,
예전엔 이걸 전부 같은 "선택→팝업→Enter" 루프 하나로 처리해 느렸다.

1. **1차 — 텍스트로 편집**: 소리 없이 본문만 읽으며 잘린 곳을 훑는다. 명백히 틀린 자동 판단은 그
   자리에서 바로 고친다.
2. **2차 — 파형 보고 세부 편집**: 문단마다 본문 바로 아래 있는 파형 스트립에서, 스냅 후에도 여전히
   시끄러운 "잔음 의심" 구간만 추적해 경계를 다듬는다.
3. **3차 — 들어보기**: 이음새 릴로 전체를 이어 들으며 마지막으로 확인하고 확정한다.

**트랜스크립트가 곧 타임라인이다.** 영상을 보며 판단하지 않고, 텍스트 위에서 판단하고 소리로 확인한다.
디자인 규칙은 루트 [`DESIGN.md`](../../DESIGN.md).

## 화면 구성

- **본문**: 두 상태뿐. 취소선(잘림) / 평범한 텍스트(유지). 검토 필요 항목도 기본 삭제라 취소선으로
  보인다. 선택할 때마다 자동으로 뜨는 팝업은 없다 (10-02 제거). 단어 일부만 정밀 삭제되면 그 부분에만
  빨간 줄, 잘린 단어 일부를 정밀 복원하면 그 부분에 파란 밑줄. **판단 근거를 보여주는 ⓘ 아이콘/패널은
  10-02에 다시 제거** — "근거 필요없어, 자동 처리→1차 텍스트 편집→2차 파형→3차 듣기로 심플하게"라는
  사용자 결정. 근거 없이도 ↑/↓·C/V로 바로 판단한다(아래 "판단 필요 툴바" 참고)
- **문단별 파형 스트립**: 평소엔 모든 문단 아래 스트립이 정적 미리보기(잘림/잔음의심 색칠)로 상시
  보인다. 그 문단을 선택하거나 스트립을 직접 드래그하면 그 스트립만 확대(핸들+버튼)되고, 다른 스트립은
  숨지 않고 그대로 보인다 — "상시 떠 있는 바 1개"(1.7.0)가 아니라 "문단마다 제자리 스트립"(1.8.0)으로
  교체됐다
- **왼쪽 사이드바**
  - 판단 필요: 카드 목록이 아니라 건수·예상 시간과 **판단 필요 툴바**를 보여준다 (10-02: 카드 목록은
    "또 다른 카드 큐"로 보여 제거). 시작/진행 중/완료 세 상태로 나뉜다(10-02 3차, "검토 모드가 편집과
    구분이 안 된다" 지적) — **시작 전**엔 "▶ 검토 시작" 버튼만, **진행 중**엔 ◀ 이전/다음 ▶(해당
    항목만 순회)·살리기/삭제 유지(C/V)·앞부분만/뒷부분만 살리기(쉼이 있을 때만, 1/3)·확정(⇧Enter)·
    ■ 검토 중단 버튼이, **완료**(남은 항목 0)엔 "✓ 완료 / 다시 검토" 가 보인다. 버튼은 ↑/↓·C/V 등
    기존 키보드 단축키와 같은 동작을 가리킬 뿐(키보드는 그대로 동작) - 팝업처럼 또 판단하는 중복이
    아니다. 액션 후 자동으로 다음 항목으로 넘어간다. **진행 중일 때만** 본문의 잘린 단어를 클릭하면
    즉시 그 단어가 복원된다(집중 모드 - 평소 편집 중 클릭은 그냥 안전한 선택일 뿐) - 화면 전체에도
    집중 모드 스타일이 걸려 상단에 강조 배너가 뜨고 검색·확정·모델 재분석·무음 리듬·빠른 확인 등
    다른 메뉴는 흐려지며 클릭도 막힌다(되돌리기만 예외 - 실수해도 바로 고칠 수 있어야 하므로)
  - 빠른 확인: 건수와 예상 시간만, "▶ 빠른 확인 릴 재생" 버튼으로 이어서 훑는다. 두 층의 분류 기준
    자체(PD/시청자 평가, 복원 이력)는 [`../기획/05-검토-화면.md`](../기획/05-검토-화면.md) 2장 그대로 유지
  - 발화 블록: 카메라 밖 대화. 클릭하면 본문에서 그 구간이 선택됨
  - 무음 리듬: 목표치 전역 조정 (아코디언)
  - 검색: 문구는 브라우저에서 즉시, 못 찾으면 서버가 의미 검색 ("셀리그만 이야기하는 부분")
- **우하단 `?`**: 전체 단축키

## 조작

| 조작 | 동작 |
|---|---|
| `←` `→` | 단어 커서 이동 (`⇧` = 범위 확장) |
| `↑` `↓` | 잘린 곳만 건너뛰며 이동 (1단계: 텍스트로 편집) |
| `C` / `V` | 삭제 / 살리기 즉시 반영 — 팝업 없음 |
| `N` / `⇧N` | 잔음 의심 지점으로 이동 (2단계: 파형 보고 세부 편집) |
| 파형 스트립 드래그 | 자유 범위 선택, 조용한 지점에 자동 스냅, 핸들을 놓으면 즉시 미리듣기 |
| `Space` | 재생/정지 (커서 위치부터) |
| `X` | 이음새 듣기 (컷 직전 + 직후를 이어서) |
| `R` | 이음새 릴 시작/정지 (3단계: 들어보기, 확정 전 전수 점검) |
| `1` `2` `3` | 대안 선택 (앞만/전부/뒤만 살림) |
| `⇧Enter` | 확정 잠금 — 지금 상태 그대로, 더는 안 봐도 되는 곳으로 흐려짐 |
| `U` / 더블클릭 | 잠금 해제 |
| `S` | 판단 보류 (건너뛰기) |
| `⌘Z` / `⌘⇧Z` | 되돌리기 / 다시 실행 (같이 바뀐 결정까지) |
| `Esc` | 선택 해제 / 정지 |

가상 재생: 브라우저가 clean.mp4를 직접 재생하며 잘린 구간을 건너뛴다. 컷 지점은 40ms 페이드 아웃 →
점프 → 60ms 복귀.

## 왜 이 형태인가 (폐기한 것들)

- FCP 마커 기반 검토 → 폐기. 48개 마커 = 결국 타임라인 전체를 훑어야 함
- 3색 표시(유지/자동 삭제/확인 필요) → 2색으로. 본문이 알록달록하면 "다 봐야 할 것 같은" 부담이 생김
- 오른쪽 큐 패널 → 폐기 후 왼쪽 사이드바 카드로 재구성 (09-29)
- 다크 테마 → 가시성 문제로 반려, 라이트 고대비로 확정
- **두 층 카드 큐 + 선택 팝업(`#pop`) + `Z` 모달 (09-30~10-01) → 폐기, 3단계로 교체 (10-02)**: 09-30
  하향식 재설계 이후에도 옛 카드 큐와 팝업이 새 `C`/`V` 플로우와 나란히 남아 있었다 — 사용자가 직접
  써보고서야 "검토 기능 없애기로 했는데 왜 남아있어?"로 지적됨. 판단 종류(텍스트로 명백한 것 / 귀로만
  확인되는 것 / 전체로 들어야 아는 것)별로 속도가 다른데 하나의 "선택→팝업→Enter" 루프로 묶여 있던 게
  느렸던 근본 원인이었다 ([`../결정-이력.md`](../결정-이력.md) 10-02)
- 상시 파형 바 1개(1.7.0) → 문단별 인라인 스트립(1.8.0)으로 교체: 매번 시선을 하단으로 옮겨야 했음

## 패턴 제안

한 세션에서 같은 케이스를 같은 방향으로 3번 연속 결정하면, LLM이 그게 일반화할 수 있는 규칙인지 판단해 배너로 제안한다 ("이후 이런 패턴은 자동으로 처리할까요?"). 사용자가 예를 눌러야만 적용된다. 현재도 **그 세션 안에서만** 유효하다 — 영상 간 규칙으로 승격하는 설계(R4)는 위 개인화 폐기와 같은 이유로 보류 상태다. [`../남은-개발.md`](../남은-개발.md)의 "few-shot L2를 공유 저장소로 재설계" 항목이 그 대안이다.

## 모든 결정은 정답 데이터

`decisions.json`에 단어 범위, 종류, 원래 자동 라벨, 사람이 바꿨는지, 아웃테이크 별표를 기록한다. 같은 raw.mp4로 동일 결과를 재생성할 수 있다. `actions.log`에는 타임스탬프와 함께 모든 이벤트가 남아 검토 시간 측정에 쓸 수 있다.
